# Поведение и ограничения

Контракты, пределы и неочевидные правила. Пользовательские инструкции — [README](../README.md), границы кода — [architecture](architecture.md).

## Сервер

- Режимы: `dev` (Vite и HMR) и `prod` (собранный `dist` на Node, `packages/server/app/standalone.ts`). Выбор — `server-mode` в каталоге данных, текущий — поле `mode` в `/api/health`.
- `projector mode prod` сначала выполняет `vp build`; при ошибке сервер не трогается. Смена режима перезапускает сервер и **завершает терминалы и процессы**.
- Один сервер на машину: повторный запуск использует работающий процесс (`instance.json`, `launch.lock`).
- `server.log` в каталоге данных ротируется: активный файл до 10 МиБ, рядом хранятся до пяти архивов `server.log.1…5`. Перезапуск начинает новый файл, работающий сервер проверяет размер каждые 15 секунд и продолжает писать в новый без потери строк. Пороги меняются через `PROJECTOR_LOG_MAX_BYTES` и `PROJECTOR_LOG_MAX_FILES`.
- `vp run desktop` ставит команду `projector` и пункт меню; установка ссылается на checkout, после переноса её нужно повторить.

## Доступ по локальной сети

- По умолчанию `localhost`; режим `lan` слушает `0.0.0.0`. Выбор — `network-mode`; смена из настроек перезапускает сервер и завершает терминалы.
- Пароль хранится как scrypt-хеш в `lan-password`. С паролем браузер получает сессию на 8 часов в `HttpOnly` cookie, программные клиенты — `Authorization: Bearer <пароль>`. Смена пароля отзывает сессии и сетевые WebSocket. Повреждённый файл закрывает сетевой доступ. Loopback-соединения идут без пароля.
- Локальность определяется по адресу соединения, а не по `Host` или proxy-заголовкам; принимаются `localhost` и числовые IP (защита от DNS rebinding). Перезапуск и смена режима из сети запрещены. LAN работает по HTTP.

## PWA и service worker

- `http://localhost` — доверенный контекст: установка из Chrome и Edge без HTTPS. Манифест — `public/manifest.webmanifest`.
- Service worker (`public/sw.js`) включается только в `prod` (`/api/health`), ничего не кеширует: навигация всегда в сеть, `/api`, WebSocket и терминалы не перехватываются, при недоступном сервере — страница «Projector не отвечает». В `dev` клиент сам снимает регистрацию и чистит кеши `projector-shell-*`.
- Адрес в локальной сети не является доверенным контекстом: service worker и установка там не работают.

## OpenAI-совместимый API

- База — `http://localhost:4177/api/openai/v1`: `GET /models`, `POST /chat/completions` (включая `stream: true`), `POST /completions`, `POST /embeddings`. Запрос идёт к провайдеру модели из `model`, без неё — к активному. Ключи провайдеров клиент не видит.
- Шлюз выключен по умолчанию. Включается через `PUT /api/openai` (`enabled`, `apiKey`, `origins`) только с локальной машины; состояние — `openai-gateway.json`, ключ — SHA-256.
- Шлюз принимает только собственный `Origin`; запросы без `Origin` (curl, SDK) проходят. Белый список `origins` отвечает CORS точным origin (не `*`, включая preflight и Private Network Access) и понимает шаблоны `@localhost` и `@lan`. С ключом шлюз требует его всегда, пароль LAN не нужен; сессия по ключу не создаётся. Без ключа в `lan` нужен пароль LAN. Неверный ключ — `401` в формате OpenAI.

## Палитра

- Поиск и выбор общие для DOM и GTK — `packages/core/modules/launcher`; модель не дублируется.
- Enter запускает приложение или открывает проект, Ctrl+Enter — основную команду проекта. Префиксы: `/` — проекты (включая ещё не открытые папки в избранных), `gh/…` — GitHub, `gl/…` — GitLab. `new/имя` создаёт проект в избранной папке или открывает уже существующую; существующая папка не перезаписывается.
- **Избранные папки** — не цели запуска: в списке их нет. Прямые дочерние папки, которых ещё нет в каталоге, попадают в поиск и в раздел «На диске»; открытие регистрирует проект.
- Хоткей: KDE — session D-Bus, Windows — `RegisterHotKey`, macOS — Swift-помощник; вне этих окружений назначайте `projector toggle`. Чужое назначение не перехватывается.
- Палитра скрывается по Esc и по потере активности **всего окна**, а не blur поля. В браузере это действует только для launcher-surface.

## Проекты

- Страницы списка и формы добавления нет: проект создаётся при первом переходе по пути, drop папки на `/` или `ide.project.path.open`. Данные — `projects.json`.
- Сценарий запуска: имя, команда, `cwd` внутри проекта, свой адрес и режим (`server` или `window`). `cwd` действует только для запуска на этой машине, не для Docker и Dev Container. Режим `window` требует HTTP/HTTPS-адрес.
- «Убрать проект» удаляет запись и завершает процессы и терминалы, файлы остаются. Если папка исчезла, страница предлагает создать её, указать новый путь или убрать проект.

## Очередь сообщений агенту

- Уточнения во время хода попадают в текущий ход перед следующим запросом к модели: выполняющийся инструмент заканчивает работу, модель получает результат и новые инструкции. Сообщение во время финального текста запускает ещё один запрос в том же ходе.
- «Передаётся агенту» — ожидание подтверждения приёма. После обычного завершения сообщение уходит следующим ходом; после остановки или ошибки ждёт пользователя. Изображения и адаптеры без поддержки уточнений ждут следующего хода. Claude Code использует собственный механизм.

## Workspace

- Раскладка блоков — модуль `dock`; файлы, терминалы, агент и настройки — вкладки. Раскладка и открытые файлы — в `sessionStorage` вкладки браузера, не на сервере.
- **Снимки файлов.** Дерево коммита и сравнение — `FileScope` (`live`, `commit`, `compare`), запись, DnD и импорт разрешены только для `live`. HTML и архивы снимка открываются как код/файл без распаковки; Markdown, изображения и SVG рендерятся из того же снимка. Поиск по снимку — `git grep` локально и GitLab blob search с `ref`; GitHub code search не принимает коммит.
- **Проводник.** «Показать в проводнике» (`ide.fileTree.entry.reveal`) выделяет файл или папку в системном файловом менеджере; без цели показывает корень проекта. Доступно только для локального проекта при открытии Projector на компьютере с сервером; в снимках и удалённых источниках команда скрыта.
- Ответ агента приходит по тому же потоку событий (`POST /api/agent` с `client` и `stream` отвечает `202`); без потока сервер отвечает `409` и отдаёт ответ телом запроса.
- **Автосохранение и наблюдение.** Текст сохраняется по Ctrl+S, потере фокуса, смене и закрытию вкладки; при конфликте с диском черновик сохраняется. Сервер следит (`fs.watch`, без рекурсии) за папками открытых файлов: `file-changed` обновляет вкладку без правок молча, при правках показывает панель «Загрузить с диска / Оставить мою версию»; `dir-changed` перечитывает только список раскрытых папок. Слежение привязано к странице и закрывается вместе с её потоком событий. Все вкладки делят один поток через SharedWorker (`projector-events-v1`); без него — свой поток.
- **Лимиты.** Текстовый файл: подтверждение от 10 МБ, потолок 256 МБ (читается одной строкой); изображения — 8 МБ. Поиск `rg` — буквальный, без регистра, 200 результатов, до 5 строк на файл. Перенос — GNU `mv --no-clobber` (вне проекта и через symlink запрещён). Удаление — в `.projector-trash` в корне проекта (скрыт из дерева, поиска и Git).
- **Просмотрщики.** Изображения и SVG — общий `ImageViewport`. HTML — `iframe` в песочнице без origin Projector, файлы отдаёт `/api/projects/<id>/site/<путь>`, `.git` и выход из проекта закрыты. Markdown — Milkdown/Crepe; открытие без правок файл не меняет. Архивы — список записей без извлечения (Python 3, 5000 записей, 256 МБ, 15 с).
- **Браузер.** Каждый сайт открывается на своём origin `<хост>.<s|h[порт]>.<ключ>.proxy.localhost:<порт Projector>`: настоящие относительные ссылки, fetch и localStorage, API Projector на другом origin. Прокси снимает `X-Frame-Options`/CSP, переписывает абсолютные ссылки и хранит cookies сайтов в своём jar. Работает только при открытии Projector на этом компьютере; WebSocket и service worker сайта не проксируются, JavaScript не переписывается, jar живёт до перезапуска. Ключ — `browser-proxy-key`, выдаётся только странице Projector.
- **Импорт из системы.** Есть путь на диске — сервер копирует сам; нет — загрузка по одному до 512 МБ. Занятые имена не перезаписываются: `keep` (`имя (2).ext`), `replace` (старое в `.projector-trash`), `prefix` или `ask`. Команда `ide.fileTree.entry.import` (`paths`, `directory`, `conflict`, `prefix`), по умолчанию конфликт — ошибка без изменений.

## Терминал

- Лимит — 24 сессии. Стек: `node-pty`, xterm.js, WebSocket с проверкой Origin; вкладки браузера делят соединения через SharedWorker с откатом на прежний транспорт. Медленная отрисовка приостанавливает чтение PTY до подтверждения.
- Сессии живут в памяти сервера: переживают переключение вкладок и перезагрузку браузера (экран, курсор, режимы, 5000 строк), но не перезапуск Projector. Ctrl+click по пути в выводе открывает файл (относительные — от cwd сессии, затем от корня проекта).
- Сборка `node-pty` требует Python, make и C++ compiler.

## Агент Projector

- Провайдер — активный OpenAI-совместимый из `providers.json` (или `DASHSCOPE_API_KEY`/`OPENAI_URL`/`OPENAI_MODEL`). История — `agent/history.sqlite`; «Новый чат» откладывает текущий в историю, закрытые чаты остаются в индексе проекта.
- Вкладка чата называется по первому сообщению — так же, как чат в истории; пустая вкладка остаётся «Агентом».
- В системный промпт попадают `AGENTS.md` и `CLAUDE.md` из корня проекта (до 20 тыс. знаков) с пометкой источника; правила подтверждений они не отменяют.
- Разрешения: «Спрашивать» подтверждает не только читающие команды оболочки и изменяющие команды Projector; «Авто» делает отдельный запрос к модели, сбой проверки уходит на подтверждение; «Без вопросов» отключает подтверждения. Оценка риска — Судья Projector (настройки «Судья Projector», для чата — меню «Ещё»).
- Контекст: последние ~90 тыс. знаков вызовов; более ранние ходы сжимаются в сводку. На 80% — подсказка, на 90% — автосжатие; `/compact` и `ide.agent.chat.compact` сжимают вручную. Сжатие и проверка команд идут с минимальным размышлением.
- Возможности: картинки, уровень размышления (`providers/thinking.ts`), MCP (свои и `.mcp.json`, запуск проектного сервера и изменяющий вызов подтверждаются), `web_search`/`web_fetch` (сайты локальной сети недоступны, первое обращение подтверждается), навыки (`skills/<имя>/SKILL.md`) и команды (`commands/<имя>.md`) из папки пользователя и `.projector/`, `.claude/` проекта, хуки `PreToolUse`/`PostToolUse`/`Stop`, память, расход по цене модели.
- Пределы: `PROJECTOR_AGENT_MAX_STEPS`, `PROJECTOR_AGENT_MAX_SECONDS` (15 мин), `PROJECTOR_AGENT_MAX_TOKENS`, `PROJECTOR_AGENT_CONTEXT_TOKENS` (128000); при остановке появляется «Продолжить».
- Ход живёт в отдельном процессе (`packages/cli/app/agent-host.mjs`, раннеры `packages/server/app/projector-runner.ts` и `claude-runner.ts`): перезапуск сервера, закрытая вкладка и перезагрузка страницы его не прерывают, чат переподключается и получает ответ с начала. Остановка — только «Стоп» (`POST /api/agent/cancel`): SIGTERM, инструменты прерываются, выход не позже 2 секунд. Без сервера ход идёт не дольше 30 минут (`PROJECTOR_AGENT_IDLE_MS`); завершённый ход без подключения удаляется через час; хост старше суток останавливается. Ожидающие карточки переживают перезапуск.
- Фоновые субагенты Claude Code живут внутри процесса агента: ход не заканчивается, пока они не отчитались (не дольше 30 минут). Фоновые команды оболочки ход не удерживают и помечаются остановленными. Задачи без живого процесса при открытии чата помечаются остановленными.

## Графические чаты внешних агентов

- Claude Code, Codex, OpenCode, Cursor и Kimi Code работают в GUI или TUI; режим — `agentModes` в `launcher.json`, `GET/PUT /api/agent/modes`. GUI-чат требует проект; в Docker и Dev Container чат отказывает — остаётся терминал.
- Claude Code идёт через Agent SDK со своими промптом, инструментами, `CLAUDE.md` и настройками. Projector ничего не добавляет в контекст, кроме включённых возможностей. Режимы разрешений — `default`, `acceptEdits`, `auto`, `bypassPermissions`.
- Codex, OpenCode, Cursor и Kimi — ACP по stdio (`opencode acp`, `agent acp`, `kimi acp`, `codex-acp`). Один клиент JSON-RPC, `session/update` → общие события, `session/load` или `session/new`, `session/request_permission`, `session/cancel`. Процесс запускается на каждый ход и не переиспользует сессии пользователя.
- Параметры над вводом приходят от агента (`AgentControl`): модель, усилие, флаги, режим. Выбор запоминается в `agentDefaults`; отклонённое агентом значение показывается как фактическое.
- Слэш-команды читаются пробной `session/new` до первого хода; новый список из хода заменяет старый.
- История — единый список разговоров: чат Projector, продолжающий нативную сессию, не дублируется. Ветки субагентов скрыты, родитель читается из `_meta` или базы OpenCode (`session_v2.parent_id`).
- Вкладка нового чата называется по первому сообщению, а когда агент назовёт нативную сессию — её именем; внедрённый текст возможностей Projector в имени сессии не показывается; явный заголовок (ветка, чат из истории) не перезаписывается.
- Возможности Projector (виджеты, команды IDE через MCP) — [agent-features](agent-features.md); Lens — [agent-lens](agent-lens.md); вопросы в сторону — [agent-side](agent-side.md); форки — [chat-forks](chat-forks.md); фоновые задания — [agent-jobs](agent-jobs.md).
