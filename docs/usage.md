# Использование Projector

[Начало работы](../README.md) · [GitHub и интеграции](integrations.md)

## Режимы запуска

```bash
./bin/projector toggle    # показать/скрыть палитру
./bin/projector --tray    # запуск без окна
./bin/projector --native  # GTK4
./bin/projector --window  # Chromium app-окно
./bin/projector --browser # браузер по умолчанию
./bin/projector quit      # завершить сервер и его процессы
./bin/projector mode [dev|prod] # показать / переключить режим сервера
./bin/projector --lan | --local # одноразово: доступ по сети / только localhost
```

Режим по умолчанию (интерфейс) выбирается на `/settings`; CLI-флаги действуют только на текущий вызов.

**Режим сервера.** `dev` (по умолчанию) — Vite с HMR; `prod` — собранный `dist` на собственном Node-сервере (`vp` нужен только для dev и сборки). Выбор хранится в `$XDG_DATA_HOME/projector/server-mode`. `projector mode prod` сначала выполняет `vp build` (при ошибке сервер не трогается), затем полностью перезапускает сервер: **терминалы и процессы завершаются**. В `prod` изменения кода применяются только повторным `projector mode prod`. Текущий режим — поле `mode` в `/api/health`.

## Доступ по локальной сети

По умолчанию сервер слушает `localhost`. Режим `lan` (`/settings` или `--lan`) слушает `0.0.0.0`. Выбор хранится в `$XDG_DATA_HOME/projector/network-mode`; смена из настроек перезапускает сервер (терминалы завершаются).

Необязательный пароль хранится как scrypt-хеш в `$XDG_DATA_HOME/projector/lan-password`. С паролем браузер получает серверную сессию на 8 часов в `HttpOnly` cookie; для программных клиентов — `Authorization: Bearer <пароль>`. Смена пароля отзывает сессии и сетевые WebSocket. Повреждённый файл пароля закрывает сетевой доступ. Loopback-соединения доступны без пароля.

Локальность определяется по адресу соединения, а не по `Host` или proxy-заголовкам. Сервер принимает `localhost` и числовые IP (защита от DNS rebinding). Перезапуск и смена режима из сети запрещены. LAN работает по HTTP.

`vp run desktop` ставит команду `projector` в `~/.local/bin` и пункт меню; установка ссылается на checkout. Автозапуск не устанавливается: добавьте `projector --tray` средствами рабочего окружения.

## Палитра

Главная страница `/` ищет приложения и проекты. Логика поиска и выбора — `core/modules/launcher`, общая для DOM и GTK; не дублируйте её.

- Enter запускает приложение или открывает проект; Ctrl+Enter запускает основную команду проекта. Вправо в конце строки, Tab или Ctrl+K входят в результат (карточка проекта и все действия; у упавшего запуска — хвост вывода). ←/Esc возвращают к списку. Ctrl+D — избранное (`launcher.json`, `favorites`; репозитории GitHub не добавляются).
- Префиксы: `/текст` — только проекты, `gh/…` — репозитории GitHub (ссылки `https://github.com/owner/repo` равны `gh/owner/repo`), `gl/…` — проекты GitLab (Enter клонирует).
- Пустое поле показывает секции: Избранное, Работает, Недавние (5), Проекты (30), Приложения (6); поиск по тексту — плоский список до 10.
- Список обновляется по событиям `/api/events`; выбранная строка не сбрасывается.
- В системном и отдельном веб-окне палитра скрывается после запуска, по Esc и при потере активности всего окна. В обычной вкладке остаётся подтверждение запуска. Детали окон и хоткея — [session-notes](session-notes.md).
- KDE: хоткей `Ctrl+Alt+Space` регистрируется автоматически и настраивается на `/settings`; в других окружениях назначьте `projector toggle` самостоятельно.
- Трей: StatusNotifierItem / DBusMenu. «Перезапустить» и «Выйти» в меню трея завершают сервер, терминалы и запущенные проекты; Esc только скрывает палитру.

## Требования интерфейсов

- Системное окно: Linux, Node.js 24, GTK4 и GObject Introspection (с GioUnix); работает отдельным Node-процессом, вызывается через D-Bus.
- Отдельное веб-окно: Chromium-совместимый браузер с отдельным профилем Projector; фокус и скрытие через `xdotool` и `xprop` (X11).
- Windows: только браузер и окно Chromium; запуск `bin\projector.cmd`, данные в `%LOCALAPPDATA%\projector`. GTK-палитра, трей и хоткей — только Linux.
- Поиск приложений использует GIO через `node-gtk`. Трей и хоткей — `dbus-next`; биндинг `usocket` отключён.

## Проекты

Страницы списка и формы добавления нет: проект создаётся при первом переходе по пути (строка пути, `/projects/<путь>`, `ide.project.path.open`) или при drop папки на `/` (`ide.project.paths.open`). В новом проекте открывается вкладка агента с предложенным запросом инициализации. GitHub открывается по `gh/…` или `gh:/owner/repo`.

Вкладка **Настройки проекта** (шестерёнка сайдбара открывает настройки Projector, а не проекта): название, иконка, команды, URL, режим запуска. «Из package.json» читает все скрипты без запуска и не заменяет существующие команды. Нужна хотя бы одна команда; команда по умолчанию запускается из палитры. «Открывать в отдельном окне» требует HTTP/HTTPS-адрес. Корневая папка только для чтения. «Убрать проект» удаляет запись и завершает процессы и терминалы, файлы остаются. Данные — `projects.json`.

Если папка проекта удалена, страница предлагает создать её заново, указать новый путь или убрать проект (`ide.project.directory.*`).

## Workspace

Слева сайдбар (Файлы / Поиск / Git; Issues, Pull requests, Discussions при GitHub в `origin`; Docker при включённой интеграции), остальное — раскладка блоков (модуль `dock`), по умолчанию редактор слева и терминалы справа. Файлы, терминалы, агент, настройки и горячие клавиши — вкладки в блоках; их можно перетаскивать на полосу вкладок, край блока (разделение) или середину. Раскладка и открытые файлы запоминаются в `sessionStorage` вкладки браузера. Команды: `ide.workbench.panel.splitRight`, `splitDown`, `hideGroup`, `ide.workbench.sidebar.toggle`, `ide.workbench.layout.reset`, `ide.workbench.terminal.new`.

**Файлы и поиск.** Дерево загружает папки по мере раскрытия, скрывает зависимости; игнорируемые `.gitignore` файлы приглушены. Текст открывается во вкладке с автосохранением (Ctrl+S, потеря фокуса, смена/закрытие вкладки); при конфликте с диском черновик сохраняется. Лимиты: текстовые файлы 1 МБ, поиск через `rg` — буквальный, без регистра, 200 результатов, до 5 строк на файл. Перенос в дереве использует GNU `mv --no-clobber` (без перезаписи; вне проекта и через symlink запрещён). Удаление перемещает в `.projector-trash` в корне проекта (скрыт из дерева, поиска и Git). Меню и клавиши дерева и вкладок вызывают IDE-команды (`ide.fileTree.*`, `ide.workbench.tabs.*`), привязки — `keybindings.json`; см. [SDK команд](ide-commands.md).

**Viewers.**

- Изображения (PNG, JPEG, GIF, WebP, AVIF) и SVG открываются в общем `ImageViewport`; SVG показывает исходник и рендер с `currentColor`, размером (8–2048 px) и фоном. Параметры рендера действуют только в просмотре.
- HTML открывается как страница в `iframe` в песочнице без origin Projector (`sandbox` и `Content-Security-Policy: sandbox`); файлы отдаёт `/api/projects/<id>/site/<путь>`, `.git` и выход из проекта закрыты. Ссылки от корня сайта (`/img/a.png`) пока ведут в корень Projector. Команды — `ide.editor.html.*`.
- Markdown — Milkdown/Crepe, визуальное редактирование; библиотека может нормализовать маркеры списков, таблицы и ограждения кода; открытие без правок файл не меняет. Ctrl+Shift+M переключает документ и исходник. Локальные изображения до 8 МБ.
- Архивы (TAR*, ZIP) показываются списком записей без извлечения: метаданные читает Python 3, лимиты 5000 записей, 256 МБ потока, 15 с. Тест — `tests/archives.test.mjs`.
- Git: `HEAD → index` только чтение, `index → рабочий файл` правится и откатывается по блокам. Подробности — [ide-commands](ide-commands.md#git-commands).

Иконки дерева — тема `public/file-icons/theme.json`, см. [file-icons](file-icons.md).

## Терминал

Вкладки **+ shell / Codex / Claude Code / OpenCode / Cursor** создают сессии в папке проекта; агенты запускаются командами `codex`, `claude`, `opencode`, `agent` из окружения пользователя (установка и вход — штатными CLI). Команды dev/preview тоже идут в терминальных сессиях. Лимит — 24 сессии. Стек: `node-pty`, xterm.js, WebSocket (с проверкой Origin); медленная отрисовка приостанавливает чтение PTY до подтверждения браузером.

Сессии живут в памяти сервера и переживают переключение вкладок, смену страницы и перезагрузку браузера (восстанавливаются экран, курсор, режимы, 5000 строк истории), но не перезапуск Projector. Закрытие сессии, удаление проекта и выход завершают процессы. Ctrl+click по пути в выводе открывает файл (`file.ts:12:3`, `~/`, пути в кавычках; относительные пути от cwd сессии, затем от корня проекта). Одиночный свайп на сенсорных экранах прокручивает историю — `src/modules/terminal/lib/touch-scroll.ts`. Сборка `node-pty` на Linux требует Python, make и C++ compiler (`pnpm-workspace.yaml` разрешает её).

Проверки: `tests/terminal.test.mjs`, `terminal-input.test.mjs`, `terminal-touch.test.mjs`.

## Агент Projector

Вкладка **Агент** (кнопка с роботом, `ide.workbench.agent.open`) использует активный OpenAI-compatible провайдер (`providers.json`, либо `DASHSCOPE_API_KEY`/`OPENAI_URL`/`OPENAI_MODEL`). Агент ищет и вызывает зарегистрированные IDE-команды; для остального есть Bash в папке проекта. История проекта — `$XDG_DATA_HOME/projector/agent`; «Очистить чат» удаляет её. Закрытие чата и уход из проекта прерывают запрос.

## Агенты в графическом чате

По умолчанию все агенты запускаются в терминале (TUI). Для Claude Code, Codex, OpenCode и Cursor есть графический режим (GUI): выберите его в «Настройки → Сессии агентов» или кнопкой **TUI/GUI** в строке агента меню «+» (режим хранится в `launcher.json`, `GET/PUT /api/agent/modes`). Тогда «+» → агент (`ide.workbench.claude.open`, `ide.workbench.codex.open`, `ide.workbench.opencode.open`, `ide.workbench.cursor.open`) открывает его в чате вместо терминала.

Claude Code идёт через Agent SDK: тот же вход, `~/.claude`, `CLAUDE.md` и настройки проекта, встроенные инструменты; Projector ничего не добавляет в контекст модели. Режим разрешений выбирается в футере чата: спрашивать (запрос «Разрешить / Отклонить»), правки без вопросов, всё без вопросов.

Запрос разрешения показывает, что именно изменится: для правок — diff с путём и строками, для остальных вызовов — аргументы. Если агент умеет помнить решение, рядом с «Разрешить» есть «Всегда разрешать»; обычное «Разрешить» всегда разовое.

Codex, OpenCode и Cursor подключаются по Agent Client Protocol (`opencode acp`, `agent acp`, Codex — через `codex-acp`, при его отсутствии `npx -y @agentclientprotocol/codex-acp`): те же CLI, вход и настройки, запросы разрешений приходят кнопками в чат. Для Codex нужен Node/npx. Режим разрешений «спрашивать / правки / всё» есть только у Claude Code, у остальных его роль играет их собственный режим (Codex — «Read-only / Workspace access / Auto review / Full access», Cursor — Agent/Plan/Ask, OpenCode — Build/Plan).

Над строкой ввода у каждого агента есть параметры, которые он сам объявляет: **модель**, **усилие рассуждений** (Codex, OpenCode, Claude Code; у Cursor усилие входит в вариант модели) и **режим**. Выбор действует со следующего сообщения и запоминается для этого агента (`agentDefaults` в `launcher.json`); если агент отклонил значение (список усилий зависит от модели), показывается то, что он реально применил. Кнопка с часами в шапке открывает **прошлые сессии** агента в этой папке (в том числе начатые в терминале): выбранная заменяет содержимое чата и продолжается следующим сообщением. Всё это доступно штатному агенту командами `ide.agent.controls.list`, `ide.agent.control.set`, `ide.agent.sessions.list` и `ide.agent.session.resume`.

Каждая сессия — отдельный диалог (продолжается по `session_id`). Нужны проект и установленный CLI агента; в проектах с Docker-окружением или Dev Container чат отказывает — используйте терминальную сессию.
