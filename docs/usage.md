# Поведение и ограничения

Контракты, пределы и неочевидные правила. Пользовательские инструкции — [README](../README.md), границы кода — [architecture](architecture.md).

## Сервер

- Режимы: `dev` (Vite и HMR) и `prod` (собранный `dist` на Node, `packages/server/app/standalone.ts`). Выбор — `server-mode` в каталоге данных, текущий — поле `mode` в `/api/health`.
- `projector mode prod` сначала выполняет `vp build`; при ошибке сервер не трогается. Смена режима перезапускает сервер и **завершает терминалы и процессы**.
- Один сервер на машину: повторный запуск использует работающий процесс (`instance.json`, `launch.lock`).
- `server.log` в каталоге данных ротируется: активный файл до 10 МиБ, рядом хранятся до пяти архивов `server.log.1…5`. Перезапуск начинает новый файл, работающий сервер проверяет размер каждые 15 секунд и продолжает писать в новый без потери строк. Пороги меняются через `PROJECTOR_LOG_MAX_BYTES` и `PROJECTOR_LOG_MAX_FILES`.
- `vp run desktop` ставит команду `projector` и пункт меню из checkout; после npm-установки то же делает `projector-install-desktop`. Установка из checkout ссылается на папку исходников, после переноса её нужно повторить.
- Установщик добавляет `%LOCALAPPDATA%\bin` в пользовательский `PATH` и кладёт туда `projector.cmd` для cmd/PowerShell и `projector` для Git Bash. Новая сессия терминала подхватывает `PATH`; уже открытой нужен перезапуск.

## CLI

- Команды работают с тем же локальным сервером: `open`, `projects`, `status`, `run`, `stop`, `search`, `start`, `restart`, `quit`, `settings` и прежние `toggle`/`mode`. Полный список — [CLI](cli.md).
- `open` принимает локальный путь, имя или id проекта, `gh:/owner/repository` и `gl:/<instance>/<group>/<project>`. Локальная папка регистрируется при первом открытии.
- `projects` и `status` не запускают сервер: без него они читают `projects.json` и `.projector/scenarios.json` проектов и показывают проекты остановленными. Остальные команды поднимают сервер по требованию.
- `--json` не меняет ошибки и коды выхода: сообщение идёт в stderr, успешный JSON — в stdout.
- `--lan` и `--local` действуют только на новый процесс; для работающего сервера нужен перезапуск или настройки.

## Обновления

- Канал поставки — npm registry, не GitHub Releases. Checkout исходников (`./bin/projector`, `vp dev`) не предлагает `npm install -g`.
- Проверка `latest` идёт по HTTPS к `registry.npmjs.org`: версия предлагается, только если есть `dist.tarball` и `dist.integrity`. Кеш — `update.json` в каталоге данных, около 20 часов. Офлайн и 5xx не ломают запуск.
- `/api/health` отдаёт `version` и `source` (`checkout` / `npm` / `other`). Подробности и команда — **Настройки → О приложении**, `GET /api/app/update` и команды `ide.app.update.check|copyCommand|dismiss`.
- Кнопка не ставит пакет из процесса сервера. Команда пинит точную версию (`@ai-projector/ide@<версия>` с `--allow-scripts=node-pty`). После неё нужен `projector restart`: он завершает терминалы и ходы агентов.
- Inbox напоминает один раз на конкретную latest и только для канала `npm`. «Не напоминать» запоминает этот номер; следующая версия снова уведомит.

## Доступ по локальной сети

- По умолчанию `localhost`; режим `lan` слушает `0.0.0.0`. Выбор — `network-mode`; смена из настроек перезапускает сервер и завершает терминалы.
- Пароль хранится как scrypt-хеш в `lan-password`. С паролем браузер получает сессию на 8 часов в `HttpOnly` cookie, программные клиенты — `Authorization: Bearer <пароль>`. Смена пароля отзывает сессии и сетевые WebSocket. Повреждённый файл закрывает сетевой доступ. Loopback-соединения идут без пароля.
- Локальность определяется по адресу соединения, а не по `Host` или proxy-заголовкам; принимаются `localhost` и числовые IP (защита от DNS rebinding). Перезапуск и смена режима из сети запрещены. LAN работает по HTTP.

## PWA и service worker

- `http://localhost` — доверенный контекст: установка из Chrome и Edge без HTTPS. Манифест — `public/manifest.webmanifest`.
- Service worker (`public/sw.js`) включается только в `prod` (`/api/health`), ничего не кеширует: навигация всегда в сеть, `/api`, WebSocket и терминалы не перехватываются, при недоступном сервере — страница «Projector не отвечает». В `dev` клиент сам снимает регистрацию и чистит кеши `projector-shell-*`.
- Адрес в локальной сети не является доверенным контекстом: service worker и установка там не работают.

## OpenAI-совместимый API

- База — `http://localhost:4177/api/openai/v1`: `GET /models`, `POST /chat/completions` (включая `stream: true`), `POST /completions`, `POST /embeddings`. Запрос идёт к провайдеру модели из `model`, без неё — к активному. Ключи провайдеров клиент не видит.
- Шлюз выключен по умолчанию. Включается через `PUT /api/openai` (`enabled`, `apiKey`, `origins`) только с локальной машины; состояние — `openai-gateway.json`, ключ — SHA-256.
- Шлюз принимает только собственный `Origin`; запросы без `Origin` (curl, SDK) проходят. Белый список `origins` отвечает CORS точным origin (не `*`, включая preflight и Private Network Access) и понимает шаблоны `@localhost` и `@lan`. С ключом шлюз требует его всегда, пароль LAN не нужен; сессия по ключу не создаётся. Без ключа в `lan` нужен пароль LAN. Неверный ключ — `401` в формате OpenAI.

## Палитра

- Поиск и выбор общие для DOM и GTK — `packages/core/modules/launcher`; модель не дублируется.
- Enter запускает приложение или открывает проект, Ctrl+Enter — основную команду проекта. Префиксы: `/` — проекты (включая ещё не открытые папки в избранных), `gh/…` — GitHub, `gl/…` — GitLab. `new/имя` создаёт проект в избранной папке или открывает уже существующую; существующая папка не перезаписывается.
- **Избранные папки** — не цели запуска: в списке их нет. Прямые дочерние папки, которых ещё нет в каталоге, попадают в поиск по тексту и в раздел «На диске» при явном `/`; пустой обзор избранные папки не сканирует. Открытие регистрирует проект.
- Хоткей: KDE — session D-Bus, Windows — `RegisterHotKey`, macOS — Swift-помощник; вне этих окружений назначайте `projector toggle`. Чужое назначение не перехватывается.
- Палитра скрывается по Esc и по потере активности **всего окна**, а не blur поля. В браузере это действует только для launcher-surface.

## Проекты

- Страницы списка и формы добавления нет: проект создаётся при первом переходе по пути, drop папки на `/` или `ide.project.path.open`. Каталог — `projects.json`; сценарии запуска — `.projector/scenarios.json` в папке проекта.
- Сценарий запуска: имя, команда, `cwd` внутри проекта, свой адрес и режим (`server` или `window`). `cwd` действует только для запуска на этой машине, не для Docker и Dev Container. Режим `window` требует HTTP/HTTPS-адрес. Файл сценариев используется и при первом открытии проекта, поэтому его можно вести вместе с кодом; команды из старых `projects.json` переносятся автоматически.
- «Убрать проект» удаляет запись и завершает процессы и терминалы, файлы остаются. Это можно сделать в настройках проекта или правым кликом по проекту в переключателе проектов. Если папка исчезла, страница предлагает создать её, указать новый путь или убрать проект.
- «Роли проекта» в настройках проекта читают `.projector/roles.json`; роли работают только после доверия к текущему хешу файла, а любая правка файла отзывает доверие.
- «Виджеты проекта» читают `.projector/widgets.json`: шаблоны из встроенных компонентов и HTML, JSON-данные, CSS и необязательный скрипт в отдельном поле `script`. Скрипт выполняется только после доверия к текущему хешу; недоверенные виджеты не попадают в промпт и не рисуются.

## Очередь сообщений агенту

- Уточнения во время хода попадают в текущий ход перед следующим запросом к модели: выполняющийся инструмент заканчивает работу, модель получает результат и новые инструкции. Сообщение во время финального текста запускает ещё один запрос в том же ходе.
- «Передаётся агенту» — ожидание подтверждения приёма. После обычного завершения сообщение уходит следующим ходом; после остановки или ошибки ждёт пользователя. Изображения и адаптеры без поддержки уточнений ждут следующего хода. Claude Code использует собственный механизм.
- Очередь хранится вместе с чатом в истории: перезагрузка страницы и обновление чата в другой вкладке возвращают сообщения и их порядок. Незавершённая передача начинается заново, сообщение не считается уже доставленным.

## Workspace

- Раскладка блоков — модуль `dock`; файлы, терминалы, агент и настройки — вкладки. Раскладка и открытые файлы — в `sessionStorage` вкладки браузера, не на сервере. Правая полоса — это панель разделов с разделом «Терминалы»: вертикальная полоса у края, группа терминалов переезжает туда из дока. Ширина панели меняется перетаскиванием границы. На средней ширине (701–1050 px) панель становится нижней под редактором, а не третьей колонкой. Проект переопределяет настройку в своей сессии.
- **Работы.** Центр работ открывается вкладкой дока: фоновые задания и живые ходы агентов всех проектов, а в Hub — всех онлайн-устройств. Колокол в панели инструментов открывает вкладку и показывает число запросов, ждущих пользователя; ответы и остановка доступны в самом списке. Подробности — в [фоновых заданиях](agent-jobs.md#центр-работ).
- **Hub.** Раздел Hub в нижней группе левой полосы показывает подключённые машины, их состояние и активные работы. На странице Hub из него открывают чужое пространство и включают или выключают уведомления по каждому устройству; локальный Projector показывает список из туннеля и открывает Hub в новой вкладке. Подробности — в [Hub](hub.md).
- **Снимки файлов.** Дерево коммита и сравнение — `FileScope` (`live`, `commit`, `compare`), запись, DnD и импорт разрешены только для `live`. HTML и архивы снимка открываются как код/файл без распаковки; Markdown, изображения и SVG рендерятся из того же снимка. Поиск по содержимому — поле с несколькими строками: рабочая копия через ripgrep (`--multiline` при переводе строки), снимок — `git grep` локально и GitLab blob search с `ref`; поиск по именам — `git ls-tree` локально. GitHub code search не принимает коммит.
- **Синхронизация Git.** Рядом с текущей веткой появляются только нужные действия: стянуть, отправить или опубликовать ветку; fetch, pull и push всегда доступны в соседнем меню. Pull работает только как fast-forward и не создаёт merge-коммит; расходящиеся ветки он честно отклоняет. Для HTTPS-remote, совпадающего с подключённым GitHub или GitLab, используется токен интеграции через временный askpass. После завершения ответа агента панель обновляется сама: изменения, ветка и открытая история перечитываются.
- **Ревью изменений.** В любом локальном diff можно сразу оставить замечание: нажать «+» рядом с номером строки или выделить фрагмент кода. Ввод и сохранённые замечания показываются прямо под строками diff с редактированием и удалением, на файлах в панели Git появляются счётчики, а сводка со сниппетами открывается во вкладке «Ревью». Команда «В чат» (`ide.review.toChat`) кладёт все замечания в поле ввода агента, не отправляя сообщение. Замечания живут в сессии вкладки браузера, не в Git и не в `.projector/`. Команды — `ide.review.*`.
- **Перетаскивание из Git.** Файл из изменений, раскрытого коммита или обзора коммита переносится в блок редактора, терминал или чат так же, как из дерева файлов. В редакторе открывается соответствующий diff (рабочая копия, индекс или коммит), а терминал и чат получают путь файла; формат переноса общий — `application/x-projector-tree-entry`.
- **Проводник.** «Показать в проводнике» (`ide.fileTree.entry.reveal`) выделяет файл или папку в системном файловом менеджере; без цели показывает корень проекта. Доступно только для локального проекта при открытии Projector на компьютере с сервером; в снимках и удалённых источниках команда скрыта.
- **Информация о записи.** «Информация…» (`ide.fileTree.entry.info`) открывает вкладку с размером, числом файлов и папок, символическими ссылками и датой последнего изменения; вкладку по явному пути открывает `ide.workbench.entryInfo.open`, обновляет `ide.workbench.entryInfo.refresh`. Для папки размер считается рекурсивно, символические ссылки не раскрываются; при очень большом объёме или истечении 4 секунд ответ помечается как частичный. Доступно для локального проекта в текущем состоянии файлов; в снимках и удалённых источниках команда скрыта.
- Ответ агента приходит по тому же потоку событий (`POST /api/agent` с `client` и `stream` отвечает `202`); без потока сервер отвечает `409` и отдаёт ответ телом запроса.
- **Автосохранение и наблюдение.** Текст сохраняется по Ctrl+S, потере фокуса, смене и закрытию вкладки; при конфликте с диском черновик сохраняется. Сервер следит (`fs.watch`, без рекурсии) за папками открытых файлов: `file-changed` обновляет вкладку без правок молча, при правках показывает панель «Загрузить с диска / Оставить мою версию»; `dir-changed` перечитывает только список раскрытых папок. Слежение привязано к странице и закрывается вместе с её потоком событий. Все вкладки делят один поток через SharedWorker (`projector-events-v1`); без него — свой поток.
- **Лимиты.** Текстовый файл: подтверждение от 10 МБ, потолок 256 МБ (читается одной строкой); изображения — 8 МБ. Поиск по содержимому (`rg`) — до 2000 символов, в том числе несколько строк, 200 результатов, до 5 совпадений на файл. Поиск по именам файлов — fuzzy по пути, до 100 путей в панели (30 у `@` в чате); снимок коммита читается через `git ls-tree`. Перенос — GNU `mv --no-clobber` (вне проекта и через symlink запрещён). Удаление — в `.projector-trash` в корне проекта (скрыт из дерева, поиска и Git).
- **Корзина.** Раздел «Корзина» в нижней группе левой полосы показывает дерево `.projector-trash`: верхние записи подписаны исходными путями, папки раскрываются на любую глубину, а справа видны размеры файлов и рекурсивный размер папок. Размеры считаются отдельным запросом с кэшем и лимитом 8 секунд / 500 тыс. записей, поэтому дерево открывается сразу, а большие папки подписываются «≥» или «считается…», пока идёт подсчёт; неполный замер клиент один раз повторяет. В шапке — суммарный размер корзины. Восстановление возвращает запись на прежнее место и создаёт недостающие папки; занятое имя не перезаписывается, а получает `(2)`. Очистка и удаление стирают записи с диска без возможности вернуть; перед ними спрашивается подтверждение. Метаданные лежат в `.projector-trash/.projector-meta`, сама папка по-прежнему скрыта из дерева, поиска и Git. Команды — `ide.trash.list`, `ide.trash.tree`, `ide.trash.sizes`, `ide.trash.refresh`, `ide.trash.restore`, `ide.trash.delete` и `ide.trash.empty`; открыть раздел — `ide.workbench.section.show` с `{ section: "trash" }`.
- **Просмотрщики.** Изображения и SVG — общий `ImageViewport`. HTML — `iframe` в песочнице без origin Projector, файлы отдаёт `/api/projects/<id>/site/<путь>`, `.git` и выход из проекта закрыты. Markdown — Milkdown/Crepe; открытие без правок файл не меняет. Архивы — список записей без извлечения (Python 3, 5000 записей, 256 МБ, 15 с).
- **Браузер.** Каждый сайт открывается на своём origin `<хост>.<s|h[порт]>.<ключ>.proxy.localhost:<порт Projector>`: настоящие относительные ссылки, fetch и localStorage, API Projector на другом origin. Прокси снимает `X-Frame-Options`/CSP, переписывает абсолютные ссылки и хранит cookies сайтов в своём jar. Работает только при открытии Projector на этом компьютере; WebSocket и service worker сайта не проксируются, текст JavaScript не переписывается, но абсолютные адреса в `fetch`, XHR, `sendBeacon` и `window.open` на лету направляются в прокси, jar живёт до перезапуска. Ключ — `browser-proxy-key`, выдаётся только странице Projector.
- **Импорт из системы.** Есть путь на диске — сервер копирует сам; нет — загрузка по одному до 512 МБ. Занятые имена не перезаписываются: `keep` (`имя (2).ext`), `replace` (старое в `.projector-trash`), `prefix` или `ask`. Команда `ide.fileTree.entry.import` (`paths`, `directory`, `conflict`, `prefix`), по умолчанию конфликт — ошибка без изменений.

## Терминал

- Лимит — 24 сессии. Стек: `node-pty`, xterm.js, WebSocket с проверкой Origin; вкладки браузера делят соединения через SharedWorker с откатом на прежний транспорт. Медленная отрисовка приостанавливает чтение PTY до подтверждения.
- Сессии живут в памяти сервера: переживают переключение вкладок и перезагрузку браузера (экран, курсор, режимы, 5000 строк), но не перезапуск Projector. Ctrl+click по пути в выводе открывает файл (относительные — от cwd сессии, затем от корня проекта).
- Сборка `node-pty` требует Python, make и C++ compiler.

## Агент Projector

- Провайдер — активный OpenAI-совместимый из `providers.json` (или `DASHSCOPE_API_KEY`/`OPENAI_URL`/`OPENAI_MODEL`). История — `agent/history.sqlite`; «Новый чат» откладывает текущий в историю, закрытые чаты остаются в индексе проекта.
- Вкладка чата называется по первому сообщению — так же, как чат в истории; пустая вкладка остаётся «Агентом».
- Диктовка: микрофон или `Mod+Shift+D` начинает и завершает запись (до пяти минут), звук превращается в WAV 16 кГц моно в браузере и уходит только выбранной в Listener модели. Текст вставляется в черновик, а не отправляется сам; «Отправить» во время записи сначала ждёт распознавание. `Esc` отменяет запись, после ошибки можно повторить тот же звук. Доступно по localhost или HTTPS при разрешённом микрофоне; модель и термины настраиваются в **Настройки → Агент → Роли агентов → Listener**.
- Выделенный текст в ленте чата цитируется кнопкой «Цитировать»: он попадает в поле ввода этого же чата как Markdown-цитата (`>` по строке на каждую строку выделения) без отправки. Выделение вне сообщений и пустое выделение кнопку не показывают.
- Ссылки в ответе: `http(s)`, `mailto` и `tel` открываются в новой вкладке браузера; путь к файлу — во вкладке редактора (`ide.editor.path.open`) с поддержкой `:12`, `:12-34` и `#L12-L34`. Контекстное меню ссылки копирует адрес, относительный или абсолютный путь; абсолютный путь вне проекта открывается как внешний файл.
- В системный промпт попадают `AGENTS.md` и `CLAUDE.md` из корня проекта (до 20 тыс. знаков) с пометкой источника; правила подтверждений они не отменяют.
- Разрешения: «Спрашивать» подтверждает не только читающие команды оболочки и изменяющие команды Projector; «Авто» делает отдельный запрос к модели, сбой проверки уходит на подтверждение; «Без вопросов» отключает подтверждения. Оценка риска — Судья Projector (настройки «Судья Projector», для чата — меню «Ещё»).
- Контекст: последние ~90 тыс. знаков вызовов; более ранние ходы сжимаются в сводку. На 80% — подсказка, на 90% — автосжатие; `/compact` и `ide.agent.chat.compact` сжимают вручную. Сжатие и проверка команд идут с минимальным размышлением.
- Возможности: картинки, уровень размышления (`providers/thinking.ts`), MCP (свои и `.mcp.json`, запуск проектного сервера и изменяющий вызов подтверждаются), `web_search`/`web_fetch` (сайты локальной сети недоступны, первое обращение подтверждается), навыки (`skills/<имя>/SKILL.md`) и команды (`commands/<имя>.md`) из папки пользователя, `.projector/`, `.claude/` проекта и встроенные навыки Projector ([навыки и команды](agent-skills.md)), хуки `PreToolUse`/`PostToolUse`/`Stop`, память, расход по цене модели.
- Пределы: `PROJECTOR_AGENT_MAX_STEPS`, `PROJECTOR_AGENT_MAX_SECONDS` (15 мин), `PROJECTOR_AGENT_MAX_TOKENS`, `PROJECTOR_AGENT_CONTEXT_TOKENS` (128000), `PROJECTOR_AGENT_BASH_SECONDS` (без предела по умолчанию); у `task` — `PROJECTOR_TASK_MAX_STEPS`, `PROJECTOR_TASK_MAX_SECONDS`, `PROJECTOR_TASK_MAX_TOKENS` (тоже без предела по умолчанию). При остановке появляется «Продолжить».
- Ход живёт в отдельном процессе (`packages/cli/app/agent-host.ts`, раннеры `packages/server/app/projector-runner.ts` и `plugin-runner.ts`): перезапуск сервера, закрытая вкладка и перезагрузка страницы его не прерывают, чат переподключается и получает ответ с начала. Остановка — только «Стоп» (`POST /api/agent/cancel`): SIGTERM, инструменты прерываются, выход не позже 2 секунд. Без сервера ход идёт не дольше 30 минут (`PROJECTOR_AGENT_IDLE_MS`); завершённый ход без подключения удаляется через час; хост старше суток останавливается. Ожидающие карточки переживают перезапуск.
- Фоновые субагенты Claude Code живут внутри процесса агента: ход не заканчивается, пока они не отчитались (не дольше 30 минут). Фоновые команды оболочки ход не удерживают и помечаются остановленными. Задачи без живого процесса при открытии чата помечаются остановленными.

## Графические чаты внешних агентов

- Claude Code, Codex, OpenCode, Cursor, Kimi Code и Antigravity работают в GUI или TUI; режим — `agentModes` в `launcher.json`, `GET/PUT /api/agent/modes`. GUI-чат требует проект; в Docker и Dev Container чат отказывает — остаётся терминал. TUI Antigravity — `agy`.
- Claude Code приходит доверенным плагином `plugins/claude-code` и идёт через Agent SDK со своими промптом, инструментами, `CLAUDE.md` и настройками. Projector ничего не добавляет в контекст, кроме включённых возможностей. Режимы разрешений — `default`, `acceptEdits`, `auto`, `bypassPermissions`.
- Codex, OpenCode, Cursor, Kimi и Antigravity — ACP по stdio (`opencode acp`, `agent acp`, `kimi acp`, `codex-acp`, `agy acp`). Один клиент JSON-RPC, `session/update` → общие события, `session/resume` / `session/load` или `session/new`, `session/request_permission`, `session/cancel`. Процесс запускается на каждый ход и не переиспользует сессии пользователя. OpenCode предпочитает `opencode2` (v2 из `@opencode/cli`), если он установлен, и откатывается на `opencode` v1. Antigravity работает в строгом режиме тонкого ACP-клиента: запускает установленный `agy` (вычищая `GEMINI_API_KEY`/`GOOGLE_API_KEY` из окружения при отсутствии явного override в `launch.json` и скрывая `/logout`), не инжектит системные промпты, инструкции фич/ролей или реплей истории — правила читаются самим `agy` из `AGENTS.md` и `.gemini/skills`; вход выполняется через сам CLI (`agy` или `agy acp --login`). Чтобы `agy` по запросу знал о виджетах, MCP-командах IDE, ролях и навыках Projector, на странице настроек Antigravity (или через `GET/PUT/DELETE /api/antigravity/skill`, команды `ide.antigravity.skill.status|install|remove`) можно явно установить официальный глобальный навык `~/.gemini/config/skills/projector/SKILL.md`.
- Параметры над вводом приходят от агента (`AgentControl`): модель, усилие, флаги, режим. Выбор запоминается в `agentDefaults`; отклонённое агентом значение показывается как фактическое.
- Слэш-команды читаются пробной `session/new` до первого хода; новый список из хода заменяет старый.
- История — единый список разговоров: чат Projector, продолжающий нативную сессию, не дублируется. Сессии без единого сообщения скрыты. Ветки субагентов скрыты, родитель читается из `_meta` или базы OpenCode (`session_v2.parent_id`).
- Вкладка нового чата называется по первому сообщению, а когда агент назовёт нативную сессию — её именем; внедрённый текст возможностей Projector в имени сессии не показывается; явный заголовок (ветка, чат из истории) не перезаписывается.
- Возможности Projector (виджеты, команды IDE через MCP) — [agent-features](agent-features.md); Lens — [agent-lens](agent-lens.md); вопросы в сторону — [agent-side](agent-side.md); форки — [chat-forks](chat-forks.md); фоновые задания — [agent-jobs](agent-jobs.md).

### Фоновые сабагенты Kimi

Текст ответа появляется сразу. Пока работают фоновые сабагенты, ход остаётся активным:
в острове видны задачи, а запросы разрешений продолжают приходить в тот же чат. Projector
читает итог из локальной записи задачи Kimi и обновляет её статус в чате.

Следующие сообщения в этом чате ждут в очереди до завершения хода. Если другой клиент уже
владеет той же нативной сессией, Projector сообщает, что она занята. «Стоп» прерывает ход
вместе с фоном.

### Продолжения OpenCode после фоновых задач

Если OpenCode ответил и оставил фонового сабагента, текст уже виден, но ход остаётся активным.
Projector ждёт отслеживаемых детей и принимает новые фоновые задачи, пока ход открыт.
Сообщение нового пользовательского хода завершает наблюдение за старым.

После завершения последнего ребёнка Projector даёт 5 секунд на доставку отчёта и ждёт
не менее 3 секунд без новых ACP-обновлений и ответов на запросы агента. Пока разрешение
или другой запрос агента ждёт ответа, соединение остаётся открытым. OpenCode может
продолжать работу в локальной истории без ACP-событий. Эту работу после закрытия хода
можно прочитать через нативную сессию OpenCode.

Наблюдение использует локальную БД OpenCode. Несовместимая схема, потеря доступа к БД
или закрытие ACP-соединения во время ожидания приводят к ошибке наблюдения. Через 20 минут
после начала наблюдения Projector проверяет, остались ли незавершённые дети. Для завершившихся
детей окно доставки отчёта сохраняется. Открытый запрос агента откладывает проверку таймаута.
Отсоединённый процесс сохраняется по правилам keep-alive (по умолчанию до 30 минут без событий).
