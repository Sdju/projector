# Плагины-агенты: что осталось

Рабочий документ: только незакрытые пункты. Контракт, манифест, доверие и текущие возможности —
[plugins](../plugins.md); устройство агентов — [architecture](../architecture.md); аналитика —
[analytics](../analytics.md) и [analytics-agent-logs](analytics-agent-logs.md). Пример
нестандартного агента — [`plugins/cursor`](../../plugins/cursor).

Декларативные ACP-агенты, доверие по хешу, `usage.command`, `projector/usage` и `backend.usageLog`
уже работают; удаление не требует перезапуска. Ниже — только то, что осталось.

## Жизненный цикл

- [ ] Hosted-агент: выключение или удаление плагина во время живого хода или задания не должно
      оставлять процесс-сироту. Нужно выбрать поведение: блокировать операцию, останавливать
      запуск с подтверждением или доигрывать его без плагина.
- [ ] Исчезнувший агент: старый чат, задание и роль должны показывать явный статус «агент
      недоступен» и не терять историю; после переустановки плагина связь должна
      восстанавливаться. Сейчас ошибка приходит общим текстом, отдельного статуса в списках нет.
- [ ] Браузерный тест агентского плагина: install → trust → enable → ход → disable → remove в
      Chromium. `packages/client/tests/plugins-ui.test.mjs` проверяет каталог, установку и
      enable/disable, но не доверие, не чат и не удаление.
- [ ] HMR и повторный reconcile не должны регистрировать агента дважды или терять состояние
      включённого плагина.

## Схема и совместимость

- [ ] `usage.kind: "http"`: решить, нужен ли http-провайдер лимитов и где хранить секрет;
      сейчас в схеме только `command` и `none`.
- [ ] `${plugin}` в `args`: разрешать путь к корню пакета для самодостаточных пакетов или
      оставить только системные бинарники.
- [ ] `usageReporting`: закрепить смысл — обязателен ли он для токенной аналитики или
      достаточно любого уведомления `projector/usage`. Схема хранит поле, поведение его не
      использует.
- [ ] Пресеты типовых диалектов: имя tool-субагента, terminal `_meta`, очистка файловых чтений,
      retry-статусы, compaction, имена plan-tool. Без них plain ACP теряет то, что встроенные
      агенты делают вручную; паритет не обещать.

## Переход встроенных агентов

- [ ] Провести Kimi через декларативный дескриптор без изменения поведения.
- [ ] Затем OpenCode, Cursor и Codex — по одному, с проверкой диалекта, сессий и фоновых команд.
- [ ] Всё, что не выражается пресетом, — маленький модуль на агента только в кодовом рантайме;
      до него — отказ с диагностикой, а не тихая деградация.

## Аналитика

- [ ] Явный статус «чат без данных» у агента, который не шлёт `projector/usage` и не имеет
      нативного журнала: сейчас такой агент просто не попадает в разрезы, а не показывает
      причину.
- [ ] Проверить by-agent, by-model, project и heatmap на фейковом агенте с `projector/usage` и
      без него.

## Изолированный runtime

- [ ] Отдельный процесс с версионированным RPC: код плагина не в процессе сервера и не в
      браузере.
- [ ] Не-ACP агенты, произвольные usage-провайдеры, нативные журналы произвольного формата.
- [ ] Разрешения и изоляция; отдельное решение по песочнице.
- [ ] Реестр/npm и автообновление — только после этого.

`projector.server` остаётся доверенным кодом в процессе сервера и не считается песочницей.

## Проверки перед закрытием

- [ ] Lifecycle: install → trust → enable → catalog → run → disable → remove → reinstall.
- [ ] Исчезнувший агент: старый чат, задание, роль; ошибка вместо default.
- [ ] Выключение во время хода и hosted rejoin.
- [ ] Analytics: usage есть и нет; отсутствие цены не превращается в ноль.
- [ ] `vp run check` целиком.
