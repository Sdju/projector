# Плагины-агенты

Рабочий план: только открытые пункты. Цель — ставить агента локальным плагином и работать без пересборки Projector. Текущее устройство плагинов — [plugins](../plugins.md), агентов — [architecture](../architecture.md), аналитики — [analytics](../analytics.md) и [analytics-agent-logs](analytics-agent-logs.md). Концепт плагинов и будущий runtime — [plugin-concept](plugin-concept/concept.md).

Главное ограничение: **в v1 плагин-агент — это данные, а не JavaScript в сервере или браузере.** Исполняемый plugin runtime, не-ACP агенты и чтение чужих нативных журналов — отдельный этап.

## Текущее состояние

Этапы 0–2 реализованы в коде: расширен валидатор манифеста, добавлены доверие по хешу, установка/удаление, серверный адаптер `agents/plugin`, `unregisterAgentBackend`, ревизия каталога, reconcile в композиции, клиентский каталог с гидратацией из `/api/agent/backends`, карточка агента в настройках плагинов и команды `ide.plugin.trust` / `ide.plugin.remove`.

Лимиты этапа 4 тоже есть: `usage.command` запускается как argv-процесс с таймаутом, а доверенный код может вернуть `backend.usage` с функцией чтения; результат нормализуется в `AgentUsage`, отдаётся через `GET /api/agent/usage/<id>`, пишется в историю лимитов и рисуется общим индикатором. `backend.usageWindows` задаёт подписи и длительность окон, поэтому плагину не нужен собственный Vue-компонент.

Токенная аналитика этапа 5 подключена: уведомление `projector/usage` маппится в событие `usage`, история сохраняет модель из отчёта, а `readAgentUsage` и графики работают без отдельного кода для плагина.

Cursor вынесен из встроенной композиции в `plugins/cursor`: декларативный манифест плюс собираемый `dist/server.cjs`, который получает `createAgents(api)` и возвращает прежний `AcpProgram` с диалектом, extensions и нормализацией выбора. Его лимиты тоже живут в плагине: `backend.usage` читает ConnectRPC и auth Cursor, `usageWindows` задаёт окна «Всего / Авто / API», а сервер отдаёт их через `/api/agent/usage/cursor`. Проверены установка, доверие, включение, регистрация в общем реестре, выключение, живой handshake с установленным `agent acp` (`PROJECTOR_TEST_CURSOR=1`) и общий маршрут лимитов.

Открыто: полный живой ход Cursor с моделью, поведение при выключении во время запуска и hosted rejoin, статусы исчезнувшего агента в истории/заданиях/ролях, HTTP-провайдер лимитов в манифесте, нативные журналы и UI-тест установки агентского плагина в Chromium.

## Три критерия готовности

Полноценность считается по трём независимым слоям; нельзя закрыть один и объявить готовым остальные.

- [ ] **Агент.** Установка, доверие, включение, чат, инструменты, permissions, сессии, терминал, удаление без перезапуска.
- [ ] **Usage.** Лимиты подписки: индикатор, история окон, запись в аналитику лимитов. Агент без провайдера лимитов честно показывает их отсутствие.
- [ ] **Аналитика.** Токены, модель, проект и стоимость в общих графиках, если агент присылает normalized usage. Если не присылает — явный статус «нет данных», а не нули. Нативные журналы в v1 не поддерживаются.

## Решение

- Версия API остаётся `1`: контракт ещё в проработке и не заморожен. `contributes.themes` становится необязательным, появляется `contributes.agents`. Хотя бы один вклад обязателен.
- Существующие theme-only манифесты остаются валидными: `themes` не удаляется, новые поля необязательны. Несовместимое изменение или заморозка контракта — отдельное решение, и только тогда понадобится новая версия API.
- Агент описывается декларативно: `id`, `title`, `caption`, `icon`, `program`, `terminal`, `command`, `args`, `binary`, `clientCapabilities`. Запуск идёт через существующий `createAcpBackend` и plain ACP.
- `usage` и `usageReporting` закладываются в схему v1 сразу, даже если реализация появится позже. Пока версия не заморожена, расширение не требует новой версии API.
- Серверный реестр — единственный источник истины. Клиент получает агентов из `GET /api/agent/backends`, а не из статического списка импортов.
- Включение агентского плагина требует явного доверия: показ команды и хеш содержимого пакета. Установка не включает агента автоматически.
- Встроенные агенты остаются в композиции. Переводить их на плагины целиком не нужно; для проверки контракта достаточно Kimi.
- Никакого произвольного JS, Vue, CSS, команд, настроек и серверных обработчиков от плагина в v1.

## Границы

Входит:

- ACP-агенты, запускаемые как внешний процесс;
- чат и терминал;
- plain ACP: текст, мысли, tool calls, permissions, controls, команды, MCP, картинки, стандартное сжатие;
- включение, доверие, диагностика, удаление;
- общий контракт лимитов и общий индикатор;
- normalized usage extension для токенной аналитики.

Не входит:

- JavaScript в сервере или браузере;
- агенты на своём SDK без ACP;
- кастомные диалекты, формы и plan readers в манифесте;
- нативные журналы произвольного формата;
- npm-реестр, автообновление, подписи пакетов;
- секреты и ключи в манифесте;
- свои Vue-компоненты и произвольные иконки.

## Масштаб по слоям

### Агент

Переиспользуется: запуск процесса, initialize/auth, `session/new` и `session/load`, prompt с файлами и картинками, текстовые чанки, мысли, `tool_call`/`tool_call_update`, permissions, controls, команды, MCP, стандартное сжатие.

Пишется на агента отдельно (приблизительно, по текущим модулям):

- Codex — `dialect.ts` около 139 строк: субагенты, `terminal_output_delta`, `terminal_exit`, фоновые команды;
- OpenCode — диалект около 264 строк и декоратор сессий около 80: дочерние сессии, retry, старая схема compaction, фоновые команды, разбор чтений;
- Cursor — около 364 строк: вложенные вызовы, `task`, план, todos, вопросы, нормализация выбора, картинки;
- Kimi — около 34 строк: нумерация строк в файловых чтениях;
- Claude Code — не ACP, около 1,4 тыс. строк SDK-адаптера.

Итого около 1 000 строк серверной специфики на четыре ACP-агента, без usage-логов и клиентских plan readers. Plain ACP не даёт группировку субагентов, фоновые команды, потоковый вывод терминала, retry-статусы, нестандартный compaction, очистку чтений, план, кастомные формы и вопросы, rename/pin/rewind, inject, branch и compact.

- [ ] В v1 честно объявить: базовый чат, без паритета со встроенными.
- [ ] Добавить декларативные пресеты типовых паттернов: имя tool-субагента, terminal `_meta`, очистка файловых чтений, имена plan-tool.
- [ ] Для остального разрешить маленький per-agent модуль внутри пакета только на этапе кодового рантайма; до него — отказ с диагностикой.

### Usage

Сейчас каждый из пяти агентов несёт свой клиент, парсер, credentials, кеш, route и Vue-индикатор — около 1 100 строк. ACP `usage_update` даёт `used`/`size`/`cost` контекстного окна и маппится в `context`, а не в лимиты подписки.

- [ ] Один контракт `AgentUsage`: `status`, `checkedAt`, `windows`, `message`.
- [ ] Провайдер `command`: argv, JSON в stdout, таймаут, лимит вывода, без shell.
- [ ] Провайдер `none`: индикатор не показывается.
- [ ] Провайдер `http` и ссылки на секреты — позже и отдельным решением.
- [ ] Общий route, кеш и `recordAgentLimits(id, payload)`.
- [ ] Один generic-индикатор вместо Vue-компонента на агента.

### Аналитика

Сейчас `usage` в сохранённых ответах шлют только Projector и Claude. Codex, OpenCode и Kimi попадают в графики через нативные журналы; Cursor — только через лимиты. ACP не передаёт per-request input/output/cache-токены. Подробности и долги по журналам — в [analytics-agent-logs](analytics-agent-logs.md).

- [ ] Необязательное расширение `projector/usage`: уведомление или `_meta` в `session/update` с `input`, `output`, `cacheRead`, `cacheWrite`, `model`, `cost?`.
- [ ] Общий маппер превращает его в событие `usage`; история уже умеет его хранить, `readAgentUsage` и графики работают без изменений.
- [ ] Модель сохранять из `context.model`; стоимость — только если агент её сообщил. Не выдумывать тарифы для чужих моделей.
- [ ] Если данных нет, показывать источник «чат без данных», а не нулевые токены.
- [ ] Нативные журналы не описывать декларативно. Они остаются в per-agent коде или кодовом рантайме.

## Манифест

```json
{
  "name": "@acme/example-agent",
  "version": "1.0.0",
  "engines": { "projector": ">=0.12.0" },
  "projector": {
    "apiVersion": 1,
    "contributes": {
      "agents": [
        {
          "id": "example-agent",
          "title": "Example Agent",
          "caption": "Запустит Example через ACP",
          "icon": "sparkles",
          "program": "example-agent",
          "terminal": { "executable": "example-agent", "title": "Example" },
          "command": "example-agent",
          "args": ["acp"],
          "binary": "example-agent",
          "usage": {
            "kind": "command",
            "command": "example-agent",
            "args": ["usage", "--json"],
            "timeoutMs": 10000
          },
          "usageReporting": "projector/usage"
        }
      ]
    }
  }
}
```

Правила:

- [ ] `id` и `program` уникальны среди зарегистрированных агентов и терминальных программ. Встроенные id зарезервированы; коллизия — диагностика, а не замена.
- [ ] `command` и `args` — argv-массив, без shell-строки, подстановок окружения и секретов.
- [ ] `icon` — имя из allowlist, не путь и не SVG.
- [ ] `capabilities` в v1 — только то, что реально умеет ACP-рантайм. `inject`, `branchSession`, `rewindFiles` и `compact` не объявляются, пока для них нет реализации; иначе UI покажет неработающую кнопку.
- [ ] `usage.command` запускается отдельно, с таймаутом и лимитом stdout; ошибка провайдера не ломает чат.
- [ ] Установка агентского плагина не включает его. В `plugins.json` хранится `trustedHash`; изменение содержимого требует повторного доверия.
- [ ] Нет `env`, `secrets`, `prompt`, `settings` и произвольных HTTP-заголовков в v1.

Открытые вопросы:

- [ ] Разрешать ли `${plugin}` в `args` для самодостаточных пакетов или только системные бинарники?
- [ ] Нужен ли `icon` из файла с санитизацией или достаточно allowlist?
- [ ] Делать ли `usage.kind: "http"` в v1, если у агента есть готовый endpoint, и как хранить секрет?
- [ ] Считать ли `usageReporting` обязательным для попадания в токенную аналитику или достаточно факта `usage`-события?

## Жизненный цикл

- [ ] `unregisterAgentBackend(id)`: запрет на встроенных и default; отказ или остановка при живых запусках и заданиях.
- [ ] Ревизия каталога агентов; `GET /api/agent/backends` отдаёт ревизию и презентационные поля.
- [ ] Reconcile при старте, enable/disable, install/remove, refresh. Повторный вызов идемпотентен.
- [ ] `GET /api/agent/backends` и запуск агента ждут готовности плагинов; `bindRuntime` остаётся синхронным.
- [ ] HMR не регистрирует агента дважды; состояние в `globalThis`.
- [ ] `resolveAgentBackend`: явно названный, но исчезнувший id — ошибка. Default только когда агент не назван вовсе.
- [ ] Hosted-запуск плагинного агента: при выключении плагина не оставлять сироту; либо блокировать выключение, либо останавливать запуск с подтверждением.
- [ ] API удаления плагина и IDE-команда; сейчас удаления нет.
- [ ] Старые чаты, задания, роли и записи аналитики с исчезнувшим id: статус «агент недоступен», данные не удаляются.

## Клиент

- [ ] Реактивное хранилище агентов вместо статической Map; `clientAgents()` остаётся синхронным чтением, но обновляется после гидратации.
- [ ] Гидратация из `/api/agent/backends` до монтирования приложения либо динамический импорт после неё.
- [ ] `icon`, `usage`, `plan`, `caption` становятся необязательными; fallback-иконка и подпись из манифеста.
- [ ] `tab-views.ts` сейчас собирает виды вкладок на уровне модуля — нужен реестр или пересборка после гидратации.
- [ ] `features.ts` не должен хранить снимок `listAgentBackends()`; нужен refresh или чтение живого реестра.
- [ ] Раздел плагинов: карточка агента, команда, доступность, доверие, удаление, диагностика.
- [ ] Страница агента в настройках работает для плагинного агента без отдельного Vue-модуля.
- [ ] После enable/disable обновлять меню «+», вкладки, режимы, роли, задания и статус-бар.

## Этапы

### 0. Контракт и доверие — 3–4 дня

- [ ] `apiVersion` остаётся `1`; `themes` необязателен; валидатор `contributes.agents`; зафиксировать, что схема v1 ещё не заморожена.
- [ ] Резерв встроенных id, проверка коллизий id и program.
- [ ] `trustedHash` и состояние доверия в `plugins.json`; агентские плагины не auto-enable.
- [ ] Схема `usage` и `usageReporting`, даже без реализации.
- [ ] Тесты валидатора: эталонный манифест, неизвестные поля, опасный argv, коллизии, отсутствие вкладов.

Выход: эталонный агентский манифест проходит, опасный — отклоняется с понятной диагностикой.

### 1. Серверный рантайм — 5–7 дней

- [ ] Новый модуль `packages/server/modules/agents/plugin`: дескриптор → `AcpProgram` → `createAcpBackend`; значения по умолчанию для program и terminal.
- [ ] `unregisterAgentBackend`, ревизия, ошибка для исчезнувшего именованного агента.
- [ ] Reconcile в `server/modules/plugins`; агенты в каталоге плагинов; удаление.
- [ ] Динамические features вместо снимка; preferences и terminal уже читают реестр лениво.
- [ ] Startup gate и идемпотентность при HMR.
- [ ] Тест с фейковым ACP-агентом: установка, доверие, включение, ход, выключение.

Выход: через API плагинный агент появляется, проходит ход и исчезает без перезапуска.

### 2. Клиент — 5–7 дней

- [ ] Реактивный каталог и гидратация с сервера.
- [ ] Fallback-иконка и подпись; необязательные usage/plan.
- [ ] Реестр видов вкладок вместо модульного снимка.
- [ ] Карточка агента в плагинах: команда, доступность, доверие, удаление.
- [ ] Общий каркас индикатора лимитов.
- [ ] Проверка: полный ход из GUI, вкладка терминала, меню «+», выключение без reload.

Выход: установка и выключение агента видны во всех поверхностях без перезагрузки.

### 3. Надёжность — 3–5 дней

- [ ] Исчезнувший агент: ошибка вместо default; статусы в истории, заданиях и ролях.
- [ ] Коллизии, выключение во время хода, hosted rejoin.
- [ ] Удаление плагина с активными чатами и заданиями.
- [ ] HMR и повторный reconcile.
- [ ] Тесты: удалить плагин, открыть старый чат, запустить задание, установить обратно.

Выход: удаление плагина не подменяет агента и не ломает данные.

### 4. Usage — 5–8 дней

- [ ] Контракт `AgentUsage` в core; переиспользовать `usageWindowsOf`.
- [ ] Command-провайдер: argv, timeout, лимит stdout, без shell.
- [ ] Общий route и кеш; `recordAgentLimits(id, payload)`.
- [ ] Generic-индикатор и `usage` в клиентском каталоге.
- [ ] История лимитов в аналитике по plugin-агенту.
- [ ] Тест с фейковым провайдером: ready, unavailable, timeout, мусор в stdout.

Выход: индикатор и история лимитов работают, провайдер не влияет на чат при ошибке.

### 5. Аналитика — 5–8 дней + принятие автором агента

- [ ] Контракт `projector/usage` и маппинг в событие `usage`.
- [ ] Сохранение модели и стоимости; отсутствие цены не превращать в ноль.
- [ ] Статус источника «чат без данных» для агента без usage.
- [ ] By-agent label из каталога; проверка by-model, project, heatmap, daily.
- [ ] Тест с фейковым агентом, который шлёт и не шлёт usage.
- [ ] Документация для авторов: без `projector/usage` токенной аналитики не будет.

Выход: агент с usage виден в токенах, модели и проекте; агент без usage даёт явный статус, а не пустой график.

### 6. Фиделити — 5–10 дней на пресеты, далее по агенту

- [ ] Пресеты: субагент по tool, terminal `_meta`, очистка чтений, retry, compaction, имена plan-tool.
- [ ] Прогнать Kimi через декларативный дескриптор, не меняя поведения.
- [ ] Затем OpenCode, Cursor, Codex — по одному, с проверкой диалекта и сессий.
- [ ] Всё, что не выражается пресетом, — маленький модуль на агента или отказ с диагностикой.

Выход: Kimi на декларативном пути; один реальный сторонний ACP-агент проходит базовый сценарий.

### 7. Изолированный кодовый рантайм — 3–6 недель, не в MVP

Узкий доверенный `projector.server` уже есть: Cursor загружает `createAgents(api)` в процессе сервера. Это не песочница и не произвольный UI.

- [ ] Отдельный процесс с версионированным RPC; код плагина не в процессе сервера и не в браузере.
- [ ] Не-ACP агенты, нативные журналы, произвольные usage-провайдеры.
- [ ] Доверие, разрешения и изоляция; отдельное решение по песочнице.
- [ ] Реестр/npm и автообновление — только после этого.

Выход: отдельный ADR и план; изолированный runtime в текущий роадмап не входит.

## Оценки

| Блок                                       | Оценка                                                      |
| ------------------------------------------ | ----------------------------------------------------------- |
| Рабочий ACP-чат без пересборки (этапы 0–3) | около 3 недель                                              |
| Плюс лимиты (этап 4)                       | 4–5 недель суммарно                                         |
| Плюс токенная аналитика (этап 5)           | 5–7 недель суммарно, при условии принятия `projector/usage` |
| Паритет с нестандартным агентом            | +1–2 недели на агента                                       |
| Не-ACP и нативные журналы                  | +3–6 недель отдельного рантайма                             |

Оценки для одного разработчика, без ревью и релизного цикла. «5–6 недель» из ранней прикидки — это платформа, а не паритет с встроенными агентами.

## Риски

- [ ] **Молчаливый откат на default.** `resolveAgentBackend` сейчас возвращает default для неизвестного id. Исправить до включения удаления плагинов.
- [ ] **Снимки каталога.** `tab-views.ts`, `features.ts` и часть меню читают список при инициализации. Без реестра или refresh plugin-агент появится не везде.
- [ ] **Асинхронный старт.** Обнаружение плагинов async, `bindRuntime` sync. Нужен ready-промис, который ждут API и запуск.
- [ ] **HMR.** Повторная регистрация и reconcile могут дублировать агента или терять состояние.
- [ ] **Выполнение команд.** Агентский плагин — это произвольный процесс. Доверие по хешу, показ argv, запрет shell и env, повторное доверие после изменения.
- [ ] **ACP не даёт токены.** Не выдавать `context.used/size` за расход. Без `projector/usage` аналитика по агенту пустая.
- [ ] **Диалект.** Plain ACP теряет субагентов, фон, план и сессии. Не обещать паритет; писать «plain ACP».
- [ ] **Устаревшие id.** История, задания, роли и аналитика хранят backend id. Нужен статус «недоступен» и восстановление после переустановки.
- [ ] **Нет удаления плагина.** Для агента жизненный цикл неполный; добавить API и команду.
- [ ] **Hosted-запуски.** Выключение плагина во время хода не должно оставлять сироту или тихо убивать работу.

## Проверки

- [ ] Валидатор: неизвестные поля, `apiVersion`, отсутствие вкладов, reserved id, коллизии, опасный argv, размеры.
- [ ] Lifecycle: install → trust → enable → catalog → run → disable → remove → reinstall.
- [ ] Фейковый ACP-агент в fixture: полный ход, permissions, отмена, сессия, терминал.
- [ ] Клиент: меню «+», вкладки, настройки, роли, задания, статус-бар; disable без reload.
- [ ] Исчезнувший агент: старый чат, задание, роль; ошибка вместо default.
- [ ] Usage: ready/unavailable/timeout/мусор; индикатор и история лимитов.
- [ ] Analytics: usage есть/нет; by-agent, by-model, project, heatmap; отсутствие цены.
- [ ] HMR: повторный `bindRuntime`, повторный reconcile.
- [ ] Точечно: `vp test related <файл>`, затем `vp check <файлы>`, перед коммитом — `vp run check`.
