# Файловые снимки: что осталось

Рабочий документ: только открытые пункты. Устройство, контракт `FileScope` и поведение снимков описаны в [architecture.md](../architecture.md), [usage.md](../usage.md) и [ide-commands.md](../ide-commands.md); здесь они не повторяются.

## Открыто

- **Сравнение двух произвольных папок на диске** — отдельный scope с allowlist, не расширение `commit`/`compare`.
- **Полное union-дерево** — только если понадобится показывать неизменённые файлы в сравнении; тогда расширять `TreePage`, а не UI.
- **Индекс** — не добавлять в `FileScope`, пока не появится отдельное дерево индекса: у него другая семантика.
- **Переименования** — показывать как deleted + added; `originalPath` использовать для подписи и перехода.
- **GitHub-поиск по снимку** — только с отдельным механизмом (индекс, клон или API с `ref`). GitLab blob search требует Advanced Search: без него показывается ошибка, а не пустой результат.
- **Кто владеет ревизией** — раздел или команда передаёт готовый хеш; scope хранит только его.

## Границы, которые решены

- **MR остаётся адаптером.** `pull-files`/`pull-diff` — источник истины для merge request, общий словарь `FileChange` и `ChangesTree` дают единый вид. Compare scope для MR не вводим: у локальной копии может не быть удалённых хешей, а GitLab compare теряет часть метаданных MR.
- **HTML и архивы на снимке отключены явно** — HTML открывается как код, архив не распаковывается; вкладка подписывает причину.
- **Live-ключи не меняются** — сессии и кеши рабочей копии сохраняют прежний вид (`path:file`, `path:index`, `path:working`, `external:...`).

## Чего не делать

- Не заводить профиль на каждый коммит: профиль — источник и его возможности, а не позиция в истории.
- Не протаскивать `rev` строкой через все вызовы: снимок передаётся как scope, параметры добавляет один адаптер.
- Не делать второе дерево «для истории»: отличаться должен источник, а не компонент.
- Не считать `commit-diff` готовым деревом: он отдаёт только изменённые файлы.
- Не вводить `FileSource`/`FileSourceCapabilities` без нового реального потребителя.
