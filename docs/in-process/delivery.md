# Поставка и доступ с других устройств

Рабочий документ: только открытые пункты. Текущее устройство — [distribution](../distribution.md),
[npm-release](npm-release.md), [usage](../usage.md). Обновления плагинов — отдельная работа:
[plugin-distribution-trust](plugin-distribution-trust.md).

Цель: удобный доступ с телефона и понятное предложение обновиться из npm. Установка остаётся
`npm install -g @ai-projector/ide` (Node 24, при необходимости сборка `node-pty` / `node-gtk`).

## Решение

- **Только npm registry.** Каналы AppImage, deb, Flatpak, установщик Windows, `.app` для macOS,
  GitHub Releases как способ установки и любой «один установщик с runtime» закрыты и не
  возвращаются. Публикуемые пакеты — `@ai-projector/ide`, `@ai-projector/native`,
  `@ai-projector/hub`; процедура — [distribution](../distribution.md).
- **Checkout не трогаем.** `vp dev`, `./bin/projector`, `vp run desktop` и режимы `dev`/`prod`
  из исходников остаются. Предложение обновиться из npm им не показываем.
- **GTK-палитра** остаётся необязательным npm-пакетом той же версии, не отдельным установщиком.
- **Автоподмена работающего процесса запрещена.** `projector restart` завершает терминалы и
  дочерние процессы ([usage](../usage.md#сервер)). Глобальный `npm install -g` не может безопасно
  перезаписать загруженные модули Node. Первый шаг — проверить registry и предложить команду,
  а не ставить пакет изнутри сервера.
- Машина без Node не является целевым сценарием поставки. Требования Node и build tools живут
  в [distribution](../distribution.md#известные-ограничения-установки); prebuilt `node-pty` /
  `node-gtk` через npm — отдельный позже, не повод возвращать OS-пакеты.

## Сейчас

- Источник `checkout` / `npm` / `other`, `/api/health` отдаёт `version` и `source`, экран
  «О приложении», inbox для npm-канала и `projector version --json` с `latest` без падения
  офлайн. Процесс не вызывает `npm install -g`.
- LAN — HTTP, cookie на 8 часов, отзыв только сменой пароля. PWA на `localhost` работает, в LAN
  по HTTP — нет; настройки PWA это уже говорят. QR входа есть у Hub, у локального Projector нет.

## Как делают другие ADE

Проверено по исходникам и докам, не по обзорам. Локально: Codex `0.171.0` (Vite+ shim),
OpenCode `v2.0.24` (`~/.opencode/bin`), Cursor Agent `2026.11.10` (три версии в
`~/.local/share/cursor-agent/versions/`), Kimi `2.6.3` (`~/.kimi-code/bin`).

Общее у CLI: определить канал установки, проверить latest в фоне, предложить, применить
**после** сессии или **рядом** с текущей версией. Никто не подменяет дерево, из которого
сейчас исполняется процесс.

- **Codex.** `codex update` и попап при старте TUI. Канал: env шима
  (`CODEX_MANAGED_BY_NPM` / bun / pnpm / Vite+) плюс путь для brew и standalone. Source/debug
  не обновляет. Кеш `version.json` ~20 ч, сеть не блокирует UI. Кандидат — GitHub Release,
  для npm-каналов ещё `ensure_version_ready`: `dist-tags.latest` совпадает с релизом и есть
  `dist.tarball` + `dist.integrity` (GH и npm не атомарны, [PR 19389](https://github.com/openai/codex/pull/19389)).
  После выхода TUI spawn `npm install -g @openai/codex` в cwd `/`, чтобы не подхватить
  проектный `.npmrc`. Команда **без** `@версия`: из-за этого Windows-апдейтер предлагал
  0.151.0, а npm ставил 0.149.0 и снова показывал попап
  ([#41876](https://github.com/openai/codex/issues/41876)). Это CLI, не демон: после npm
  просят перезапустить Codex.
- **Claude Code.** Native: `~/.local/share/claude/versions/` + symlink, качает в фоне,
  вступает **со следующего запуска**. npm — автообновление, если global prefix доступен
  на запись, иначе одноразовое предупреждение и `claude doctor`. Каналы `latest`/`stable`,
  `DISABLE_AUTOUPDATER` / `DISABLE_UPDATES`. OS-пакеты сами не обновляются (нужны права).
- **Cursor Agent.** Тоже versioned dir + symlink, `agent update` и `/update` в сессии.
  Автоочистка не трогает каталог, который держит живой процесс; если файлы всё же исчезли —
  просят restart, а не падают с module error.
- **OpenCode.** `opencode upgrade [версия] --method …`. Latest с GitHub Releases. npm-команда
  **пинит** `opencode-ai@${target}`. Method угадывается по path и `npm list -g`; есть ручной
  `--method`.
- **Gemini CLI.** `latest-version` к npm при старте (таймаут 2 с), `DEV=true` пропускает.
  Для npm/pnpm/yarn/bun/volta spawn в фоне; brew/git/проект — только текст команды;
  npx и бинарник — молча. Новая версия со следующего запуска.
- **Kimi.** `kimi upgrade`/`update`: npm-канал ставит пакет на переднем плане, native качает
  бинарник и меняет его со следующего старта. `-y` без подтверждения.

Для Projector из этого следует другое, чем «сделать как Codex»:

1. Мы — долгоживущий Node-сервер с терминалами и ходами агентов, не TUI, который выходит
   и потом зовёт npm. Spawn `npm install -g` из живого процесса подменит `node_modules`
   и `node-pty` у себя под ногами.
2. Versioned dir + symlink (Claude/Cursor/Kimi native) безопасен именно потому, что новая
   версия лежит **рядом**. У глобального npm такого каталога нет; заводить свой — второй
   установщик, это закрыто.
3. Источник latest для нас — npm registry, не GitHub Release: единственный канал поставки.
   Перед предложением проверить `dist-tags.latest`, наличие версии и `dist.integrity`.
4. В команду ставить **точную** версию, не плавающий `@latest` (урок Codex #41876 и плюс
   OpenCode).
5. Маркер канала надёжнее эвристики: Codex пишет env из JS-шима. Имеет смысл, чтобы `bin`
   опубликованного `@ai-projector/ide` выставлял `PROJECTOR_MANAGED_BY_NPM=1`.
6. Скрытие «не напоминать» — на конкретную latest, как у Codex.

## Обновления

Первый шаг: **проверка + предложение**. Установка пакета из процесса Projector не входит.

### Проверка

- Источник: HTTPS `registry.npmjs.org` для `@ai-projector/ide` (и native/hub, если они стоят).
  Не вызывать `npm` ради номера версии: чужой CLI-конфиг, дольше, лишняя зависимость от npm 12.
  Шаблон запроса — как у загрузки медиа: только HTTPS, таймаут, лимит тела, без редиректов.
- Предлагать версию только если `dist-tags.latest` указывает на неё и в metadata есть
  `dist.tarball` и `dist.integrity` (как `ensure_version_ready` у Codex). GitHub Release не
  источник истины: пакет мог ещё не появиться в registry.
- Сравнивать установленную semver с этим `latest`. Канала `beta`/`next` нет — не выдумывать
  настройку канала, пока тег не публикуется.
- Кеш в каталоге данных (порядка суток, как 20 ч у Codex). Офлайн и сбой registry не
  блокируют запуск и не шумят в UI. Повтор по команде `ide.app.update.check`.
- Не проверять provenance ради сравнения номеров. Подпись пакета уже есть у публикации (OIDC);
  она понадобится только если когда-нибудь сами скачаем tarball.

### Источник установки

Нужны три состояния, иначе checkout начнёт предлагать `npm install -g` поверх исходников:

- `checkout` — корень с git и без `node_modules/@ai-projector/ide` как корня пакета; CLI уже
  отличает собранный пакет по `packages/server/app/standalone.js`, этого мало: `projector mode
  prod` в checkout тоже собранный.
- `npm` — корень пакета внутри `node_modules/@ai-projector/ide` (глобальный prefix или
  `--prefix ~/.local`), либо `PROJECTOR_MANAGED_BY_NPM` из опубликованного `bin`.
- `other` — npx-кеш, распакованный tarball, неизвестно. Предложение можно показать, команду —
  с оговоркой «если ставили через npm».

### Предложение

- Раздел настроек «О приложении»: текущая версия, источник, версия native если стоит, latest,
  ссылка на GitHub Release / CHANGELOG этой версии, копируемая команда.
- Одно inbox-уведомление на конкретную latest-версию: «доступна 0.x.y», ссылка в этот раздел.
  Скрытие запоминает номер; следующая версия снова уведомляет. Не тост на каждый загруз страницы
  и не `TrustNotice` — это не вопрос доверия.
- Команды: `ide.app.update.check`, `ide.app.update.copyCommand`. Кнопка «обновить» в первом шаге
  не ставит пакет, а копирует команду и предупреждает про restart.
- CLI `projector version --json` может добавить `latest` и `outdated`, без сетевой ошибки как
  падения команды.
- Команда для npm 12 (пример, версии подставить из registry):

      npm install -g --allow-scripts=node-pty @ai-projector/ide@<версия>
      # если стоит native:
      npm install -g --allow-scripts=node-pty,node-gtk @ai-projector/native@<версия>
      projector restart

- Если ide и native разошлись — предупреждение lockstep, даже когда latest не новее ide.
  Локально установленный hub в том же prefix — в ту же подсказку. Удалённый Hub (другая машина
  или VPS) Projector не обновляет.

### Что не делать

- Тихое автообновление и «обновить при выходе».
- `npm install -g` из процесса сервера: нет прав на prefix, npm 12 режет scripts, модули уже
  загружены, restart убивает терминалы и ходы агентов.
- Скачивать tarball в `$XDG_DATA_HOME` и подменять дерево пакета: это второй установщик.
- Смешивать с обновлениями плагинов: у них своё доверие по хешу и отдельный документ.

### Позже, не сейчас

- Кнопка, которая запускает `npm` в дочернем процессе, если prefix доступен на запись, затем
  предлагает restart с явным предупреждением. Только после того, как проверка и предложение
  работают.
- Dist-tag `next`, если появится бета.
- Prebuilt native-аддоны в npm, чтобы снять Python/make/C++. Это всё ещё registry, не OS-пакет.

### Доступ по локальной сети

- [ ] HTTPS для LAN (self-signed или локальный CA), чтобы адрес стал доверенным контекстом:
      PWA, service worker, Web Push, clipboard.
- [ ] Если HTTPS остаётся вне рамок — явно писать в интерфейсе, почему на телефоне нет
      установки и уведомлений, и не обещать их. Бейдж «HTTP в сети» в PWA-настройках уже есть;
      того же нет в панели LAN и в предложении открыть с телефона.
- [ ] QR-код с LAN-адресом в настройках сети и панели LAN. Одноразовый QR входа в Hub
      (60 секунд) уже есть и не заменяет вход в локальный Projector. Пароль в QR не класть
      без предупреждения.
- [ ] Web Push для завершения задания, вопроса и разрешения; без HTTPS он невозможен.
- [ ] Список доверенных устройств LAN и отзыв сессий; сейчас пароль даёт cookie на 8 часов, а
      отзыв есть только сменой пароля.

### Мобильное

- [ ] Разница PWA на `localhost` и в LAN видна не только в «Интерфейс → Приложение».
- [ ] Ссылка «открыть на телефоне» с QR из настроек сети.
- [ ] Не ломать существующую мобильную раскладку и нижнюю панель.

## Границы

- Не делать облачный сервис и синхронизацию между машинами: Projector остаётся локальным
  сервером.
- Не хранить пароль LAN в открытом виде и не включать его в QR без предупреждения.
- Не ставить OS-пакеты, бинарные установщики и runtime-бандлы «без Node».
- Не обновлять удалённый Hub с локальной машины.
- Не автообновлять плагины этим же механизмом.

## Открытые вопросы

- Устраивает ли предупреждение браузера о self-signed сертификате или нужен локальный CA?
- Нужен ли Web Push или достаточно уведомлений при открытой PWA?
- Когда появится кнопка «поставить через npm»: только если prefix доступен на запись, или
  достаточно копируемой команды навсегда?
- Нужен ли канал `next`, или достаточно `latest`?

- [ ] Скрытие уведомления не возвращается на той же latest и возвращается на следующей.
- [ ] LAN с телефона: вход, PWA (или честный отказ), отзыв пароля.
