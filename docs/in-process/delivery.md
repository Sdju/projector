# Поставка и доступ с других устройств

Рабочий документ: только открытые пункты. Текущее устройство — [distribution](../distribution.md),
[npm-release](npm-release.md), [usage](../usage.md).

Цель: установка без сборочного окружения и удобный доступ с телефона. Сейчас Projector
ставится из npm (`0.11.1`), требует Node 24 и сборки `node-pty`/`node-gtk`, а LAN работает по HTTP.

## Установка

- [ ] Бинарная или пакетная поставка: AppImage/deb/Flatpak для Linux, установщик Windows,
      `.app` для macOS; либо один установщик, который сам поднимает нужный runtime.
- [ ] Prebuilt `node-pty` и `node-gtk` или отказ от сборки при установке; понятная ошибка,
      если build tools нет.
- [ ] Автообновление и канал stable/beta; проверка подписи или checksum перед запуском.
- [ ] Не ломать текущие пути: checkout, `@ai-projector/ide`, `@ai-projector/native` и
      `projector-install-desktop` остаются рабочими.
- [ ] Документировать первый запуск без Node и без GTK: что именно нужно и что необязательно.

## Доступ по локальной сети

- [ ] HTTPS для LAN (self-signed или локальный CA), чтобы адрес стал доверенным контекстом:
      PWA, service worker, Web Push, clipboard.
- [ ] Если HTTPS остаётся вне рамок — явно писать в интерфейсе, почему на телефоне нет
      установки и уведомлений, и не обещать их.
- [ ] QR-код с LAN-адресом и паролем или одноразовым токеном в настройках и панели LAN.
      Одноразовый QR входа в Hub (60 секунд) уже есть, но он ведёт на Hub и не заменяет вход в
      локальный Projector.
- [ ] Web Push для завершения задания, вопроса и разрешения; без HTTPS он невозможен.
- [ ] Список доверенных устройств LAN и отзыв сессий; сейчас пароль даёт cookie на 8 часов, а
      отзыв есть только сменой пароля.

## Мобильное

- [ ] Проверить установку PWA на `localhost` и в LAN; разница должна быть видна в интерфейсе,
      а не только в документации.
- [ ] Ссылка «открыть на телефоне» с QR из настроек.
- [ ] Не ломать существующую мобильную раскладку и нижнюю панель.

## Границы

- Не делать облачный сервис и синхронизацию между машинами: Projector остаётся локальным
  сервером.
- Не хранить пароль LAN в открытом виде и не включать его в QR без предупреждения.

## Открытые вопросы

- Какой формат поставки первый: AppImage, deb, Flatpak или установщик Windows?
- Устраивает ли предупреждение браузера о self-signed сертификате или нужен локальный CA?
- Нужен ли Web Push или достаточно уведомлений при открытой PWA?
- Делать ли отдельный установщик для native-палитры или оставить её необязательной?

## Проверки перед закрытием

- [ ] Чистая машина без Node, GTK и build tools: установка, запуск, обновление.
- [ ] LAN с телефона: вход, PWA, уведомления, отзыв пароля.
- [ ] `vp run build:distribution` (с самопроверкой) и `vp run check` остаются зелёными.
