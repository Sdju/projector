# Цикл ревью изменений

Рабочий документ: только открытые пункты. Текущее устройство — [usage](../usage.md#workspace),
[ide-commands](../ide-commands.md#git-commands), [agent-jobs](../agent-jobs.md),
[integrations](../integrations.md).

Цель: человек проходит путь «посмотрел diff → оставил замечания → поправил или принял →
закоммитил → отправил» внутри Projector. Сейчас панель умеет stage/unstage/discard, ветки,
diff, снимки и обмен с remote (fetch/pull/push); commit, публикация ревью и частичное принятие
заданий остаются терминалу и браузеру.

## Замечания к изменениям

- [ ] Аннотация строки или диапазона в diff: текст, автор, статус (открыто, исправлено,
      принято), ответ агента.
- [ ] Список замечаний по файлу и по всему изменению; переход к строке; фильтр «только
      открытые».
- [ ] Отправка пачки замечаний агенту одним сообщением или заданием с привязкой `path:line`.
- [ ] Отметка файла «просмотрено» и фильтр непросмотренных; сброс отметки при изменении
      файла.
- [ ] Решить, где живут замечания: в истории чата, в `.projector/` проекта или только в
      состоянии вкладки. От этого зависит, переживут ли они перезагрузку и попадут ли в
      ветку или задание.

## Индекс и коммит

- [ ] Stage и unstage по хунку: сейчас `ide.git.stage` принимает путь и добавляет файл
      целиком. Нужен выбор блока в diff и частичный индекс.
- [ ] Diff рабочей копии с базовой веткой или произвольным ref, а не только index ↔
      worktree. Для проверки перед PR нужен весь набор изменений.
- [ ] Commit из интерфейса: staged-набор, сообщение, автор; команда `ide.git.commit` с
      явными аргументами.
- [ ] Черновик сообщения коммита по staged-diff от агента; пользователь правит и
      подтверждает.
- [ ] Публикация ветки: создать PR/MR из текущей ветки и открыть его после создания.
- [ ] Опасные операции (`push --force`, `reset --hard`, `clean -fd`, `branch -D`) — только с
      отдельным подтверждением и явным аргументом; по умолчанию недоступны.

## Задания агента

- [ ] Частичное принятие копии: принять выбранные файлы или хунки, остальное отклонить.
      Сейчас `ide.agent.job.worktree.merge` вливает всю копию, `discard` удаляет всю.
- [ ] Показывать diff задания в общем ревью-интерфейсе с теми же замечаниями и отметками, а
      не только во вкладке задания.
- [ ] После принятия предложить commit с сообщением из задания; сохранить связь «задание →
      коммит».
- [ ] Решить, что делать с копией, если принята только часть: оставить ветку, удалить или
      пометить частично принятой.

## Удалённые ревью

- [ ] GitHub и GitLab: публикация комментария и ответа в обсуждении, approve/request
      changes, создание issue.
- [ ] Inline-комментарии GitHub PR сейчас не читаются; у GitLab inline-diff есть. Нужен
      общий вид комментария к строке и ответа на него.
- [ ] Issue или MR → фоновое задание: номер, заголовок, тело, обсуждение и изменённые файлы
      попадают в постановку; итог и diff возвращаются комментарием или сводкой.
- [ ] Писать только в локальный проект с `origin`; `gh:/` и `gl:/` остаются read-only. Нужны
      отдельные scopes токенов и подтверждение публикации.
- [ ] Кеш и лимиты API при отправке: не дублировать комментарий при повторе, показывать
      ошибку 403/429 понятным текстом.

## Границы

- Не делать полноценный Git-клиент: цель — изменения, которые пользователь уже посмотрел.
  Сложные истории, rebase-конфликты и восстановление остаются Git и агенту.
- Не публиковать ничего без явного действия пользователя.
- Не смешивать ревью рабочей копии и ревью удалённого MR в одной модели без общего ключа:
  у них разные источники и права.

## Открытые вопросы

- Замечания — часть чата, проекта или отдельная сущность с версией?
- Кто пишет сообщение коммита: агент, шаблон проекта или пользователь?
- Нужны ли merge/rebase/stash в интерфейсе или их оставляем агенту и терминалу?
- Делать ли approve за пользователя или только показывать состояние и вести в браузер?

## Проверки перед закрытием

- [ ] `vp run check` целиком.
- [ ] Ручной прогон: stage/unstage по хунку, commit, push в тестовый remote, частичное
      принятие задания, комментарий и approve в тестовом репозитории.
- [ ] Мобильная ширина и клавиатура: список замечаний, diff, подтверждения.
- [ ] Ошибки: конфликт индекса, истёкший токен, 403/429, закрытая вкладка во время
      публикации.
