# Аналитика по журналам агентов

Рабочий материал: только открытые пункты. Цель — считать расход не только из `turns.usage`, а из нативных журналов агентов, чтобы в аналитику попали Codex, OpenCode, Kimi, запуски в терминале и фоновые задания. Текущее устройство — [аналитика](../analytics.md) и [архитектура](../architecture.md); контракт — `packages/core/modules/usage-analytics`.

## Решение

- Источник — локальные журналы агентов; ACP остаётся для контекста и лимитов, но не для токенов за ход.
- Записанная стоимость (`costUSD`, `cost`, `chargedCents`) приоритетнее расчётной; иначе цена по каталогу LiteLLM/OpenRouter.
- Каждый читатель живёт в модуле своего агента; встроенные и плагинные бэкенды отдают его через `backend.usageLog`. Общий контракт и агрегация — в `usage-analytics`.
- Дедупликация по `(agent, session, messageId/turnId)`, отдельные правила для вложенных агентов и форков.
- По умолчанию читаются только метаданные: модель, токены, время, id. Промпты и вывод инструментов не индексируются.

## Границы

- Не биллинг и не бюджеты: остановка расхода и лимиты — задача шлюза, не чтения логов.
- Нет кросс-машинной синхронизации; при необходимости — OTLP или отдельный синк.
- Новые агенты — только когда у них есть читаемый журнал; Cursor подключён последним через плагин.
- Не выдавать оценку за счёт и не показывать ноль там, где данных нет.

## Открытые пункты

### Быстрые победы

- [ ] Карточка «Агенты»: рядом с долей токенов показывать число ответов без `usage` и без цены; сейчас у агента без данных остаётся пустой график, а не причина (`packages/client/modules/analytics`).
- [ ] Счётчик ответов без цены рядом с происхождением суммы: `costSource` уже есть в контракте и источниках, UI показывает «записано агентом»/«по тарифу» и «—», но не говорит, сколько ответов осталось без цены.

### Контракт и хранение

- [ ] Дедупликация между агентами: OpenCode через `claude-agent` и Claude Code, форки, resume и субагенты не должны считаться дважды.

### Читатели журналов

- [ ] Claude Code для терминала: `~/.claude/projects/**/*.jsonl` или OTel; только если нужен расход вне чата Projector; помнить про retention 30 дней.
- [ ] Gemini/Qwen/Copilot: добавлять только при появлении в каталоге; OTel предпочтительнее собственного парсера.

### Цена

- [ ] Каталог цен: LiteLLM + OpenRouter/models.dev, offline snapshot, исторические тарифы, кэш и длинный контекст, алиасы моделей.
- [ ] Ручные override'ы цены; отсутствие цены уже показывается как «—», а не `0`.
- [ ] Учитывать фиксированные платежи (web search, vision), если источник их отдаёт.

### Поверхности

- [ ] Фоновые задания: читать `usage` из `journal.json` или сохранять его в записи задания; не дублировать с чатом.
- [ ] Проверить пересечение чата, задания и нативного журнала на одном ходе.

### Проверки

- [ ] Тесты на обезличенных реальных логах Codex/OpenCode/Kimi и версиях форматов: сейчас проверены синтетические образцы и текущие журналы машины.
- [ ] Тест дедупликации между OpenCode `claude-agent` и Claude Code, форком и resume.

## Критерий готовности

- За период в «Агентах», «Моделях» и «Проектах» видны токены Codex, OpenCode, Kimi и Cursor из реальных логов, а не нули.
- OpenCode через `claude-agent` и Claude Code не считаются дважды.
- У каждой суммы есть происхождение; выдуманных долларов нет.
- Расход терминала и фоновых заданий попадает в аналитику у тех агентов, где есть журналы.
- Нечитаемый или неподдерживаемый источник показывает явное состояние и количество, а не пустой график.
- После изменения поведения обновлены `docs/analytics.md` и `CHANGELOG.md`; этот файл удалён.
