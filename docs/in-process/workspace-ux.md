# Рабочее место: навигация и сохранность

Рабочий документ: только открытые пункты. Текущее устройство — [usage](../usage.md#workspace),
[ide-commands](../ide-commands.md), [virtualization](../virtualization.md),
[large-files](../large-files.md).

Цель: убрать ежедневное трение при чтении и переходе по коду. Projector не заменяет
редактор, но должен быстро отвечать на «где этот файл», «откуда эта строка» и «что я делал в
прошлый раз».

## Быстрое открытие

- [ ] Ctrl+P (команда `ide.workbench.file.quickOpen`) — fuzzy-поиск по путям проекта.
      `findProjectPaths` уже ранжирует пути, а `@` в чате использует тот же поиск; нужен
      общий вид рабочего пространства.
- [ ] Недавние файлы и недавние проекты в том же окне.
- [ ] Переход к строке прямо в поле (`src/app.ts:42`) и открытие на строке.
- [ ] Учитывать `files.exclude`; для снимков и удалённых профилей — только реально доступные
      пути.
- [ ] Клавиатурная навигация: стрелки, Enter, Esc, Ctrl+Enter — открыть в другом блоке.

## История файла

- [ ] Вкладка «История файла»: `git log --follow` по пути, список коммитов, автор, дата,
      статус.
- [ ] Blame: строка, коммит, автор; переход к снимку коммита и к diff родителя.
- [ ] Для GitHub и GitLab — запрос коммитов с `path`, если API это поддерживает; иначе
      вкладка честно недоступна.
- [ ] Не дублировать общую историю: это отдельный вид, а не ещё один фильтр `GitHistory`.

## Терминал

- [ ] Поиск по скроллбеку (xterm addon-search): Ctrl+F, следующее и предыдущее, подсветка,
      счётчик.
- [ ] Команда `ide.terminal.find` для агента: возвращает совпадения и позиции, не пишет в
      PTY.
- [ ] Не ломать существующие кнопки «В чат» и Ctrl+click по путям.

## Внешний редактор

- [ ] Команда «Открыть в редакторе»: текущий файл и строка; редактор из настройки, `$VISUAL`,
      `$EDITOR`, `code`, `cursor`.
- [ ] Работает только для локального проекта при открытии на машине с сервером; в снимках и
      удалённых профилях скрыта.
- [ ] Аргументы передаются без shell-склейки; путь с пробелами и юникодом не ломает запуск.

## Восстановление окна

- [ ] Хранить раскладку, открытые вкладки и активный блок после закрытия окна. Сейчас это
      `sessionStorage` вкладки браузера.
- [ ] Решить, где состояние: на сервере (общее для окна и телефона) или в браузере (проще, но
      теряется). Учесть две вкладки на один проект.
- [ ] Именованные раскладки и выбор при открытии проекта; пресеты
      `side/stacked/editor/terminal` уже есть.
- [ ] После рестарта сервера восстанавливать вкладки и файлы, но не обещать мёртвые
      терминалы; показывать, что сессия потеряна.
- [ ] Снимки и удалённые файлы, которых больше нет, — заглушка с причиной, а не пустая
      вкладка.

## Локальная история файлов

- [ ] Таймлайн сохранений файла вне Git: снимок при сохранении и перед перезаписью агентом;
      просмотр, diff и откат.
- [ ] Хранение и лимиты: `.projector/local-history` или `$XDG_DATA_HOME`; срок, размер,
      исключения секретов и больших файлов.
- [ ] Не заменять Git: это страховка от перезаписи и удаления, а не альтернатива коммитам.
- [ ] Не писать историю для исключённых файлов и не хранить содержимое `.env` и ключей.

## Границы

- LSP, диагностика, полноценный редактор и маркетплейс расширений — вне рамок. Projector
  остаётся средой чтения, навигации и запуска.
- Не добавлять второй редактор кода: Markdown и просмотр файлов не должны превращаться в
  IDE.

## Открытые вопросы

- Хранить состояние на сервере или в браузере? Что важнее — общий вид на телефоне или
  независимые окна?
- Сколько дней и мегабайт локальной истории держать по умолчанию?
- Нужна ли история для файлов, изменённых агентом, если есть Git и работа в изолированной
  копии?

## Проверки перед закрытием

- [ ] `vp run check` целиком.
- [ ] Ручной прогон: закрыть и открыть окно, две вкладки на проект, рестарт сервера, снимок,
      удалённый файл, большой файл.
- [ ] Мобильная ширина: быстрый поиск, история файла, восстановление.
