# Настройки и файлы плагина

Рабочий документ. Контракт плагинов — [plugins](../../plugins.md), текущие API — [plugins](../../plugins.md#api).

Плоское хранилище (`api.storage`, `plugins/data/<package-key>/state.json`) уже реализовано и
описано в [plugins.md](../../plugins.md#расположение-и-состояние); здесь остались декларативные
настройки, автоформа и изменяемые файлы/медиа пакета.

## Что осталось

1. **Схема в манифесте.** `projector.settings` или `contributes.settings`: массив полей
   `{ id, type, title, description?, default?, enum?, min?, max?, maxLength? }`. Валидатор —
   `packages/core/modules/plugins/settings.ts`, allowlist как у `browser.ts`; неизвестные поля и
   типы отклоняют пакет с диагностикой. Схема входит в хеш доверия: правка полей требует повторного
   доверия, как любое изменение пакета.
2. **Значения отдельно от схемы.** `plugins/data/<package-key>/settings.json` с `version: 1` и
   миграцией по версии; не `plugins.json`, иначе правки настроек смешиваются с `enabled` и
   `trustedHash`. Запись — тем же способом, что `state.json`: `withFileLock`, `writeFileAtomic`,
   `setAsideBroken`, квота 1 МБ.
3. **Автоформа в карточке.** Новая вкладка `PluginSettings.vue` рисует поля из схемы; ближайший
   ограниченный набор типов — `fieldsOf` из `server/modules/agents/acp/acp-elicitation.ts`
   (`string | number | integer | boolean | array`, `enum`/`oneOf`/`anyOf` до 50 опций). Произвольные
   контролы и Vue-компоненты не выдаются.
4. **Порядок значений.** Приоритет: явно сохранённое значение → `default` из схемы → встроенное
   поведение плагина. Тип значения проверяется при записи и при чтении; несовпадение не затирает
   файл, а даёт диагностику в карточке.
5. **API для кода плагина.** Либо `api.settings.get/set` поверх того же файла, либо значения
   доступны только через `api.storage` с ключом из схемы. Решение принять до реализации: два
   источника значений на один пакет быстро расходятся.

## Файлы и медиа

`api.storage` — JSON с квотой 1 МБ, поэтому бинарные данные в него не помещаются. Два готовых
пути не покрывают состояние пакета:

1. **Статика пакета** — файлы внутри установленной папки через `api.assetUrl(relative)` и
   `/api/plugins/assets/<key>/<hash>/...`. Read-only, версия и хеш в пути, живёт вместе с пакетом.
   Подходит для спрайтов, иконок, шрифтов и словарей, которые автор кладёт в артефакт.
2. **Медиатека проекта** — `/api/media/*` и `ide.media.generate`: результат провайдера скачивается
   в `media/files`, отдаётся `/api/media/files/<id>`, MIME проверяется по allowlist, лимиты
   32/64/512/2 МиБ. Это общий каталог без владельца: нельзя удалить «файлы плагина», посчитать
   квоту пакета или принять файл от пользователя.

Чего нет — **изменяемых файлов, принадлежащих пакету**: кэш озвучки, пользовательские картинки,
экспортированные отчёты, вложения. Ни один из шести разобранных плагинов на это не опирается:
`hover-glossary` и `usage-limits` обходятся JSON и статикой, `whale-girl` может брать TTS из
медиатеки.

Вариант, если понадобится, — `api.files` поверх `plugins/data/<package-key>/files`:

- `put(blob, { type, name }) → { id, url, size, mime }`, `get(id) → Blob`, `list()`, `delete(id)`,
  `url(id)`.
- Файлы `files/<id>` (id — uuid, имя только в индексе), индекс `files.json`
  `{ version: 1, files: [...] }`.
- Квоты: 25 МБ на файл, 100 МБ на пакет; проверка до записи и потоковая при загрузке.
- Маршруты `POST|GET|DELETE /api/plugins/<key>/files[/<id>]`, отдача с `nosniff`, `same-origin`,
  sandbox CSP и `Content-Disposition: inline`.
- MIME-allowlist как у медиатеки: png/jpeg/webp/gif/avif, audio/mpeg|wav|ogg|opus|mp4,
  video/mp4|webm, text/plain, application/json. HTML, SVG и исполняемые файлы не принимаются:
  SVG из чужого контента — это скрипт на origin приложения.
- Удаление вместе с managed-установкой, сохранение при disable и смене версии; осиротевшие файлы
  чинятся сверкой индекса и каталога.
- Оценка: сервер 2–3 дня (потоковая запись, квоты, индекс, маршрут, тесты), клиент 0.5–1 день.

## Открытые вопросы

1. Область значений: только per-install (per-device) или ещё `projectId`, как `.projector/roles.json`?
   Второе тянет trust-модель проекта.
2. Нужны ли секреты плагина, или это всегда vault интеграций и keyring провайдеров?
3. Лимит на поле и на файл: 1 МБ на весь файл или отдельная квота на настройки?
4. Удалять ли настройки при `remove` всегда или предлагать выбор в карточке?
5. Показывать ли схему без доверия к коду: декларативные настройки не исполняются, но схема входит
   в хеш — проверять ли её до подтверждения доверия.
6. Нужны ли плагинам изменяемые файлы вообще, или хватает статики пакета и медиатеки?
7. Квоты файлов: 25 МБ на файл и 100 МБ на пакет — или меньше, чтобы `plugins/data` не стал свалкой.
8. Давать ли плагинам читать артефакты медиатеки по `fileId` или только через `ide.media.generate`.
9. Разрешать ли SVG/иконки из пользовательских файлов отдельной безопасной отдачей (attachment,
   sandboxed origin) или не разрешать вовсе.
