# Концепт плагинов Projector

Рабочий концепт. Текущие вклады, манифест, доверие и API описаны в [plugins.md](../../plugins.md);
здесь — что осталось за пределами реализованного и каким может быть следующий runtime.

## Решение

Плагин — версионируемый локальный пакет с `package.json` и `apiVersion: 1`. Сейчас поддерживаются
два декларативных вклада:

- `themes` — JSON токенов из закрытого allowlist; полный ID `<package>/<theme>`; применяется без
  перезагрузки, токены вставляются bootstrap-скриптом до первого кадра.
- `agents` — декларативный ACP-агент: команда и argv, terminal, `usage.command`, уведомление
  `projector/usage`. Включается только после доверия по хешу содержимого пакета.

По умолчанию плагин — данные, а не код. Исключение — `projector.server`: собранный CommonJS-модуль,
который получает `createAgents(api)` и исполняется в процессе сервера с его правами. Это доверенный
код, а не песочница; поэтому он доступен только после отдельного доверия, а изменение файлов
снимает доверие. Контракт API — `packages/server/modules/plugin-api`, пример — `plugins/cursor`.

Не копируем у [Orca Note](https://www.orca-studio.com/orcanote-docs/documents/Quick_Start.html):
обязательный `dist/index.js`, произвольный CSS, глобальный объект состояния, идентичность по имени
папки и ручной `unregister` как единственный механизм очистки.

Главный компромисс: декларативный формат уже даёт темы и обычных ACP-агентов без sandbox и
произвольного UI; нестандартные агенты требуют доверенного серверного кода. Изолированный runtime
нужен, чтобы вернуть эту свободу безопасно, и он остаётся следующей ступенью.

## Что осталось

1. **Поставка.** npm/tarball install/update/remove, staging, `--ignore-scripts`, проверка
   совместимости, rollback и curated-каталог метаданных. Сейчас установка — только копирование
   локальной папки (`POST /api/plugins`, действие `install`); обновления установленной версии нет.
2. **Browser runtime.** Versioned `PluginContext`: команды, уведомления, settings schema и
   изолированное key-value хранилище; доверие по хешу. Это доверенный runtime, не sandbox:
   обновление хеша требует повторного доверия.
3. **UI и Node capabilities.** Вкладки/renderers и серверные разрешения проектировать отдельно
   после runtime; не расширять `context` неявно.
4. **Тема редактора.** Держать в паре со схемой интерфейса после стабилизации `--syntax-*` или
   общего открытого реестра; не смешивать с закрытым списком `editorThemes`.
5. **Изолированный runtime.** Отдельный процесс с версионированным RPC: не-ACP агенты, нативные
   журналы, произвольные usage-провайдеры. `projector.server` остаётся переходным уровнем.

## Формат и хранение

Минимальный theme-пакет — `package.json` плюс JSON токенов; правила, примеры и установка — в
[plugins.md](../../plugins.md). Управляемые установки лежат в `plugins/packages/<id>/<version>/`,
прямые папки — в `plugins/<folder>/package.json`. `plugins/data/<id>` зарезервирован под будущее
хранилище плагина и сейчас не используется.

`plugins.json` хранит enabled-состояние, выбранную версию, хеш и диагностику. `appearance.json`
остаётся источником выбранной схемы; при отключении внешней темы интерфейс временно использует
`dark`, сохранённый ID не затирается. Состояния: `disabled`, `enabled`, `error`, `missing`;
ошибка одного пакета не блокирует остальные.

Для runtime-плагинов следующего этапа: `activate(context)` возвращает disposer, а `context.signal`
и plugin-scope гарантируют очистку команд, подписок и вкладов.

## Архитектура

Текущие модули: `packages/core/modules/plugins` (манифест и allowlist вкладов),
`packages/server/modules/plugins` (discovery, установка, доверие, состояние),
`packages/client/modules/plugins` (каталог и настройки), `packages/server/modules/plugin-api`
(контракт для `projector.server`), `packages/server/routes/api/plugins.ts` (API каталога).

`appearance` уже разделён на `ThemeId` и `ColorMode`, а `appearanceOptions` объединяет встроенные
и включённые внешние темы; `/api/appearance/bootstrap.js` вставляет токены до первого кадра.
Новым этапам не нужно менять этот контракт.

## UX

Раздел находится в настройках рядом с интерфейсом и редактором. Это библиотека локальных пакетов,
а не магазин: без аккаунтов, рейтингов и автоматических обновлений.

1. **Каталог** — сейчас показывает только локальные пакеты; поиск, фильтры и превью палитр —
   целевой curated UI после появления источника метаданных.
2. **Карточка пакета** — превью темы, совместимость, статус, доверие и диагностика; для агента —
   команда, доступность и лимиты.
3. **Установленные** — включение/выключение, установка из папки, удаление, ошибки и объяснение
   ограничений.

Статические мокапы: [каталог](01-catalog.png), [Gruvbox Material](02-gruvbox.png),
[установленные](03-installed.png). Автономный HTML — [index.html](index.html), экраны
переключаются через `#catalog`, `#gruvbox`, `#installed`.

## Проверка

- манифест и токены: неизвестные поля, размеры, конфликты ID, режим и совместимость;
- discovery: битый пакет, symlink/path traversal, duplicate ID, изоляция ошибки;
- API: same-origin/access control, enable/disable/uninstall активной темы, атомарность;
- browser/Hub: внешние токены в bootstrap, `color-scheme` и `theme-color`, переключение без
  reload, fallback;
- реальные экраны: чат, файлы, Git/diff, редактор/Markdown, терминал, настройки, мобильная
  ширина;
- установка production-пакета в отдельный data dir без npm scripts;
- runtime: `activate`/disposer, `signal`, очистка команд и подписок, повторное доверие после
  изменения файлов.

Вне рамок: произвольный CSS, Node API без изоляции, зависимости между плагинами, аккаунты,
отзывы, покупки, визуальный редактор тем и автообновления.

Первый этап — theme-only MVP — закрыт; актуальное поведение и контракты ведутся в
[plugins.md](../../plugins.md), а не здесь.
