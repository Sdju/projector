# Перед следующей сессией

Актуально на 2026-10-01. Это контекст разработки и причины решений; команды пользователя и требования установки описаны в [README](../README.md).

## Что строим

Projector — узкая альтернатива Raycast: прежде всего поиск и запуск системных приложений по горячей клавише. Управление локальными проектами и агент Qwen уже существуют, но основной экран `/` теперь палитра поиска. Проекты находятся на `/projects`, настройки на `/settings`.

Пользователь отказался от Electron из-за его веса. Согласованы три режима: системное окно GTK4 по умолчанию, отдельное Chromium app-окно и обычная страница в браузере. В обычное время приложение должно оставаться в трее. Пользователь явно выбрал `Ctrl+Alt+Space`; сочетание показывает или скрывает палитру. Полная потеря фокуса должна скрывать палитру, как у других лаунчеров.

## Карта реализации

| Место | Ответственность |
| --- | --- |
| `bin/projector`, `cli/app/launch.mjs` | CLI, поиск Node/vp, блокировка запуска, повторное использование сервера |
| `vite.config.ts`, `server/app/plugin.ts` | Vite и локальный API в dev и preview |
| `server/modules/launcher/launcher.ts` | Общий поиск, настройки режима/хоткея, история и запуск |
| `native/app/entry.ts`, `native/modules/desktop/catalog.ts`, `native/modules/desktop/Palette.vue`, `native/modules/desktop/palette.ts`, `native/modules/desktop/resident.ts` | Node CLI, каталог GIO, запуск `.desktop`, иконки, резидентное GTK4-окно |
| `packages/vio` | Независимый Vue custom renderer для GTK4, компоненты, SFC loader, CSS и тесты |
| `native/modules/desktop/tray.ts`, `native/modules/desktop/shortcut.ts`, `native/modules/system-bus/bus.ts` | StatusNotifierItem/DBusMenu и KDE kglobalaccel через dbus-next |
| `core/modules/launcher/launcher.ts`, `core/modules/launcher/launcher-model.ts` | Общие типы, HTTP-клиент и модель поведения для Vue и GTK |
| `server/modules/window/window.ts` | Вызов нативного окна, Chromium, скрытие/активация в X11 |
| `src/pages/index.vue` | Веб-палитра |
| `src/app/App.vue`, `src/common/lib/launcher-surface.ts` | Потеря фокуса, возврат к поиску и сохранение идентичности app-окна |
| `server/modules/processes/processes.ts` | Владение процессами проектов, логи и состояние запусков |

Сервер слушает `localhost:4177`. CLI проверяет `/api/health`, использует `launch.lock` и при повторном вызове отправляет запрос работающему серверу. Обычный запуск сейчас поднимает **`vp dev`**, а не собранное самостоятельное приложение. `vp run build` проверяет типы и собирает фронтенд; это ещё не упаковка desktop-продукта.

GTK работает отдельным Node.js 24 / TypeScript-процессом через `node-gtk`. Резидентный процесс владеет D-Bus именем `dev.projector.Launcher` и экспортирует `dev.projector.Launcher.Control.Command` на `/dev/projector/Launcher`; повторный CLI-вызов обращается к нему. GLib MainLoop сохраняет процесс при скрытом окне: он обслуживает трей и хоткей. Команда `tray` не показывает окно и также обновляет регистрацию хоткея. Ответ `READY` служит подтверждением для сервера. Python больше не используется.

Общий модуль `core/modules/launcher/launcher-model.ts` отвечает за поиск, дебаунс, отмену устаревших ответов, выбор и запуск. Vue и GTK подписываются на одну модель и используют HTTP-клиент из `core/modules/launcher/launcher.ts`. Native-компоненты не импортируют Vue. GIO helper остаётся отдельным процессом, чтобы нативные биндинги и GTK main loop не вмешивались в Vite.

Прямой экспорт D-Bus через `Gio.DBusInterfaceVTable` в node-gtk 4.1.1 аварийно завершает процесс при присваивании callback. Поэтому весь D-Bus обслуживает dbus-next. usocket — необязательный нативный модуль, его сборка отключена. GTK-типы генерируются из typelibs перед build; генератор ошибочно объявляет `Gtk.Window.isActive` boolean вместо метода, что учтено публичным структурным WindowWidget в vio.

Нативная палитра теперь Vue SFC (`native/modules/desktop/Palette.vue`). `vio` использует `@vue/runtime-core.createRenderer`, без runtime-dom. Reconciler в `vio/core` отделён от GTK driver: keyed moves сохраняют нативные объекты, comments/fragment anchors остаются виртуальными, handlers заменяются без повторных подключений и отключаются на unmount. `vio/register` устанавливает GI и SFC loaders; путь к нему разрешается абсолютно в server/modules/window/desktop.ts. Соберите пакет `vp run vio:build` перед native-запуском после checkout/install. Основная build-команда делает это автоматически.

SFC styles применяются через CSS provider с cleanup в Vue scope; scoped attributes заменяются GTK classes. Обёртка setup обязана иметь два аргумента: Vue проверяет setup.length для создания expose/slots context. GTK declarations генерируются отдельно в node_modules каждого пакета; публичные декларации vio не требуют местных .gir файлов. Native HMR пока отсутствует: перезапускайте только нативный процесс (`node --import vio/register native/app/entry.ts native http://localhost:4177 quit`), затем обычный `./bin/projector --native`; не вызывайте `projector quit` ради перезапуска UI.

## Нюансы, которые уже приводили к ошибкам

- **Не скрывать по blur поля ввода.** В GTK используется активность всего окна (`notify::is-active`), флаг фактической активации `was_active` и задержка 100 мс. Показ отменяет отложенное скрытие. Перемещение между полем и результатами не должно закрывать окно.
- **Веб-скрытие ограничено палитрой.** Проверяются app-surface, маршрут `launcher` и `document.hasFocus()` через 100 мс после оконного blur. Настройки и проекты в этом окне не скрываются при потере фокуса; обычные браузерные вкладки тоже. `surface=window` сохраняется в `sessionStorage`, поскольку query исчезает при переходах между маршрутами. Событие SSE `launcher-show` возвращает app-окно к поиску при явном вызове.
- **Chromium создаёт вспомогательные X11-окна с тем же классом.** Одного `xdotool search --class` недостаточно: он может вернуть невидимое helper-окно, и скрытие внешне не сработает. `paletteWindow()` фильтрует кандидатов по наличию `WM_STATE` через `xprop`, включая скрытое настоящее окно. Палитра имеет класс `ProjectorLauncher`; не путать с `Projector` для других окон.
- **HMR API не завершает уже запущенные проекты.** При хранении процессов в переменных модуля перезагрузка Vite теряла записи о живых дочерних процессах. Теперь `sessions`, `listeners` и `hooksBound` находятся в `globalThis.projectorProcesses`. Сохранять этот инвариант: иначе UI покажет остановленный проект и разрешит дублирующий запуск. Полный перезапуск Node всё равно завершает принадлежащие ему проекты.
- **Выход отличается от скрытия.** `projector quit` и пункт выхода в трее завершают сервер и проекты, запущенные через него. Во время GUI-проверки однажды случайно был нажат выход в трее; проект пришлось восстановить. Не проверять меню вслепую по старым координатам и не перезапускать сервер без проверки активных проектов.
- **GIO должно запускать `.desktop`, а не самодельный парсер `Exec`.** Важны поля `%c`/`%k`, пробелы, `Terminal`, D-Bus activation и скрытые записи. ID приложения проверяется по установленному каталогу. Каталог кешируется на 15 секунд; история сохраняется только после успешного запуска, записи сериализованы.

## Хоткей, окружение и данные

Автоматическая регистрация хоткея реализована для KDE через session D-Bus. В `native/modules/desktop/shortcut.ts` используются Qt-коды клавиш и флаги `SetPresent | NoAutoloading` (6): пользовательская настройка должна иметь приоритет над старым назначением KDE. Проверка доступности считает собственное существующее назначение допустимым, но не забирает чужое. При завершении вызывается `setInactive`. Настройки показывают реальное состояние регистрации.

Поддержаны `Ctrl+Alt+Space`, `Super+Space`, `Alt+Space` и отключение. В других окружениях пользователь назначает `projector toggle` средствами рабочего стола. Автозапуск **не устанавливается** автоматически; для него предназначена команда `projector --tray`.

Проверенное окружение — Linux/KDE Plasma/X11. Трей требует StatusNotifierItem/DBusMenu. Native требует Node.js 24, GTK4 и GObject Introspection с GioUnix; GIO также нужен для каталога приложений в веб-режимах. Chromium-палитра использует `xdotool` и `xprop`; её повторный показ/скрытие на Wayland пока не реализован. Native-фокус на Wayland требует отдельной проверки.

Данные лежат в `$XDG_DATA_HOME/projector`, по умолчанию `~/.local/share/projector`:

- `launcher.json`: выбранный режим, хоткей и история запусков;
- `projects.json`: сохранённые проекты;
- `providers.json`: настройки провайдеров и ключи; не копировать в Git или диагностические отчёты;
- `instance.json`, `launch.lock`, `server.log`: состояние запуска и серверный лог;
- `chrome-profile-launcher`: отдельный профиль палитры; `chrome-profile` используется для других app-окон.

Не менять текущий профиль браузера пользователя ради тестов. Установка пункта меню и `~/.local/bin/projector` ссылается на этот checkout: при переносе каталога её нужно повторить.

## Проверки и безопасное продолжение

```bash
vp run build
node --test tests/launcher.test.mjs
node tests/launcher-model.test.mjs
vp run vio:test
vp run vio:gtk-test
```

API-тест создаёт временные XDG-данные в `/tmp` и безопасное тестовое приложение. Он проверяет поиск, скрытые записи, `Exec` с пробелами и подстановками, режимы, историю при параллельных запросах, отказ для чужого Origin, default-команду проекта и сохранение состояния после повторного импорта модуля процессов. Пользовательские настройки не меняются, глобальный хоткей тест не переназначает. `--prepare` создаёт только тестовую среду для ручной проверки. Автоматические тесты не подтверждают настоящий фокус, трей или нажатие глобального хоткея.

В предыдущей сессии сборка и API-тест прошли; в реальном X11 проверены вызов `Ctrl+Alt+Space`, повторный показ, скрытие native и Chromium при переключении в другое приложение, переходы фокуса внутри GTK и меню трея. При изменении этих механизмов повторить соответствующую GUI-проверку, учитывая фактические ID окон.

Перед работой проверить `/api/health` и `/api/status`: сервер и проекты могли остаться работающими. В конце предыдущей сессии через Projector был восстановлен `@han-agent/web` (`dev`, URL `http://localhost:5174`); это исторический ориентир, а не гарантия текущего состояния. PID и ID окон получать заново.

Git-корень находится **на уровень выше**, в `image-gen`; Projector — подкаталог. Коммиты `fa1f470` (приложение) и `9e57d97` (тесты) впервые добавили его в репозиторий. В соседнем `text2text_project` остались пользовательские изменения. При staging и коммитах ограничивать пути каталогом Projector.
