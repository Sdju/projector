# Запуск ACP-агентов

Встроенные ACP-агенты и декларативные агенты плагинов описывают команду запуска в коде или
манифесте: OpenCode — `opencode acp`, Codex — `npx …`, Kimi — `kimi acp`, Cursor — `agent acp`.
На каждой машине команду можно переопределить, не меняя проект, плагин и исходники Projector.

## Файл

`$XDG_DATA_HOME/projector/agent/launch.json`, по умолчанию
`~/.local/share/projector/agent/launch.json`. Файл принадлежит только владельцу и пишется
атомарно.

```json
{
  "version": 1,
  "agents": {
    "opencode": {
      "command": "C:\\Tools\\opencode\\opencode.exe",
      "args": ["acp"],
      "env": {
        "OPENCODE_CONFIG": "C:\\Users\\me\\.config\\opencode"
      }
    },
    "codex": {
      "command": "npx",
      "args": ["-y", "@agentclientprotocol/codex-acp@2.1.1"]
    }
  }
}
```

| Поле      | Смысл                                                                                    |
| --------- | ---------------------------------------------------------------------------------------- |
| `command` | Имя в `PATH` или абсолютный путь.                                                        |
| `args`    | Аргументы после команды, один элемент — один аргумент. Пустой массив означает «без них». |
| `env`     | Дополнительные или переопределяющие переменные окружения.                                |

Пустой объект, отсутствующее поле или отсутствие записи означают «как в дескрипторе». Запись
применяется только к зарегистрированному ACP-агенту с тем же id; новые бэкенды так не создаются.
Файл доступен только владельцу, но значения `env` лежат в нём открытым текстом: токены лучше
оставлять в настройках самого CLI.

## Приоритет

1. Если задан `command`, запускается он и его `args`. Если `args` не задан, берутся базовые
   аргументы агента (`acp` у ACP-режимов; у предпочитаемого бинарника — его собственные).
   Явный пустой `args: []` означает запуск без аргументов.
2. Без `command` сохраняется обычный выбор: установленный `binary`, затем `command`
   дескриптора. Если в переопределении есть только `args` или `env`, они накладываются на него.
3. `env` добавляется поверх окружения, которое Projector готовит для агента; секреты самого
   Projector в это окружение не попадают.
4. `npx` (включая `npx.cmd`, `npx.exe`, полный путь) запускается из каталога данных, как и
   раньше; остальные команды — из каталога проекта.

Изменение применяется к новым запускам: уже работающий процесс агента и его терминал не
перезапускаются.

Терминальный режим того же агента запускает переопределённый `command`; аргументы ACP в TUI не
добавляются, а `env` действует на ACP-процесс, поэтому для TUI надёжнее указать полный путь.
Проверка «программа установлена» и подпись в чате используют итоговую команду и добавленное
окружение, а не значение из кода.

Переопределение не меняет диалект, формы, `clientCapabilities`, доверие к плагину и не действует
на не-ACP бэкенды (встроенный Projector, Claude Code на Agent SDK). Команды лимитов, которые
запускают отдельный CLI, настройкой не затрагиваются.

## API

- `GET /api/agent/launch` — `{ file, agents }`; у каждого агента: `default`, `override`,
  `effective` с `command`, `args`, `source` (`override` / `binary` / `default`), `found` и `path`.
- `PUT /api/agent/launch/:id` — тело `{ command?, args?, env? }`.
- `DELETE /api/agent/launch/:id` — удалить переопределение.
- Чтение и запись доступны только со страницы Projector.

Ответ `GET /api/agent/backends` помечает ACP-бэкенды полем `launch: true`; остальные бэкенды его
не имеют.

## Настройки

На странице внешнего ACP-агента есть секция «запуск»: исполняемый файл, аргументы (по одному в
строке), переменные окружения (`KEY=value`), итоговая команда, найденный путь и файл настроек.
Когда вводится своя команда, поле аргументов заполняется базовыми аргументами агента; очистить
его можно вручную, чтобы запустить без аргументов. Кнопка «Вернуть по умолчанию» удаляет запись.

Команды IDE:

| Команда                  | Что делает                                                                     |
| ------------------------ | ------------------------------------------------------------------------------ |
| `ide.agent.launch.list`  | Все настройки запуска с дефолтами и итоговой командой.                         |
| `ide.agent.launch.set`   | `{ backend, command?, args?, env? }`; в форме настроек без аргументов — форма. |
| `ide.agent.launch.reset` | `{ backend }`; удаляет переопределение.                                        |
| `ide.agent.launch.check` | `{ backend }`; перечитывает файл и возвращает найденный путь.                  |

Команды доступны и из чата проекта, поэтому агент может поправить запуск на другой машине, не
открывая страницу настроек. Аргументы передаются массивом, а не строкой для shell: кавычки
`cmd.exe` и POSIX не смешиваются, и настройка не может превратиться в произвольный скрипт.
