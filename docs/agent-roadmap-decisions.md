# Дорожная карта агентов: спорные решения

Здесь записано то, что при реализации дорожной карты агентов (откат, версии разговора, очередь,
план, правки за ход, уведомления, сессии) пришлось решать без вашего слова. Для каждого пункта:
что выбрано сейчас, почему, какие есть другие варианты и пустое поле **Ответ** — допишите туда
решение, и я приведу код в соответствие. Пока ответа нет, действует выбор «Сейчас».

Что сделано, описано в [SDK команд IDE](ide-commands.md#projector-chat-agent); здесь — только вопросы.

## 1. Версии разговора и отдельные чаты

- **Сейчас.** Правка сообщения и «Повторить» не стирают прежний ход: он остаётся другой версией
  этого сообщения («‹ 2 / 3 ›» над сообщением), а следующее сообщение продолжает показанную версию.
  Версии хранятся в истории чата на сервере (до 20 других версий на сообщение).
- **Почему.** Не требует нового вида вкладки и работает для всех агентов, потому что версия — это
  просто другой хвост ходов.
- **Иначе.** «Новый чат отсюда» — открывать копию разговора до выбранного сообщения в новой
  вкладке. Это ближе к слову «форк», но создаёт много вкладок и сессий.
- **Вопрос.** Нужен ли ещё и «новый чат отсюда» поверх версий?
- **Ответ: нет**

* **Принято и сделано:** отдельные чаты «отсюда» не нужны, остаются только версии разговора.

## 2. Что откатывает «Откатить»

- **Сейчас.** Три варианта: только разговор (по умолчанию, сообщение возвращается в поле ввода),
  разговор и файлы, только файлы. Перед откатом файлов показывается список (сколько файлов, плюс и
  минус строк). Откатывается всё, что Claude Code менял своими инструментами записи и правки с
  начала этого сообщения.
- **Что не откатывается.** Файлы, изменённые командами оболочки (`bash`, `sed -i`, сборка) —
  Claude Code их не отслеживает. Предупреждение об этом в панели пока не показано.
- **Вопрос.** Показывать ли в панели прямое предупреждение «команды оболочки не откатываются»? И
  оставлять ли «только разговор» вариантом по умолчанию (он безопаснее)?
- **Ответ:** только разговор

* **Принято и сделано:** по умолчанию «Только разговор». В вариантах с файлами в панели добавлено предупреждение, что файлы, изменённые командами оболочки, не откатываются.

## 3. Откат файлов у Codex, OpenCode, Cursor и штатного агента Projector

- **Решение.** Не реализовывать вообще. Универсальные снимки через git, которые я было сделал, удалены
  из кода; файлы возвращает только Claude Code (по своим резервным копиям), остальным агентам доступен
  откат разговора.
- **Ответ: пока не реализовывай вообще**

## 4. Повторить ответ

- **Сейчас.** «Повторить» задаёт тот же вопрос заново и не трогает файлы: агент видит проект уже
  с правками прошлой попытки.
- **Иначе.** Для Claude Code перед повтором откатывать файлы к началу хода (чистый повтор).
- **Вопрос.** Откатывать ли файлы при «Повторить» (спросить в панели или всегда)?
- **Ответ: откатываем только разговор**

* **Принято и сделано:** «Повторить» откатывает только разговор, файлы не трогает (как было).

## 5. Очередь сообщений и вмешательство в ход

- **Сейчас.** Сообщение, написанное пока агент отвечает, встаёт в очередь над полем ввода и
  уходит, когда ответ закончен. У каждого пункта три действия: «Добавить в ответ» (только Claude
  Code: сообщение уходит в идущий ответ сразу, агент учитывает его, не останавливаясь, а в ответе
  остаётся цитата «Вы добавили: …»), «Отправить сразу» (останавливает ответ и отправляет это
  сообщение) и «Убрать». После остановки кнопкой или ошибки очередь сама не уходит.
- **Как устроено.** Вход Claude Code остаётся открытым, пока агент работает, и закрывается через 1,5
  секунды после результата, если новых сообщений нет. Если ответ закончился раньше, чем дошло
  добавление, сообщение остаётся в очереди и интерфейс об этом сообщает.
- **Что не покрыто.** У ACP-агентов (Codex, OpenCode, Cursor) вставки нет: их процесс живёт один ход.
- **Вопрос.** Показывать ли добавленное сообщение отдельным пузырём пользователя, а не цитатой внутри
  ответа? Нужна ли вставка в ход для ACP-агентов, если они научатся принимать сообщения во время хода?
- **Ответ: да**

* **Принято и сделано:** добавленное во время ответа сообщение теперь показывается отдельным пузырём пользователя внутри ответа (а не цитатой), сохраняется в истории и попадает в экспорт.

## 6. «Всегда разрешать» у Claude Code

- **Сейчас.** Кнопка появилась и у Claude Code. Она сохраняет правило, которое Claude Code сам
  предложил для этого вызова (`suggestions`): так же, как в его терминале.
- **Что неясно.** Куда SDK записывает правило (настройки проекта или пользователя), решает сам
  Claude Code; Projector это не выбирает и в интерфейсе не показывает.
- **Вопрос.** Показывать ли, куда сохранится правило, и давать ли выбор (только на сессию, в
  проект, для пользователя)?
- **Ответ:** общие настройки для claude code

* **Принято и сделано:** правило сохраняется в общие настройки Claude Code пользователя (`userSettings`), поэтому действует во всех проектах и в терминале.

## 7. Уведомления

- **Сейчас.** Когда агент закончил или ждёт разрешения, а страница скрыта, браузер показывает
  системное уведомление. Разрешение запрашивается при первом отправленном сообщении.
- **Иначе.** Настройка в «Настройках» (вкл/выкл, звук), уведомление через трей нативного режима.
- **Вопрос.** Нужна ли настройка и что делать с нативным окном (трей), где страница видима, но не в
  фокусе?
- **Ответ: пока нет**

* **Принято и сделано:** настройки уведомлений не добавлялись, всё как было.

## 8. Изоляция параллельных агентов (git worktree)

- **Сейчас.** Сделано. В пустом чате внешнего агента кнопка с веткой в правом верхнем углу включает
  изоляцию: первое сообщение создаёт `git worktree` в каталоге данных Projector
  (`worktrees/<проект>-<id>`) на ветке `projector/<id>`, и агент работает только там. Над полем ввода
  появляется панель «Чат работает в изолированной копии» с числом изменённых файлов и двумя кнопками:
  «Влить в проект» (изменения коммитятся в копии, ветка копии вливается обычным `git merge` в
  текущую ветку проекта, копия и ветка удаляются) и «Отбросить» (копия удаляется вместе со всем, что
  в ней сделано). Конфликтное слияние отменяется, проект остаётся как был, причина показывается в
  панели. Команды: `ide.agent.chat.isolate`, `ide.agent.worktree.status/merge/discard`.
- **Ограничения.** Нужен git-проект с хотя бы одним коммитом. Файлы неотслеживаемые и неотправленные в
  HEAD в копию не попадают. Дерево файлов и открытые вкладки показывают проект, а не копию: чтобы
  смотреть изменения до слияния, их надо открывать из списка «Изменено файлов» (он показывает пути) или
  вливать. После слияния или удаления чат продолжается в самом проекте с новой сессией агента.
- **Вопросы.** Показывать ли файлы копии в дереве и редакторе (отдельный раздел)? Нужен ли выбор
  стратегии слияния (merge, squash, патч)? Что делать с копиями, чьи чаты закрыли без слияния
  (сейчас они остаются в каталоге данных до ручного удаления)? Включать ли изоляцию по умолчанию,
  когда в проекте уже идёт другой ответ?

## 9. MCP, хуки, субагенты

- **Сейчас.** Claude Code сам читает настройки пользователя и проекта (`~/.claude`, `.claude/`,
  `.mcp.json`), поэтому MCP-серверы, хуки и субагенты в нём работают без участия Projector. В
  острове параметров появился раздел «MCP-серверы» (имя, состояние, число инструментов; читается при
  открытии острова). ACP-агентам Projector теперь передаёт stdio-серверы из `.mcp.json` проекта (с
  подстановкой `${ПЕРЕМЕННАЯ}`), и остров показывает, какие переданы. Вызовы субагентов показываются
  внутри их вызова `Task`. Команда: `ide.agent.mcp.list`.
- **Что не покрыто.** HTTP и SSE-серверы из `.mcp.json` ACP-агентам не передаются (помечены «не
  передан»). Серверы из пользовательских настроек (не из проекта) ACP-агентам тоже не передаются.
  Интерфейса добавления серверов нет, только файлы.
- **Вопросы.** Передавать ли ACP-агентам HTTP и SSE-серверы, когда агент объявляет их поддержку?
  Нужен ли интерфейс добавления и включения серверов?
- **Ответ: да**

* **Принято и сделано:** HTTP и SSE-серверы из `.mcp.json` передаются ACP-агентам, если те объявили `mcpCapabilities.http` или `.sse`; заголовки и адреса поддерживают `${ПЕРЕМЕННАЯ}`. Статус в острове подписан.

## 10. Лимиты хода

- **Сейчас.** В острове параметров Claude Code два новых параметра: «Бюджет хода» (1, 5, 20 $) и
  «Шагов в ходе» (10, 30, 100). Значения заданы жёстко, по умолчанию лимитов нет.
- **Вопрос.** Подходят ли значения? Нужен ли общий лимит на сессию?
- **Ответ: оставь как есть**

* **Принято и сделано:** значения оставлены как есть.

## 11. Форки засоряют список сессий

- **Сейчас.** Каждая ветка Claude Code — отдельная сессия на диске (так SDK хранит ответвления),
  поэтому правка сообщения добавляет в «Прошлые сессии» ещё одну запись.
- **Иначе.** Скрывать из списка сессии-ответвления, чьи ходы уже есть в других чатах Projector.
- **Вопрос.** Скрывать ли такие сессии?
- **Ответ: пока нет**

* **Принято и сделано:** сессии-ответвления не скрываются.

## 12. Что теряется при перезагрузке страницы

- **Сейчас.** Версии сохраняются. Не сохраняется только одно состояние: сообщение, возвращённое в
  поле ввода откатом, вместе с отрезанным хвостом ждёт отправки; до отправки при перезагрузке
  страницы хвост пропадёт, потому что он ещё не привязан ни к какому сообщению.
- **Иначе.** Хранить такой хвост в истории сразу.
- **Вопрос.** Нужно ли сохранять его при перезагрузке?
- **Ответ: да нужно**

* **Принято и сделано:** правка сообщения больше не отрезает хвост сразу. Сообщение уходит в поле ввода, а то, что оно заменит, показывается бледным; хвост становится версией только когда новое сообщение отправлено. Поэтому перезагрузка или «Отмена» ничего не теряют (кнопка «Отмена» над полем ввода). Откат разговора через панель работает так же.

## 13. Контекст

- **Сейчас.** При заполнении от 80% над полем ввода у Claude Code появляется подсказка «Сжать»
  (отправляет `/compact`). Автоматического сжатия сверх того, что делает сам Claude Code, нет.
  Кольцо у Claude Code обновляется после хода, у ACP-агентов слэш-команды известны только после
  первого сообщения.
- **Вопрос.** Нужны ли подсказка при 90% с другим текстом, автосжатие или обновление кольца
  по ходу ответа?
- **Ответ: да**

* **Принято и сделано:** над полем ввода подсказка при 80% (спокойная) и при 90% (красная: «после этого ответа он сожмётся сам»); при 90% и выше после окончания ответа Claude Code автоматически получает `/compact` (кроме случая, когда последнее сообщение уже было `/compact`, и когда был сбой); кольцо обновляется по ходу ответа после результатов инструментов, не чаще раза в 4 секунды. Автосжатие срабатывает и после ручной остановки ответа; если это мешает, скажите.

## 14. План и задачи

- **Сейчас.** Панель плана строится по последнему `TodoWrite` в последнем ответе (Claude Code) и
  исчезает, когда следующий ответ его не обновил. План ACP-агентов не показывается.
- **Вопрос.** Держать ли план закреплённым, пока в нём есть невыполненные пункты, даже после
  следующих сообщений? Показывать ли план ACP-агентов?
- **Ответ: придумай визуальное решение соотвествующее легкому и ненавязчивому дизайну проекта**

* **Принято и сделано:** план стал одной тонкой строкой без рамки: «План 3 / 7», текущий пункт и полоска прогресса; разворачивается по клику, сам раскрыт, пока агент работает. Он остаётся закреплённым, пока в нём есть невыполненные пункты, даже после следующих сообщений; завершённый план показывается только для ответа, который его завершил.

## 15. Экспорт чата

- **Сейчас.** Кнопка сохраняет разговор как Markdown: реплики и подписи вызовов инструментов,
  без их входа и вывода. Команда `ide.agent.chat.export` отдаёт тот же текст.
- **Вопрос.** Нужен ли полный экспорт (вход и результаты вызовов) и другие форматы (JSON, HTML)?
- **Ответ: нет**

* **Принято и сделано:** экспорт остаётся только кратким Markdown.

## 16. Где живут команды `ide.agent.*`

- **Сейчас.** Все команды чатов зарегистрированы один раз в области редактора проекта
  (`registerAgentCommands`, вызывается из `ProjectWorkspace`) и работают с последним активным чатом
  проекта (или с чатом по ключу `chat`). Прежние команды параметров и сессий, которые регистрировал
  сам чат, перенесены туда же, так что команд во временных компонентах больше нет.
- **Вопрос.** Устраивает ли выбор «последний активный чат», или команды должны требовать `chat`
  явно, когда открыто несколько чатов?
- **Ответ: по-умолчанию активный, с возможостью указания конкретного**

* **Принято и сделано:** без `chat` команды берут активный чат (видимый, затем последний, с которым работали), а `chat` указывает конкретный. Как было.
