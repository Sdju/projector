# Виртуализация списков

`src/common/ui/UiVirtualList.vue` — универсальный Vue-компонент без собственной разметки,
на основе `@tanstack/vue-virtual`. Первое применение — таблица горячих клавиш:
`src/modules/ide/ui/KeybindingsTable.vue`. В DOM находятся видимые строки, запас
по краям и, при необходимости, строка с активным фокусом.

Выбран `@tanstack/vue-virtual`: разметка и состояние строк принадлежат Projector. Реализован только вертикальный список с собственным scroll-контейнером; сетки, горизонтальная виртуализация и закреплённые группы — задачи потребителей. Виртуализация ограничивает DOM, но не объём данных и не стоимость фильтрации.

## Контракт

- `items`: полный отфильтрованный массив; `itemKey(item)` возвращает уникальный
  стабильный ключ `string | number`. Индекс не подходит для сортируемых списков.
- `scrollElement`: DOM-элемент с ограниченной высотой и `overflow: auto`.
- `estimateSize`: начальная оценка высоты в пикселях или функция `(item, index)`;
  реальные размеры отслеживаются через `measureElement` и ResizeObserver.
- `overscan`: запас строк с каждой стороны (по умолчанию 6).
- `scrollMargin`: высота содержимого перед списком, например заголовка таблицы.
  Потребитель отслеживает её через `useElementSize`.
- `resetKey`: изменение фильтра сбрасывает вертикальную прокрутку. Обновление
  данных само по себе не сбрасывает позицию; при сокращении списка она ограничивается.
- Scoped slot получает `rows`, `paddingAfter`, `measureElement`. Каждая строка
  содержит исходный `item`, логический `index`, стабильный `key` и `gapBefore`.
  Перед строкой нужно отрисовать пустой промежуток высотой `gapBefore`, после
  списка — `paddingAfter`. Это учитывает и удерживаемую строку вне видимого диапазона.
- Измеряемая строка получает `:ref="measureElement"`, `:data-index="index"`
  и `:data-virtual-index="index"`. Последний атрибут позволяет удерживать строку,
  пока внутри неё находится фокус. После ухода фокуса она снова может размонтироваться.
- Через ref компонента доступны `scrollToIndex(index)` и `measure()`.
  Пользовательские действия потребителя по-прежнему должны проходить через IDE-команды.

## Разметка и доступность

Обычный список может использовать `div`, а таблица сохраняет `table/thead/tbody/tr/td`.
Для таблицы промежутки — `tr aria-hidden="true"` с одной `td colspan`, нулевыми
padding/border и указанной высотой. Колонки должны иметь устойчивую ширину
(`table-layout: fixed` и `colgroup`), иначе ширины будут меняться при прокрутке.
На таблице указывается полное `aria-rowcount` с заголовком, на строках —
`aria-rowindex`, учитывающий заголовок.

Удержание фокуса не реализует клавиатурную навигацию или выделение за потребителя.
Состояние редактирования должно храниться вне размонтируемой строки. Поиск браузера
по странице видит только DOM; для полного списка используется поиск приложения.
Не добавляйте вертикальные margin к измеряемой строке: отступ должен входить в её высоту.

## Проверка

`vp run test:virtual-list` — headless Chromium (`CHROMIUM_BIN`; без браузера тест пропускается), входит в `vp run check`.

## Большое файловое дерево

Дерево использует отдельную стратегию: каждый родитель сначала загружает 30
дочерних записей, затем добавляет следующие порции по кнопке «Показать ещё».
Кнопка вызывает `ide.fileTree.directory.loadMore` с путём родителя; доступна
также через клавиатуру. Вложенные папки загружаются только после раскрытия.
Обычная прокрутка сама не инициирует запросы. Обновление сохраняет уже раскрытые
порции; после ошибки старые строки остаются, а запрос можно повторить.

Контракт `tree`: параметры `path`, `offset`, `limit`, необязательный `reveal`.
Ответ содержит `entries`, `total`, `nextOffset` (число или `null`), `truncated`.
Сортировка выполняется до выделения страницы. Локальный backend читает имена
папки целиком, но получает executable-метаданные только для возвращаемых записей.
У GitHub список папки кешируется провайдером: Git Trees API не даёт постраничное
чтение одной папки, поэтому порции выделяются из полученного списка.
Таким образом, стратегия ограничивает обычные ответы и DOM, но не стоимость
чтения и сортировки имён очень большой папки.

Явное «Показать в дереве» автоматически открывает необходимые порции до целевого
элемента, включая промежуточные папки. Это осознанное исключение из начального
лимита 30: файл за пределом первой страницы должен оставаться доступным.
Старое ограничение первых 1000 записей больше не мешает следующей странице.
Индексы страниц не являются снимком файловой системы: при внешнем изменении
папки следует обновить дерево. UI не дублирует строки при повторе пути.

`vp run test:tree` — реальная папка >1000 записей и Chromium.
