# Task: read-only субагент Projector

Инструмент `task` даёт штатному агенту Projector отдельный контекст для исследования проекта. Субагент читает файлы и ищет текст, но ничего не меняет; родитель получает короткую сводку.

## Поведение

- Входные данные: `description` (короткое название), `prompt` (что исследовать) и необязательный `role` — id chat-роли Projector.
- Без `role` субагент наследует `selection` роли текущего чата, если она есть, иначе модель чата.
- Роль с агентом не `projector` и служебная роль отклоняются: `task` всегда работает на встроенном Projector.
- Инструменты только чтение: `read_file`, `list_directory`, `search`.
- Пути проверяются после `realpath`: выход за проект, символические ссылки наружу и файлы с секретными именами отклоняются. `search` запускает ripgrep с `--no-config` и исключает `.env`, ключи и `.ssh`.
- Пределы: 6 шагов модели, 90 секунд, 4000 токенов ответа, 80 000 символов одного чтения или поиска.
- История, MCP, навыки, память, команды IDE и разрешения в субагент не передаются. Он не создаёт run-файл и не продолжается после ответа. Расход его модели не входит в счётчик текущего чата.

## Роль

`role` — chat-роль Projector из `ide.agent.roles.chat.list`. Её `selection` задаёт модель и размышление субагента; `permissionMode`, `isolate` и настройки внешних агентов не применяются. Если роль не указана, используется роль родительского чата, а затем модель чата.

Правка роли после запуска не влияет на уже идущий `task`: субагент живёт в своём контексте и не сохраняет снимок в истории.

## Отображение

Начало и конец `task` приходят в чат событием `task` (`AgentTaskPatch`): вид `agent`, `background: false`, название, `subagent` с именем роли, `prompt`, `tool: "task"`, состояние `running`/`done`/`error`/`stopped`, итоговая подпись и число вызовов. Задача показывается в блоке «Работа» как обычный субагент; отдельной вкладки и нативной сессии у неё нет.

## Ограничения

- Субагент не умеет работать с браузером, чатами, терминалами, Git-командами и внешними MCP.
- Нет вложенного `task`: субагент не получает инструмент `task`.
- Нет фонового режима: родительский ответ ждёт сводку.
- Роль внешнего агента не превращает `task` в задание; для этого есть `ide.agent.job.start`.

## Проверки

`tests/projector-task.test.mjs` — вызов инструмента только при наличии `runTask`, чтение файла в отдельном контексте, события `task`, наследование роли, отказ служебной и чужой роли.
