# Иконки

Интерфейс не импортирует иконки из `~icons/...`: единственное место с этими импортами — [наборы реестра](../packages/client/common/icons/sets.ts). Шаблоны и данные называют иконку строкой, а `ProjectorIcon` ищет компонент в реестре во время отрисовки.

```vue
<ProjectorIcon name="chevron-right" />
<ProjectorIcon name="simple-icons:github" label="GitHub" />
```

Компонент живёт в [`packages/client/common/icons`](../packages/client/common/icons) рядом с реестром: иконки нужны универсальным частям `common/ui`, а не только модулям. Он рендерит только `svg` иконки без обёртки, поэтому прежние CSS-правила вида `.button > svg` продолжают работать; `pointer-events: none` оставляет клики и HTML5-drag кнопке или строке вокруг. Без `label` иконка декоративная (`aria-hidden`), с `label` — `role="img"` и доступное имя.

## Имена

- Без префикса — Lucide: `chevron-right` = `lucide:chevron-right`.
- `simple-icons:github`, `devicon:git` — другой набор; префикс обязателен.
- `alert` — псевдоним `lucide:circle-alert`: это имя документировано для виджета `InlineIcon`.

## Реестр

`registry.ts` собирает наборы в одну карту `lucide:<name>`, `simple-icons:<name>`, `devicon:<name>` и отдаёт публичное API:

| Функция                         | Назначение                                                      |
| ------------------------------- | --------------------------------------------------------------- |
| `resolveIcon(name)`             | Компонент иконки; неизвестное имя даёт запасную иконку          |
| `hasIcon(name)`                 | Проверка без предупреждения — для «есть иконка или точка»       |
| `iconNames()`                   | Все известные имена, включая добавленные в рантайме             |
| `registerIcon(name, component)` | Добавить или заменить иконку под этим именем                    |
| `registerIcons(map)`            | То же для набора; смонтированные иконки обновляются одним разом |
| `unregisterIcon(name)`          | Снять замену, вернуть встроенную иконку                         |

Неизвестное имя один раз пишет `console.warn` с подсказкой и показывает `lucide:circle-question-mark`: опечатка видна, но интерфейс не остаётся с пустым местом. Зарегистрировать иконку можно в любой момент — реестр реактивен, поэтому уже показанные иконки перерисуются. Этим пользуется каталог агентов: SVG плагина регистрируется под именем `agent:<backend>`, а данные продолжают хранить строку.

Данные хранят имена, а не компоненты: `ContextMenuItem.icon`, `SidebarView.icon`, `SidebarItem.icon`, `SessionRow.icon` и `ClientAgent.icon` — строки. Компоненты из данных (`usage`, `component` вкладки) остаются компонентами: это не иконки.

## Новая иконка

1. Добавьте импорт и запись в `sets.ts` (`import LucideThing from "~icons/lucide/thing"`).
2. Используйте `<ProjectorIcon name="thing" />` или `"simple-icons:thing"` для брендов.

Других прямых импортов `~icons/...` в клиенте быть не должно. Виджеты `InlineIcon` и `Chips` проверяют имя через `hasIcon`, чтобы неизвестная иконка не превращалась в вопросительный знак вместо точки.

Иконки файлового дерева — отдельный механизм с CSS-маской и темой в `public/file-icons`: см. [иконки файлов](file-icons.md).

`vp test run packages/client/tests/icons.test.mjs` проверяет наборы, фоллбек, предупреждение и замену.
