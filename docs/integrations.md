# Интеграции

[Начало работы](../README.md) · [Использование](usage.md)

На `/settings` есть раздел «интеграции». Каждая интеграция имеет переключатель, параметры и собственную авторизацию. Общий реестр находится в `server/modules/integrations/index.ts`, реализация GitHub — в `server/modules/integrations/github.ts`.

Настройки и учётные данные сохраняются сервером в `$XDG_DATA_HOME/projector/integrations.json` (по умолчанию `~/.local/share/projector/integrations.json`), с правами `0600` и атомарной заменой файла. Токены и ключи интеграций хранятся в системном хранилище секретов (Linux: Secret Service по D-Bus — KWallet, GNOME Keyring), в файле остаётся только пометка `"vault": "keyring"`. Без доступного хранилища они лежат в этом файле; страница настроек показывает, какой вариант действует. Старые открытые токены переносятся в хранилище при первом открытии настроек: файл переписывается только после проверки, что значение читается обратно. Если запись в хранилище существует, но не открывается (заблокировано, отказ в диалоге), изменения интеграции отклоняются, а сохранённый секрет не затирается. `PROJECTOR_SECRET_STORE=file` отключает хранилище. Если токен GitHub защищён хранилищем, в настройках рядом с ним есть «глазок»: токен показывается на 30 секунд. Просмотр работает только с локальной машины (не по LAN), не для токенов из файла и намеренно не зарегистрирован как IDE-команда, чтобы секрет не попадал к агенту. Токен не возвращается в браузер; `localStorage` для настроек не используется. Существующие настройки интерфейса и модели остаются в `launcher.json` и `providers.json`.

Docker: [контейнеры, Compose и терминалы](docker.md).

### GitHub

1. Укажите папку для импорта. Подключение через токен включает интеграцию автоматически; для Device Flow сначала сохраните параметры интеграции.
2. Авторизуйтесь одним из способов:
   - **Через браузер:** создайте [GitHub OAuth App](https://github.com/settings/developers), включите **Enable Device Flow**, внесите её **Client ID** в настройки Projector. Homepage и callback URL при регистрации можно указать `http://localhost:4177`; Device Flow не использует callback или Client secret. Нажмите «войти через GitHub», откройте ссылку, введите показанный код и подтвердите доступ. Projector запрашивает `repo` для импорта приватных репозиториев.
   - **Personal Access Token:** fine-grained token с доступом к нужным репозиториям и **Contents: read**, либо classic token со scope `repo` для приватных репозиториев. Projector проверяет токен через `/user` перед сохранением. Доступ к организациям может требовать разрешения организации / SSO.
3. На `/projects` откройте «импорт из GitHub». Выберите репозиторий из списка или вставьте `owner/repository` / ссылку GitHub. Список доступных репозиториев загружается страницами по 50, фильтр действует на загруженные записи.

Импорт требует установленного `git`. Репозиторий клонируется по HTTPS в `<папка импорта>/<owner>/<repository>` и регистрируется в `projects.json`. Для JS-проектов читаются `package.json` и команды запуска. Для остальных добавляется безопасная команда `git status`, которую можно заменить в карточке проекта. Projector не устанавливает зависимости и не запускает код при импорте. Существующие папки не перезаписываются; их можно добавить обычным способом как локальный проект.

«Выйти» удаляет сохранённый токен из Projector. Для отзыва доступа на стороне GitHub используйте настройки аккаунта GitHub. Выключение интеграции запрещает новые импорты, сохраняя её параметры и уже добавленные локальные проекты.

Проверка входа, файловых настроек и импорта без обращения к настоящему GitHub:

```bash
node --test tests/integrations.test.mjs tests/launcher.test.mjs
```

Тесты используют временные XDG-каталоги, подмену GitHub API и Git; проверяют обязательную авторизацию, приватные репозитории, пагинацию, Device Flow (ожидание, ограничение частоты, истечение и отмену), права файла, отсутствие токена в публичном API и Git URL, повторный и параллельный импорт.

## Просмотр репозитория без клонирования

`/gh/projects/owner/repository` открывает GitHub как readonly-проект. В сегментированной строке пути он отображается как `gh:/owner/repository`; этот путь можно вводить вместо локальной папки. Кнопка «открыть» в GitHub-панели каталога делает тот же переход. Публичные репозитории доступны без подключения интеграции; приватные используют сохранённый токен включённой интеграции с доступом Contents: read.

Слева — папки и файлы, справа — обычные вкладки Projector с просмотром кода, Markdown и изображений. Дерево загружается по папкам, файлы — при открытии. Ветка фиксируется на коммите до обновления: дерево, файлы и относительные изображения Markdown относятся к одному снимку. `?ref=branch-or-tag` выбирает ref (в том числе имена с `/` через URL encoding), `&path=src/main.ts` открывает конкретный файл; без `path` после открытия автоматически показывается README.md, а по умолчанию используется основная ветка.

В панели инструментов workspace кнопка с логотипом GitHub открывает вкладку **О репозитории** (`ide.github.repository.info`): описание, темы, звёзды, форки, наблюдатели, открытые issues, язык, лицензия, ветка по умолчанию, текущий ref и даты. Значения приходят из того же запроса метаданных; ссылка «Открыть на GitHub» ведёт на страницу репозитория. Для пустого репозитория карточка доступна без дерева и README.

Раздел **Issues** в боковой панели показывает issues выбранного состояния (открытые, закрытые или все) сворачиваемым блоком: номер, заголовок, метки, автора и число комментариев, с подгрузкой следующих страниц по 30. Нажатие открывает отдельную вкладку обсуждения с состоянием, метаданными, Markdown-телом и комментариями; комментарии читаются страницами по 100 до 500, о большем сообщается отдельно. Pull requests из списка исключаются. Действия доступны как `ide.issues.block.toggle`, `ide.issues.filter`, `ide.issues.refresh`, `ide.issues.more` и `ide.issues.open`.

Раздел **Git** показывает историю выбранного ref: граф коммитов, поиск по сообщению или `@автору`, загрузку следующих страниц, раскрытие изменённых файлов и отдельный обзор коммита. Нажатие на файл открывает diff относительно первого родителя; добавления, удаления и переименования учитываются. История и текущие файлы привязаны к одному снимку до обновления workspace. Для другой ветки откройте репозиторий с `?ref=имя-ветки`; режим «все ветки» в этом провайдере недоступен. Все действия доступны через общие команды `ide.git.history.*` и `ide.git.commit.*`.

История читается через [GitHub Commits API](https://docs.github.com/en/rest/commits/commits). Поиск просматривает до 500 коммитов за запрос; при отсутствии совпадений в этой части можно продолжить кнопкой «Показать ещё». Бинарные файлы нельзя сравнить как текст. Для коммитов с 3000 и более изменёнными файлами обзор сообщает об ограничении GitHub API, вместо показа неполного списка.

Просмотр не клонирует репозиторий, не добавляет его в локальный каталог и не запускает команды. Нет записи файлов, Git-мутаций и терминалов. Состояние открытых вкладок пока живёт только в текущей странице. Файлы больше 5 MiB не просматриваются; подмодули обозначаются недоступными для открытия, символические ссылки показывают свой текст. Лимиты GitHub API и отсутствие доступа отображаются как ошибки.

GitHub использует общий `ProjectWorkspace`, дерево файлов, вкладки предпросмотра, toolbar, viewers и мобильные поверхности. Профиль `github` (см. [архитектуру](architecture.md)) предоставляет файлы, историю Git и issues без записи, поэтому запись файлов, Git-мутации, поиск по файлам, терминалы, Docker, чат агента и настройки локального проекта недоступны. Историю Git и issues предоставляют отдельные readonly-провайдеры. Markdown получает readonly-режим в обычном визуальном редакторе.

Действия доступны агенту через `ide.github.repository.open`, `ide.github.repository.refresh` и `ide.github.repository.info` (вкладка о репозитории), а работа с файлами и раскладкой использует общие семейства `ide.fileTree.*`, `ide.editor.*` и `ide.workbench.*`; недоступные для источника команды отключены. Общий переход по строке пути — `ide.project.path.open`. Стрелки между сегментами строки `gh:/owner/repository` открывают другие репозитории того же пользователя или организации (`ide.project.path.suggestions`). При вводе `gh:/owner/` список фильтруется по началу имени; Tab дополняет имя, ↑/↓ выбирают репозиторий, Enter открывает его, Escape закрывает список. Публичные репозитории доступны без входа, приватные — в пределах прав подключённого аккаунта. Список ограничен первыми 1000 репозиториями владельца.

После имени репозитория вместо стрелки находится кнопка клонирования (`ide.github.repository.clone.dialog`). В модальном окне можно ввести папку назначения или выбрать её системным диалогом. Команда `ide.github.repository.clone` (фоновая задача с фазами, отмена — `ide.github.repository.clone.abort`) создаёт копию в `папка/owner/repository`, добавляет её в локальный каталог и после успешного клонирования открывает `/projects/...`. По умолчанию окно выбирает [изолированный запуск через Docker](docker.md#изолированное-клонирование-github): образ, сеть и порты передаются в аргументе `environment`; `"local"` явно выбирает локальный режим. Команда UI без `environment` использует настройки диалога; прямой HTTP-запрос без этого поля сохраняет прежний локальный режим. Публичную копию можно получить без входа; для приватной используется включённая интеграция GitHub. Существующие папки не перезаписываются, установка зависимостей и запуск кода не выполняются. Выбранная в окне папка не меняет настройки интеграции.

Чтение использует [Git Trees](https://docs.github.com/en/rest/git/trees) и [Git Blobs](https://docs.github.com/en/rest/git/blobs); токен остаётся на сервере. Реестр локальных проектов и существующий импорт остаются отдельными сценариями.

## Codex CLI

Projector читает недельный лимит через локальный `codex app-server --stdio` и JSON-RPC `account/rateLimits/read`. Требуются Codex CLI в PATH серверного процесса и выполненный `codex login`; используется существующая авторизация Codex, отдельные ключи Projector не хранит. Запущенные сессии Codex не перезапускаются и не отключаются.

Серверный модуль `server/modules/codex` изолирует протокол CLI, нормализует ответ и объединяет запросы всех окон с кешем на минуту, сохраняемым при HMR. Перед запросом к Codex выполняется фиксированный probe `GET https://ipwho.is/`; лимиты запрашиваются только при `success: true` и `is_eu: true`. `GET /api/codex/usage` возвращает только состояние, недельное окно и время проверки; учётные данные, IP и сведения об аккаунте не публикуются. Недельное окно определяется по длительности 10080 минут, а не по позиции primary/secondary. Ошибка CLI, сетевого probe или отсутствие недельного окна дают явную недоступность.

В статусной строке workspace иконка Codex и полоса показывают **оставшийся** процент недельного лимита. Наведение или клавиатурный фокус показывают время сброса в часовом поясе браузера. Опрос выполняется раз в минуту в видимой вкладке; при закрытии компонента подписка и запрос очищаются.

В подсказках Codex и OpenCode лимиты показаны полосами: рядом с оставшимся процентом внутри каждой полосы находится отсчёт до сброса (`2д 4ч`, `2ч 15м`, `35м` или `<1м`). Прошедший срок обозначается «сейчас», неизвестный — «—». Отсчёт обновляется локально без дополнительных API-запросов. Статусная строка сохраняет компактное отображение процента; точные даты доступны в описании индикатора для средств доступности.

## OpenCode Go

Projector получает реальные лимиты подписки через официальный `GET https://opencode.ai/zen/go/v1/usage`. Установка плагинов и новые зависимости не нужны. Используется ключ `opencode-go.key` из `$XDG_DATA_HOME/opencode/auth.json` (по умолчанию `~/.local/share/opencode/auth.json`); `OPENCODE_AUTH_CONTENT` полностью заменяет содержимое файла, как в OpenCode. Для подключения выполните `opencode auth login` и выберите OpenCode Go. Ключ Zen (`opencode`) не подставляется вместо Go.

Чтение авторизации закрыто в адаптере `core/modules/os`. Ключ отправляется только фиксированному официальному адресу, перенаправления запрещены, таймаут — 10 секунд. `GET /api/opencode/usage` публикует только нормализованные окна (5 часов, неделя, месяц), время проверки и безопасное сообщение об ошибке. Запросы всех окон объединяются с кешем на минуту, сохраняемым при HMR; ошибки также кешируются.

Индикатор с логотипом **OpenCode** рядом с Codex показывает оставшийся процент выбранного лимита (по умолчанию недельного). Клик, Enter или Space переключают окно по кругу: месяц → 5 часов → неделя (`ide.opencode.usage.window.cycle`); подпись «мес», «5ч» или «нед» указывает текущее окно. Переключение использует уже загруженные данные и не делает дополнительных запросов. Выбор живёт в текущем компоненте и не записывается в browser storage. Наведение и клавиатурный фокус раскрывают остаток и время сброса всех трёх окон в часовом поясе браузера. Исчерпанное окно явно помечается; при отсутствии авторизации или ошибке показывается «—». Обновление выполняется раз в минуту в видимой вкладке. Локальная статистика токенов не используется для оценки квот.

## Cursor Agent CLI

Projector читает лимиты подписки через официальный ConnectRPC `POST https://api2.cursor.sh/aiserver.v1.DashboardService/GetCurrentPeriodUsage`. Требуются Cursor Agent CLI в PATH (`agent` / `cursor-agent`) и выполненный `agent login`; используется существующая авторизация Cursor из `$XDG_CONFIG_HOME/cursor/auth.json` (по умолчанию `~/.config/cursor/auth.json`). `CURSOR_AUTH_CONTENT` полностью заменяет содержимое файла. Отдельные ключи Projector не хранит; запущенные сессии Cursor не перезапускаются и не отключаются.

Чтение авторизации закрыто в адаптере `core/modules/os`. Перед запросом к Cursor выполняется фиксированный probe `GET https://ipwho.is/`; лимиты запрашиваются только при `success: true` и `is_eu: true`. Токен отправляется только фиксированному официальному адресу, перенаправления запрещены, таймаут — 10 секунд. `GET /api/cursor/usage` публикует только нормализованные окна (всего, авто-модели, API-модели), время проверки и безопасное сообщение об ошибке. Запросы всех окон объединяются с кешем на минуту, сохраняемым при HMR; ошибки также кешируются. Учётные данные, IP и сведения об аккаунте не публикуются.

Индикатор с логотипом **Cursor** рядом с OpenCode показывает оставшийся процент выбранного лимита (по умолчанию общего). Клик, Enter или Space переключают окно по кругу: всего → авто → API (`ide.cursor.usage.window.cycle`); подпись «вс», «авт» или «API» указывает текущее окно. Переключение использует уже загруженные данные и не делает дополнительных запросов. Выбор живёт в текущем компоненте и не записывается в browser storage. Наведение и клавиатурный фокус раскрывают остаток и время сброса биллингового цикла в часовом поясе браузера. Исчерпанное окно явно помечается; при отсутствии авторизации или ошибке показывается «—». Обновление выполняется раз в минуту в видимой вкладке.
