# Интеграции

[Начало работы](../README.md) · [Использование](usage.md)

На `/settings` есть раздел «интеграции». Каждая интеграция имеет переключатель, параметры и собственную авторизацию. Хранилище настроек и секретов — `server/modules/integration-store`, GitHub — `server/modules/github`, GitLab — `server/modules/gitlab`, общее клонирование — `server/modules/git-import`; статусы собирает маршрут `/api/integrations`.

Настройки и учётные данные сохраняются сервером в `$XDG_DATA_HOME/projector/integrations.json` (по умолчанию `~/.local/share/projector/integrations.json`), с правами `0600` и атомарной заменой файла. Токены и ключи интеграций хранятся в системном хранилище секретов (Linux: Secret Service по D-Bus — KWallet, GNOME Keyring), в файле остаётся только пометка `"vault": "keyring"`. Без доступного хранилища они лежат в этом файле; страница настроек показывает, какой вариант действует. Старые открытые токены переносятся в хранилище при первом открытии настроек: файл переписывается только после проверки, что значение читается обратно. Если запись в хранилище существует, но не открывается (заблокировано, отказ в диалоге), изменения интеграции отклоняются, а сохранённый секрет не затирается. `PROJECTOR_SECRET_STORE=file` отключает хранилище. Если токен GitHub защищён хранилищем, в настройках рядом с ним есть «глазок»: токен показывается на 30 секунд. Просмотр работает только с локальной машины (не по LAN), не для токенов из файла и намеренно не зарегистрирован как IDE-команда, чтобы секрет не попадал к агенту. Токен не возвращается в браузер; `localStorage` для настроек не используется. Существующие настройки интерфейса и модели остаются в `launcher.json` и `providers.json`.

Docker: [контейнеры, Compose и терминалы](docker.md).

### GitHub

1. Укажите папку для импорта. Подключение через токен включает интеграцию автоматически; для Device Flow сначала сохраните параметры интеграции.
2. Авторизуйтесь одним из способов:
   - **Через браузер:** создайте [GitHub OAuth App](https://github.com/settings/developers), включите **Enable Device Flow**, внесите её **Client ID** в настройки Projector. Homepage и callback URL при регистрации можно указать `http://localhost:4177`; Device Flow не использует callback или Client secret. Нажмите «войти через GitHub», откройте ссылку, введите показанный код и подтвердите доступ. Projector запрашивает `repo` для импорта приватных репозиториев.
   - **Personal Access Token:** fine-grained token с доступом к нужным репозиториям и **Contents: read**, либо classic token со scope `repo` для приватных репозиториев. Projector проверяет токен через `/user` перед сохранением. Доступ к организациям может требовать разрешения организации / SSO.
3. В палитре введите `gh/` (список последних репозиториев) или вставьте ссылку GitHub, откройте репозиторий и нажмите кнопку клонирования в строке пути.

Импорт требует установленного `git`. Репозиторий клонируется по HTTPS в `<папка импорта>/<repository>` и регистрируется в `projects.json`. Для JS-проектов читаются `package.json` и команды запуска. Для остальных добавляется безопасная команда `git status`, которую можно заменить в настройках проекта. Projector не устанавливает зависимости и не запускает код при импорте. Существующие папки не перезаписываются; их можно добавить обычным способом как локальный проект.

«Выйти» удаляет сохранённый токен из Projector. Для отзыва доступа на стороне GitHub используйте настройки аккаунта GitHub. Выключение интеграции запрещает новые клонирования, сохраняя её параметры и уже добавленные локальные проекты.

Тесты без настоящего GitHub: `vp test run tests/integrations.test.mjs tests/launcher.test.mjs` (временные XDG-каталоги, подмена GitHub API и Git).

## Просмотр репозитория без клонирования

`/gh/projects/owner/repository` открывает GitHub как readonly-проект. В сегментированной строке пути он отображается как `gh:/owner/repository`; этот путь можно вводить вместо локальной папки. Кнопка «открыть» в GitHub-панели каталога делает тот же переход. Публичные репозитории доступны без подключения интеграции; приватные используют сохранённый токен включённой интеграции с доступом Contents: read.

Слева — папки и файлы, справа — обычные вкладки Projector с просмотром кода, Markdown и изображений. Дерево загружается по папкам, файлы — при открытии. Ветка фиксируется на коммите до обновления: дерево, файлы и относительные изображения Markdown относятся к одному снимку. `?ref=branch-or-tag` выбирает ref (в том числе имена с `/` через URL encoding), `&path=src/main.ts` открывает конкретный файл; без `path` после открытия автоматически показывается README.md, а по умолчанию используется основная ветка.

В панели инструментов workspace кнопка с логотипом GitHub открывает вкладку **О репозитории** (`ide.github.repository.info`): описание, темы, звёзды, форки, наблюдатели, открытые issues, язык, лицензия, ветка по умолчанию, текущий ref и даты. Значения приходят из того же запроса метаданных; ссылка «Открыть на GitHub» ведёт на страницу репозитория. Для пустого репозитория карточка доступна без дерева и README.

Раздел **Issues** в боковой панели показывает issues выбранного состояния (открытые, закрытые или все) сворачиваемым блоком: номер, заголовок, метки, автора и число комментариев, с подгрузкой следующих страниц по 30. Нажатие открывает отдельную вкладку обсуждения с состоянием, метаданными, Markdown-телом и комментариями; комментарии читаются страницами по 100 до 500, о большем сообщается отдельно. Pull requests из списка исключаются.

Раздел **Pull requests** устроен так же: состояние (открытые, закрытые, все), номер, заголовок, метки, автор и ветки `head → base`; влитые PR отмечены отдельно, черновики — значком. Нажатие открывает вкладку PR: состояние, ветки, число коммитов и строк, Markdown-описание, ревью (одобрено / запрошены изменения; пустые обёртки над inline-комментариями скрыты), обсуждение до 500 комментариев и изменённые файлы (до 300; о большем сообщается). Inline-комментарии к коду и diff файлов PR пока не показываются. Действия — `ide.pulls.block.toggle`, `ide.pulls.filter`, `ide.pulls.refresh`, `ide.pulls.more` и `ide.pulls.open` (scope `pulls:<projectId>`). Раздел есть и в локальном проекте с GitHub в `origin`.

Раздел **Discussions** показывает обсуждения тем же блоком: фильтр открытые/закрытые/все, категория, число комментариев, отметка «есть ответ». Вкладка discussion содержит описание, комментарии (до 250) и ответы на них (до 50 на комментарий; об усечении сообщается), комментарий-ответ помечен. Discussions есть только в GraphQL API GitHub, а он работает лишь с токеном: без входа раздел показывает подсказку, а в репозитории с выключенными Discussions — соответствующее сообщение. Страницы идут по курсору, а не по номеру.

Реакции показываются чипами под описанием и комментариями (только чтение). Шорткоды `:name:` в заголовках и readonly-Markdown заменяются картинками из `GET /api/integrations/github/emojis` (прокси к GitHub `/emojis`, кеш сутки; соответствие имён реакций и эмодзи — `REACTION_EMOJI` в `src/common/utilities/github-emoji.ts`). Команды `ide.discussions.*` (scope `discussions:<projectId>`) и `ide.issues.*` устроены как `ide.pulls.*`.

Раздел **Git** показывает историю выбранного ref: граф коммитов, поиск по сообщению или `@автору`, загрузку следующих страниц, раскрытие изменённых файлов и отдельный обзор коммита. Нажатие на файл открывает diff относительно первого родителя; добавления, удаления и переименования учитываются. История и текущие файлы привязаны к одному снимку до обновления workspace. Для другой ветки откройте репозиторий с `?ref=имя-ветки`; режим «все ветки» в этом провайдере недоступен. Все действия доступны через общие команды `ide.git.history.*` и `ide.git.commit.*`.

История читается через GitHub Commits API: поиск просматривает до 500 коммитов за запрос, бинарные файлы не сравниваются как текст, для коммитов с 3000+ файлов обзор сообщает об ограничении API.

Просмотр не клонирует репозиторий, не добавляет его в локальный каталог и не запускает команды. Нет записи файлов, Git-мутаций и терминалов. Состояние открытых вкладок пока живёт только в текущей странице. Файлы больше 5 MiB не просматриваются; подмодули обозначаются недоступными для открытия, символические ссылки показывают свой текст. Лимиты GitHub API и отсутствие доступа отображаются как ошибки.

GitHub использует общий `ProjectWorkspace`, дерево файлов, вкладки предпросмотра, toolbar, viewers и мобильные поверхности. Профиль `github` (см. [архитектуру](architecture.md)) предоставляет файлы, историю Git, issues, pull requests и discussions без записи, поэтому запись файлов, Git-мутации, поиск по файлам, терминалы, Docker, чат агента и настройки локального проекта недоступны. Историю Git и трекеры предоставляют отдельные readonly-провайдеры. Markdown получает readonly-режим в обычном визуальном редакторе.

Действия доступны агенту через `ide.github.repository.open`, `ide.github.repository.refresh` и `ide.github.repository.info` (вкладка о репозитории), а работа с файлами и раскладкой использует общие семейства `ide.fileTree.*`, `ide.editor.*` и `ide.workbench.*`; недоступные для источника команды отключены. Общий переход по строке пути — `ide.project.path.open`. Стрелки между сегментами строки `gh:/owner/repository` открывают другие репозитории того же пользователя или организации (`ide.project.path.suggestions`). При вводе `gh:/owner/` список фильтруется по началу имени; Tab дополняет имя, ↑/↓ выбирают репозиторий, Enter открывает его, Escape закрывает список. Публичные репозитории доступны без входа, приватные — в пределах прав подключённого аккаунта. Список ограничен первыми 1000 репозиториями владельца.

После имени репозитория вместо стрелки находится кнопка клонирования (`ide.github.repository.clone.dialog`). Диалог и команды клонирования живут на уровне всей страницы репозитория (scope `github-clone:<projectId>`), поэтому доступны из командного центра и без открытия строки пути; `clone.directory` и `clone.cancel` имеют `palette: false`, так как работают только внутри открытого окна. В модальном окне можно ввести папку назначения или выбрать её системным диалогом. Команда `ide.github.repository.clone` (фоновая задача с фазами, отмена — `ide.github.repository.clone.abort`) создаёт копию в `папка/repository`, добавляет её в локальный каталог и после успешного клонирования открывает `/projects/...`. По умолчанию окно выбирает [изолированный запуск через Docker](docker.md#изолированное-клонирование-github): образ, сеть и порты передаются в аргументе `environment`; `"local"` явно выбирает локальный режим. Команда UI без `environment` использует настройки диалога; прямой HTTP-запрос без этого поля сохраняет прежний локальный режим. Публичную копию можно получить без входа; для приватной используется включённая интеграция GitHub. Существующие папки не перезаписываются, установка зависимостей и запуск кода не выполняются. Выбранная в окне папка не меняет настройки интеграции.

Чтение использует [Git Trees](https://docs.github.com/en/rest/git/trees) и [Git Blobs](https://docs.github.com/en/rest/git/blobs); токен остаётся на сервере. Реестр локальных проектов и существующий импорт остаются отдельными сценариями.

### GitHub в локальном проекте

Если `origin` локального проекта указывает на GitHub, Projector добавляет часть функций GitHub прямо в обычное рабочее пространство: файлы, редактирование, поиск и Git остаются локальными (дерево и вкладки не меняются), а боковая панель получает раздел **Issues**, а toolbar — кнопку **О репозитории** (`ide.github.repository.info`). Репозиторий определяется по `origin` (HTTPS, `git@github.com:…`, `ssh://…`); `upstream` и другие remote игнорируются. Публичный репозиторий читается без входа; для приватного нужна включённая интеграция GitHub с доступом Contents: read. Проекты в Docker-окружении и проекты без GitHub в `origin` сохраняют прежнее поведение. Метаданные приходят из того же запроса, что и для `gh:/`, но дерево и история при этом локальные.

### GitLab

Раздел **GitLab** в настройках работает с gitlab.com и self-hosted GitLab. Реализация: `server/modules/gitlab`; настройки и токен хранятся так же, как у GitHub (`integrations.json`, системное хранилище секретов).

1. Укажите адрес GitLab (по умолчанию `https://gitlab.com`) и папку для импорта, сохраните настройки. Смена адреса сбрасывает токен: он принадлежит одному серверу.
2. Создайте Personal Access Token со scope `read_api` и `read_repository` и подключите его; Projector проверяет токен через `/api/v4/user`. Токен отправляется только на настроенный адрес, перенаправления запрещены, браузеру он не возвращается (просмотр — «глазок» для токена из хранилища, только локально и не как IDE-команда).
3. В палитре введите `gl/` (недавно активные проекты аккаунта) или `gl/часть-названия`; Enter клонирует проект. Тот же импорт есть в настройках: поле «Клонировать проект» принимает `group/project` или ссылку на сервер GitLab, включая вложенные группы.

Клонирование идёт по HTTPS в `<папка импорта>/<группа>/<подгруппа>/<проект>` (`git` с `core.hooksPath=/dev/null`, токен через временный `GIT_ASKPASS`), проект регистрируется в `projects.json`; зависимости не устанавливаются, код не запускается, существующие папки не перезаписываются. Команды агента: `ide.gitlab.integration.save`, `.connect`, `.disconnect` и `ide.gitlab.repository.import`.

Пока не реализованы: Device Flow/OAuth, просмотр репозитория без клонирования (`gl:/…`), issues и история Git через API, клонирование в Docker.

Проверка без настоящего GitLab: `vp test run tests/gitlab.test.mjs`.

## Лимиты агентов в статусной строке

Код: `server/modules/agents-integration/{codex,claude,opencode,cursor}` (источник данных, кеш) и `src/modules/agents-integration/*` (индикаторы); общее ядро — `_` в обоих корнях. Секреты Projector не хранит: используется существующая авторизация CLI, учётные данные не попадают в публичный API. Запросы всех окон объединяются, кеш переживает HMR, опрос идёт раз в минуту только в видимой вкладке, перенаправления запрещены, таймаут 10 с. Эндпоинты `GET /api/{codex,claude,opencode,cursor}/usage` отдают только нормализованные окна, время проверки и безопасную ошибку. Чтение файлов авторизации закрыто в `core/modules/os`.

| Сервис   | Источник                                                                                    | Авторизация                                                                                                   | Особенности                                                                               |
| -------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Codex    | `codex app-server --stdio`, JSON-RPC `account/rateLimits/read`                              | `codex login`                                                                                                 | Недельное окно определяется по длительности 10080 минут; кеш 1 мин; нет переключения окон |
| Claude   | `GET https://api.anthropic.com/api/oauth/usage` (внутренний API)                            | `claudeAiOauth.accessToken` из `~/.claude/.credentials.json` (`CLAUDE_CONFIG_DIR`); токены не обновляются     | Окна 5ч и неделя; кеш 5 мин; при 429 пауза 5/10/20/30 мин, `Retry-After` приоритетнее     |
| OpenCode | `GET https://opencode.ai/zen/go/v1/usage`                                                   | `opencode-go.key` из `$XDG_DATA_HOME/opencode/auth.json` (`OPENCODE_AUTH_CONTENT`); ключ Zen не подставляется | Окна 5 часов, неделя, месяц; кеш 1 мин, ошибки тоже кешируются                            |
| Cursor   | ConnectRPC `POST https://api2.cursor.sh/aiserver.v1.DashboardService/GetCurrentPeriodUsage` | `$XDG_CONFIG_HOME/cursor/auth.json` (`CURSOR_AUTH_CONTENT`), `agent login`                                    | Окна: всего, авто-модели, API-модели; кеш 1 мин                                           |

Codex и Cursor перед запросом выполняют фиксированный probe `GET https://ipwho.is/` (`server/modules/network/eu-context.ts`): лимиты запрашиваются только при `success: true` и `is_eu: true`.

Индикатор показывает **оставшийся** процент выбранного окна; клик, Enter или Space переключают окно без новых запросов (`ide.<claude|opencode|cursor>.usage.window.cycle`); выбор не сохраняется. Ошибка получения данных не означает исчерпание квоты и показывается как «—».
