# Фоновые задания и делегирование

Задание — один ход Claude Code, Codex, OpenCode, Cursor или Kimi Code, который сервер ведёт сам, без открытой вкладки чата. Только GUI-режим; TUI не участвует. Штатный агент Projector не пишет код сам: он запускает задания, следит за ними и сверяет результат с diff.

## Модель данных

Хранилище: `$XDG_DATA_HOME/projector/agent/jobs/<id>/` (`id` — 12 hex-символов).

- `job.json` — `AgentJob`: `id`, `backend`, `task`, `projectId`, `cwd`, `worktree` (`{ id, branch }`), `worktreeCleared`, `history` (для агентов без нативной сессии, в API не отдаётся), `role` (снимок chat-роли), `selection`, `permissionMode`, `unattended`, `status`, `rev` (растёт при каждой смене), `createdAt`/`startedAt`/`endedAt`, `runId`, `sessionId`, `result` (до 100 000 символов), `error`, `files`, `pending`.
- `journal.json` — события в формате чата (`text`, `tool`, `tool-result`, `task`, `thought`, `permission-request`, `question-request`, `answer`, `status`). Соседние `text` склеиваются, большие входы и выходы обрезаются, не больше 1500 записей. Вкладка задания свёртывает журнал через `applyAgentEvent` и рисует `AgentTurn`.
- Состояния: `queued` (создано, ход ещё не запущен), `running`, `needs-user`, `done`, `error`, `stopped`. Завершённые хранятся 14 дней.

## Поток

1. `POST /api/agent/jobs` проверяет вход и создаёт запись. `packages/server/modules/agent/jobs.ts` создаёт ход (`createRun`, `chat: "job:<id>"`) и вызывает `runAgent` со своим эмиттером. Ход живёт в `packages/cli/app/agent-host.ts`, как и у обычного чата.
2. Эмиттер пишет журнал и обновляет запись: `session` → `sessionId`, `done` → итог, `error` → ошибка.
3. Разрешения и вопросы идут через `createApprovalBridge` и `createQuestionBridge`: карточка журнала, состояние `needs-user`, ответ — `POST /api/agent/jobs/:id/answer`. Мост команд Projector и мост секретов не подключаются.
4. В конце вычисляются изменённые файлы: `git status` до и после, коммиты после стартового `HEAD`, пути из `Write`/`Edit`/`MultiEdit`. Ход удаляется (`removeRun`).
5. `recoverJobs` при старте присоединяется к `queued`/`running`/`needs-user` через `run.attach` и проигрывает трафик хоста заново. Учёт — в `globalThis.projectorAgentJobs`, HMR дублей не создаёт. Неотвеченные запросы после рестарта задаются снова (новые id). Ход с исчезнувшей трассой даёт `error`. `pruneRuns` оставляет ходы заданий на 24 часа.

## API

- `POST /api/agent/jobs` — `{ projectId, backend?, role?, task, isolate?, selection?, mode?, unattended?, origin? }` (`backend` необязателен, если указан `role`; `role` — id chat-роли, её агент и настройки становятся снимком задания; `mode` — режим Claude Code или `mode` ACP; `origin` — ключ чата, который запустил задание).
- `GET /api/agent/jobs` — список без журнала; `?projectId=` фильтрует. `GET /api/agent/jobs/:id` — с журналом; `?wait=<сек ≤45>&rev=<N>` ждёт роста `rev`.
- `GET /api/agent/jobs/:id/diff` — файлы, `--stat`, patch без секретных путей; `?limit=`. После удаления или передачи копии — `409`.
- `GET /api/agent/jobs/:id/worktree`, `POST …/worktree/merge|discard` — копия. Операции взаимоисключающие; слияние и удаление отклоняются, если копию использует другое активное задание.
- `POST …/stop`, `POST …/answer` (`{ request?, allow?, always?, text?, answers? }`), `POST …/send` (`{ text }`: идущему — в текущий ход, `accepted: false` если не умеет; завершённому — новый ход в той же записи, `continued: true`), `POST …/retry` (новый ход с той же задачей, папкой, копией и сессией), `POST …/fork` (`{ task? }`: новая копия из текущего состояния), `DELETE …/:id` (только завершённое).

## Команды

Scope проекта, регистрируются вместе с командами чатов (`model/job-commands.ts`):

- `ide.agent.job.start` `{ agent?, role?, task, isolate? }` — изменяющая команда, штатный агент спрашивает подтверждение; режим разрешений задаёт пользователь. Вместо `agent` можно указать chat-роль: её агент, `selection`, `permissionMode`, промпт, навыки и MCP сохраняются снимком, `isolate` роли включает копию. Роль проекта должна быть доверена.
- `ide.agent.jobs.list` — состояние, запросы, файлы, начало итога. `ide.agent.job.result` `{ job, wait? }` — полный итог, `wait` до 45 с.
- `ide.agent.job.diff` `{ job, limit? }`, `ide.agent.job.log` `{ job, tail? }` — проверка вместо доверия итогу.
- `ide.agent.job.stop`, `.answer` (только вопросы, по идентификаторам вариантов), `.send`, `.retry`, `.continue`, `.fork`, `.open`.
- `.worktree`, `.merge`, `.discard` — копия; слияние и удаление только по просьбе пользователя.

`projector-guard` считает безопасными `result`, `list`, `open`, `diff`, `log`, `worktree`; остальные команды заданий требуют подтверждения.

## Делегирование

- **Задание** — ход внешнего агента под управлением сервера. **Чат Projector** — оркестратор: запускает задания, показывает их как задачи, передаёт запросы, объясняет результат. **Чат внешнего агента** остаётся для ручной работы и продолжения.
- Разрешения и вопросы решает пользователь карточкой в чате Projector; модель видит только «ждёт разрешения» и не может подтвердить за пользователя. `always` и «без вопросов» модель не включает.
- `isolate: true` передаёт штатный агент, когда задачи могут мешать друг другу; по умолчанию — папка проекта. Изоляция — обычный `git worktree`; автослияния нет.
- Когда задание, запущенное этим чатом (`origin`), завершается, чат продолжает разговор сам: в историю добавляется сообщение о завершении с именем сессии, агент проверяет diff и итог.
- Артефакты задания недоверенные: промпт требует сверять их с diff. Файлы с секретными именами (`.env`, ключи, `.ssh`) исключаются из списка, статистики и patch, включая обе стороны переименования.
- `retry`, `fork`, `send`, `merge`, `discard` над одной копией взаимоисключающие. После передачи копии повтору старая запись не может её читать.
- `retry` и `fork` сохраняют снимок роли задания (`job.role`), даже если роль в настройках позже изменена или удалена.
- Задания стартуют сразу; `queued` — короткое состояние до запуска. Планировщика, триггеров и автоповтора нет; повтор после ошибки — явная команда. Вложенное делегирование глубже одного уровня не поддерживается.

## Чат и остров

- Остров активности показывает задания вместе с обычными ходами: агент, тема, состояние, `needs-user`. Клик открывает вкладку только для чтения: журнал, итог, изменённые файлы, «Остановить», «Ответить», «Продолжить в чате».
- В шапке вкладки — имя сессии агента, иначе короткое название из первой фразы задания; полный текст — в свёрнутом блоке «Задание» и подсказке заголовка.
- В чате Projector задания, задачи, план и очередь собраны в одну строку активности над вводом. Ожидающие разрешения и вопросы — в общей стопке карточек; ответ уходит прямо в задание.
- «Продолжить в чате» открывает обычный GUI-чат и возобновляет `sessionId`; для изолированной копии недоступно (сессия привязана к папке копии) — используйте `ide.agent.job.send` или `.continue`.
- Первое сообщение сессии внешнего агента начинается с инструкций включённых возможностей Projector; чат показывает только текст пользователя, инструкции — в сворачиваемом блоке «Возможности Projector».
- Завершение и `needs-user` дают браузерное уведомление на скрытой странице (`lib/notify.ts`).

## Центр работ

Правая полоса workspace (`profile.aside`) открывает «Работы» — обзор всех фоновых заданий и
живых ходов агентов, а не второй чат. Раздел `inbox` есть в локальном профиле и в профилях
GitHub/GitLab; кнопка-колокол в правой части панели инструментов открывает его, а счётчик
показывает, сколько работ ждёт пользователя. Значок раздела на правой полосе повторяет счётчик.

- Одна лента на страницу (`model/jobs-feed.ts`): сервер сам присылает `jobs-changed` и
  `runs-changed` в общий поток `/api/events`, страница перечитывает `GET /api/agent/jobs` и
  `GET /api/agent/runs` и раздаёт результат панели, колоколу, острову и открытым чатам. Панель и
  колокол делят одно состояние, а шина отписывается от последнего потребителя. Вспомогательный
  таймер — раз в 60 секунд; он нужен только если поток пропустил событие. Сервер склеивает
  изменения за 300 мс (`modules/agent/change-events.ts`) и присылает только факт изменения, без
  текста заданий.
- На странице Hub (`/devices/<id>/…`) список устройств приходит событием `hub-devices` по
  управляющему WebSocket Hub → устройство → `/api/events`, а изменения чужих заданий —
  событием `hub-activity`: оно называет устройство, и страница перечитывает только его.
  Резервный опрос устройств, проектов и чужих работ — раз в 30 секунд и сразу при возвращении
  на вкладку. Уведомления на скрытой странице приходят и по этим событиям.
- На странице Hub (`/devices/<id>/…`) список устройств берётся из `/api/hub/devices`, после чего
  задания и ходы читаются у всех онлайн-устройств через `/api/devices/<id>/agent/…`. Действия
  «Остановить», «Прервать» и ответы на разрешения и вопросы уходят на то же устройство.
  Локальный Projector без браузерной сессии Hub показывает только собственные работы.
- Работы делятся на «требует внимания» (`needs-user`, ожидающие карточки, ошибка), «работает»
  (`queued`, `running`, живой ход) и «завершилось». Завершённые показываются за последние сутки
  в свёрнутом блоке; история чатов в список не попадает. Группировка — устройство и проект;
  внутри группы сначала ждущие ответа, затем работающие и завершённые.
- Переход открывает проект и вкладку задания или чата. Для другого устройства ссылка ведёт на
  `/devices/<id>/projects/…?job=…` или `?chat=…`, и страница проекта сразу открывает нужную
  вкладку. Ответы и остановка выполняются прямо в списке, без перехода.
- Уведомление о новом запросе отправляется один раз: подпись включает статус и идентификаторы
  карточек, а карта увиденного переживает скрытие и открытие страницы. Ссылка из уведомления
  ведёт в тот же проект и вкладку. В списке нет полного промпта, содержимого файлов и секретов —
  только тема и безопасный итог.
- Web Push для телефона после HTTPS не входит в этот контур: остаются уведомления открытой PWA
  и браузера на скрытой странице. Команды — `ide.inbox.open`, `ide.inbox.refresh`,
  `ide.inbox.work.open`, `ide.inbox.work.stop`, `ide.inbox.notifications.allow`; открытие панели
  также доступно как `ide.workbench.aside.section.show` с `section: "inbox"`.

## Ограничения

- Задания только для GUI-агентов; TUI не участвует. Своих файловых инструментов у штатного агента нет, автооткат файлов не делается.
- Потолка одновременных заданий нет; задание дольше 24 часов останавливает очистка ходов. Запрос разрешения ждёт до двух часов, потом отклоняется.
- `stop` ждёт хост: после ответа задание получает `stopped`, даже если агент ещё завершается.
- Размер журнала, срок хранения, таймауты ожидания и лимит текста задания — пределы с реальной причиной.
