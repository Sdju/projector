# Делегирование кодовым агентам

Штатный агент Projector не пишет код сам: он запускает фоновые задания Claude Code, Codex, OpenCode, Cursor и Kimi Code, следит за ними и показывает результат. Задание — один ход внешнего агента, которым управляет сервер; вкладка для него не нужна.

Связанные документы: [фоновые агенты](agent-background.md) — модель данных, API и жизненный цикл задания; [форки чатов](chat-forks.md); [SDK команд](ide-commands.md); [возможности агентов](agent-features.md).

## Команды

| Команда                                | Что делает                                                                                         |
| -------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `ide.agent.job.start`                  | Запускает задание: `agent`, `task`, `isolate?`; возвращает запись задания                          |
| `ide.agent.jobs.list`                  | Задания проекта: состояние, ожидающие запросы, файлы, начало итога                                 |
| `ide.agent.job.result`                 | Состояние и полный итог; `wait` до 45 с ждёт смены состояния                                       |
| `ide.agent.job.diff`                   | Файлы, `--stat` и patch того, что сделало задание                                                  |
| `ide.agent.job.log`                    | Последние вызовы инструментов и их вывод                                                           |
| `ide.agent.job.stop`                   | Останавливает задание, сделанное остаётся в файлах                                                 |
| `ide.agent.job.answer`                 | Отвечает на вопросы задания по идентификаторам вариантов; разрешения выдаёт пользователь карточкой |
| `ide.agent.job.send`                   | Уточнение: идущему — в текущий ход, завершённому — новый ход в той же записи                       |
| `ide.agent.job.retry`                  | Повтор с нуля в новой записи, той же копии и сессии                                                |
| `ide.agent.job.continue`               | То же, что `send` для завершённого задания                                                         |
| `ide.agent.job.fork`                   | Новая копия из текущего состояния копии задания                                                    |
| `ide.agent.job.worktree/merge/discard` | Осмотр, слияние и удаление копии задания                                                           |
| `ide.agent.job.open`                   | Открывает вкладку задания: журнал, итог, файлы, запросы                                            |

Задание живёт на сервере (`$XDG_DATA_HOME/projector/agent/jobs/<id>/`), переживает перезапуск, видно в острове активности и во вкладке, уведомляет о завершении и об ожидании пользователя. Состояния: `queued`, `running`, `needs-user`, `done`, `error`, `stopped`. Изоляция — обычный `git worktree`; слияние только по просьбе пользователя.

## Решения

1. **Разрешения решает пользователь, а не модель.** Ожидающий запрос задания показывается карточкой в чате Projector; ответ уходит прямо в задание. Модель видит только «ждёт разрешения» и не может нажать «разрешить».
2. **Чат продолжается сам.** Когда задание завершилось (`done` или `error`), ход Projector возобновляется с результатом; ожидание пользователя показывают карточки, отдельный клик не нужен.
3. **Изоляция остаётся ручной.** `isolate: true` передаёт штатный агент, когда задачи могут мешать друг другу; по умолчанию задание работает в папке проекта.
4. **Задания стартуют сразу.** `queued` — короткое состояние до запуска; если ресурсов действительно не хватит, задание останется в очереди, а не получит отказ. Итог в команде читается целиком, хранилище защищено отдельно.

## Модель

- **Задание** — один ход внешнего агента, которым управляет сервер. Вкладка не нужна; журнал и итог доступны командами и во вкладке.
- **Чат Projector** — оркестратор. Он запускает задания, показывает их как задачи, передаёт пользователю запросы разрешений и объясняет результат.
- **Чат внешнего агента** — обычный графический чат. Он остаётся для ручной работы и для продолжения задания, когда нужен диалог.

Штатный агент не получает файловых инструментов и не откатывает файлы: это работа кодовых агентов. Делегирование — не новая подсистема, а связка существующих чатов, заданий и рабочей области.

## Безопасность

- Разрешения и вопросы задания решает пользователь; модель передаёт только факт ожидания.
- `always` и «без вопросов» не включаются моделью.
- Слияние и удаление копии — только по явной просьбе; автослияния нет.
- Задание запускается с подтверждением старта; параметры задания проверяются на сервере, пути берутся из реестра проектов.
- Артефакты задания (журнал, итог) считаются недоверенными: промпт требует сверять их с diff. Файлы с секретными именами (`.env`, ключи, `.ssh` и т. п.) исключаются из списка, статистики и patch `ide.agent.job.diff`, включая обе стороны переименования.
- Операции `retry`, `fork`, `send`, `merge` и `discard` над одной копией взаимоисключающие. Слияние и удаление дополнительно проверяют, что копия не принадлежит активному заданию; после передачи копии повтору старая запись не может её использовать или читать её diff.

## Границы и пределы

- Автослияние копий и автоматический откат файлов не делаются.
- Вложенное делегирование глубже одного уровня не поддерживается.
- Планировщика и триггеров по событиям нет; повтор после ошибки — явная команда.
- Заданий для TUI-режима нет.
- Своих файловых инструментов у штатного агента нет.
- Очереди с позицией нет: задания стартуют сразу, `queued` — короткое состояние до запуска.
- Остаются пределы с реальной причиной: размер журнала, срок хранения завершённых заданий, таймауты ожидания разрешения и лимит текста задания.
