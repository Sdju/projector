# Роли агентов

Роль — именованный пресет агента, модели и настроек. Есть два вида:

- **Служебные роли** (`doctor`, `lens`, `judge`) — короткие внутренние вызовы Projector без инструментов и истории.
- **Chat-роли** — пользовательские пресеты, которые открывают обычный чат выбранного агента из меню «+», запускают фоновые задания и read-only субагента `task`.
- **Роли проекта** — те же chat-роли, но из `.projector/roles.json`; работают только после явного доверия к файлу.

## Служебные роли

| Роль     | Где работает                         | Что делает                                     |
| -------- | ------------------------------------ | ---------------------------------------------- |
| `doctor` | `form-doctor.ts`, `answer-doctor.ts` | Чинит Vue-разметку формы или готового ответа   |
| `lens`   | `agent-lens.ts`                      | Пишет короткую подпись о текущей работе агента |
| `judge`  | `judge/verdict.ts`                   | Оценивает риск действия перед подтверждением   |

Все три роли выполняются на встроенном бэкенде `projector`: фиксированный промпт, один запрос, без инструментов, без записи истории и без доступа к файлам. Роль меняет только модель; thinking для этих вызовов намеренно погашен через `quietChatModel`. Политика Судьи (`show`, `auto`, `maxRisk`, `confidence`) остаётся в разделе «Судья Projector» и не входит в роль.

Если у роли не выбрана модель, она наследует модель вызывающего чата, а при её отсутствии — активного провайдера. Поэтому до первой настройки поведение прежнее.

## Chat-роли

Chat-роль хранит агента и его настройки: модель, усилие, режим и другие controls, которые публикует адаптер. Название и описание видны в меню новой сессии. Пустое значение control наследует умолчание агента.

Роль применяется **один раз при открытии чата**. В историю чата записывается снимок `AgentRoleSnapshot`:

```ts
interface AgentRoleSnapshot {
  roleId: string;
  name: string;
  selection: Record<string, string>;
  permissionMode?: "default" | "auto" | "bypassPermissions";
}
```

Снимок хранится в `chats.role` (`history.sqlite`) и возвращается в истории и списке недавних чатов. Поэтому:

- правка роли не меняет уже открытые и начатые чаты;
- удаление роли не ломает старые чаты — остаются её имя и настройки;
- ветка чата сохраняет тот же снимок;
- смена модели внутри ролевого чата меняет только снимок этого чата, а не `agentDefaults` для всех новых чатов.

- Открыть роль можно из меню «+» или командой `ide.agent.role.open`; роль открывает вкладку своего агента с новым `chatId`. В меню и командах видны глобальные роли и доверенные роли текущего проекта.

## Фоновые задания

`ide.agent.job.start` принимает `role` вместо `agent` или вместе с ним. Сервер берёт агента роли, её `selection` и `permissionMode`, а `isolate` роли включает изолированную копию. Эти значения записываются в `job.json` как снимок (`job.role`), поэтому `retry` и `fork` не зависят от последующих правок роли. Служебную роль запустить как задание нельзя.

API принимает `role` в `POST /api/agent/jobs`; `backend` можно не передавать. Если передать агента, который не совпадает с ролью, сервер отвечает `400`. Проектная роль должна быть доверена, иначе она не находится.

## Роли проекта

Проект может хранить свои chat-роли в `.projector/roles.json`:

```json
{
  "version": 1,
  "roles": [
    {
      "id": "role-a1b2c3d4",
      "name": "Ревьюер проекта",
      "kind": "chat",
      "agent": "claude-code",
      "selection": { "model": "claude-sonnet" }
    }
  ]
}
```

Пока файл не доверен, роли **не используются** — ни в меню «+», ни в заданиях, ни в `task`. Доверие выдаётся на странице настроек самого проекта, в разделе «Роли проекта», и привязано к хешу файла: любая правка `.projector/roles.json` автоматически отзывает доверие. Решение хранится в `$XDG_DATA_HOME/projector/agent/role-trust.json` с правами `0600`, ключ — реальный путь проекта.

Ссылка `.projector` или `roles.json` за пределы проекта не читается и не доверяется. Служебные роли в проектный файл не принимаются; проектные роли действуют только в своём проекте и перекрывают глобальную роль с тем же id.

API: `GET /api/agent/project-roles?projectId=`, `POST /api/agent/project-roles`, `PUT /api/agent/project-roles/:id`, `DELETE /api/agent/project-roles/:id?projectId=`, `PUT /api/agent/project-roles/trust` `{ projectId, trusted }`.

## Projector task

`task` — read-only субагент Projector в отдельном контексте. Он принимает `role` — chat-роль Projector; без неё наследует роль текущего чата. Служебные роли и роли внешних агентов отклоняются: `task` всегда работает на встроенном Projector. Подробности и пределы — [task](agent-task.md).

## Настройки

Раздел **Настройки → Агент → Роли агентов** показывает служебные и chat-роли.

У служебной роли выбирается модель:

- **Как в чате** — наследовать модель чата;
- конкретная модель из провайдеров Projector — использовать её только для этой роли;
- **Как в чате** кнопкой — удалить сохранённый выбор.

У chat-роли задаются название, агент, описание и controls. Список controls читается у агента в первом проекте каталога; для агентов без проекта доступны их умолчания. Новая роль создаётся кнопкой «Добавить роль» с именем «Новая роль» и агентом Projector, затем редактируется.

Проектные роли настраиваются отдельно, на странице настроек проекта: раздел **«Роли проекта»** показывает файл `.projector/roles.json`, состояние доверия к его текущему хешу и те же карточки ролей. Глобальный раздел «Роли агентов» к проекту не привязан.

Сохранённая модель может исчезнуть из списка провайдеров. Настройки не скрывают её: она показывается как «недоступна», а вызов продолжает работать по обычному fallback провайдера.

Файл: `$XDG_DATA_HOME/projector/agent/roles.json`.

```json
{
  "version": 1,
  "roles": [
    {
      "id": "role-a1b2c3d4",
      "name": "Ревьюер",
      "description": "Проверяет изменения",
      "kind": "chat",
      "agent": "claude-code",
      "selection": { "model": "claude-sonnet" }
    }
  ],
  "builtins": {
    "lens": { "selection": { "provider": "provider-id:model-alias" } }
  }
}
```

Файл пишется атомарно с правами `0600`. Повреждённый JSON откладывается рядом как `roles.json.broken-<время>`, а роли читаются как «все служебные наследуют модель»; chat-роли из повреждённого файла не загружаются, но их можно восстановить из отложенной копии.

## API

- `GET /api/agent/roles` — `{ roles, file }`; у каждой роли `id`, `name`, `description`, `kind`, `agent`, `selection`, `builtin` и `inherited`.
- `POST /api/agent/roles` — `{ role: { name, agent, selection, description? } }`; создаёт chat-роль и возвращает `created`.
- `PUT /api/agent/roles/:id` — для служебной роли `{ selection: { provider } }`; для chat-роли `{ role: { name, agent, selection, description? } }`.
- `DELETE /api/agent/roles/:id` — удаляет chat-роль; служебную удалить нельзя.
- `POST /api/agent/roles/:id/reset` — удаляет сохранённую модель служебной роли.

Чтение доступно странице Projector; изменение требует совпадающего `Origin`. Неизвестная роль и некорректный id дают `400`.

## Команды

Настройки:

- `ide.agent.roles.list` — все роли и путь к файлу.
- `ide.agent.roles.set` `{ role, provider }` — выбрать модель служебной роли; пустая строка — как в чате.
- `ide.agent.roles.reset` `{ role }` — вернуть наследование.
- `ide.agent.roles.create` — создать chat-роль.
- `ide.agent.roles.save` `{ role, name, agent, description?, selection? }` — сохранить chat-роль.
- `ide.agent.roles.delete` `{ role }` — удалить chat-роль.

Рабочая область проекта:

- `ide.agent.roles.chat.list` — chat-роли, доступные для открытия.
- `ide.agent.role.open` `{ role }` — открыть новый чат со снимком роли.

## Ограничения

- Роли проекта — только chat; служебные и роли внешних агентов в `.projector/roles.json` не принимаются.
- Файл ролей проекта без доверия не участвует в меню, заданиях и `task`; правка файла отзывает доверие.
- Chat-роль не меняет промпт, навыки, MCP или хуки: это агент и его controls.
- Служебную роль нельзя запустить как чат, фоновое задание или `task`.
- Смена роли внутри начатого чата не поддерживается: роль фиксируется снимком. Новую роль открывает меню «+».
- Список controls chat-роли берётся из первого проекта каталога; значения, которых нет у агента сейчас, показываются как «недоступно».
