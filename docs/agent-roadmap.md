# Дорожная карта штатного агента Projector

Касается только штатного агента (`server/modules/agents/projector`, OpenAI-compatible провайдеры). Claude Code, Codex, OpenCode и Cursor получают возможности от своих CLI. Состояние на 2026-10-21 взято из кода, не из замеров.

Каждый пункт: что сейчас → что делаем → критерий готовности. Всё новое для пользователя регистрируется как IDE-команда (`ide.*`), а инструменты модели описываются один раз в `tool-specs.ts`.

## Решение 0. Как агент работает с кодом

Ваш ответ: сам код агент не правит, но запускает субагентов, которые работают с кодом. Это вариант A плюс делегирование; фаза 4 (свои файловые инструменты) не делается.

**Принцип: субагент — обычный чат внешнего агента.** Не новая подсистема, а Claude Code, Codex, OpenCode или Cursor в обычной вкладке чата. Пользователь видит его, может остановить, откатить разговор, ответить на запрос разрешения и влить изолированную копию. Всё это уже есть; штатному агенту не хватает только способа этим управлять.

Что уже работает через `execute_command`: `ide.agent.chats.list`, `ide.agent.chat.send/stop/inject`, `ide.agent.chat.isolate`, `ide.agent.worktree.status/merge/discard`, `ide.agent.tasks.list`. Чаты остаются смонтированными в фоне (keep-alive дока), так что вкладку можно открыть, не отнимая фокус.

Чего не хватает, из кода:

1. `ide.workbench.<agent>.open` открывает терминал, если режим сессии TUI, и не возвращает ключ чата.
2. `ide.agent.chat.send` ждёт конца всего ответа, а мост команд обрывает вызов через 60 с (`createCommandBridge`).
3. `ide.agent.turns.list` отдаёт только первые 200 знаков, полного ответа субагента не прочитать.
4. Штатный агент не знает про делегирование: в `IDE_CAPABILITIES` и промпте об этом нет, а промпт отправляет «в терминал».
5. Субагента не видно в панели задач самого штатного чата.

Что делаем (все действия — IDE-команды в реестре):

1. **`ide.agent.chat.delegate`** `{ agent, task, isolate? }`. Открывает новый графический чат выбранного агента независимо от TUI/GUI, в фоновой вкладке; в git-проекте по умолчанию включает изолированную копию (`isolate`), чтобы параллельные субагенты не мешали друг другу. Отправляет `task` первым сообщением, не дожидаясь ответа, и сразу возвращает `{ chat, agent, worktree? }`. Подтверждение как у любой изменяющей команды: карточка показывает агента и задание.
2. **`ide.agent.chat.result`** `{ chat, wait? }`. Возвращает `status` (`running | done | error | needs-user`), полный последний ответ (с лимитом), число и список изменённых файлов, состояние изолированной копии и задач самого субагента. `wait` до 45 с держит вызов, пока не изменится состояние, и умещается в 60 с моста; длиннее агент вызывает команду снова. `needs-user` — субагент ждёт разрешения или ответа в своём чате: штатный агент сообщает об этом и не отвечает за пользователя.
3. **`ide.agent.delegate.agents`** — какие агенты можно запустить (CLI установлен и вошёл) и какой выбран по умолчанию; значение по умолчанию лежит в настройках сессий агентов (`launcher.json`).
4. **Промпт и подсказки.** Строка в `IDE_CAPABILITIES` и правило: любую работу с кодом (написать, править, отлаживать, чинить сборку и тесты) отдавать субагенту; независимые части — разным субагентам, каждый в своей копии; результат сверять с `ide.agent.chat.result` и git-diff; изолированную копию вливать (`ide.agent.worktree.merge`) только по просьбе пользователя. Запрет «писать код не твоя задача» заменяется на «пишешь не сам, а через делегирование».
5. **Панель задач.** Результат `delegate` превращается в `task` события (контракт `agent-task`: `kind: "agent"`, `subagent` — агент, `session` — ключ чата) и обновляется по `result`; клик по задаче открывает вкладку чата субагента, а не только чтение.
6. **Уведомление.** Конец ответа субагента показывается так же, как у обычного чата (уведомление и остров активности), даже если штатный агент уже закончил ход.

Ограничения и риски:

- Команды выполняются в браузере: пока вкладка проекта не открыта, делегировать нельзя (как и для остальных IDE-команд).
- Субагент спрашивает разрешения у пользователя по своим правилам; штатный агент не повышает права и не нажимает за пользователя.
- Один субагент не вызывает других через Projector (глубина 1), чтобы не получить лавину чатов; лимит одновременных делегированных чатов — 4.
- Docker/Dev Container-проекты: внешние чаты там отказывают (см. «Агенты в графическом чате»), делегирование тоже; штатный агент говорит об этом пользователю.

Порядок: сначала команды 1–3 (пользуются ручным вызовом и уже полезны), затем промпт (4), потом панель задач и уведомления (5–6). Переносится в фазу 5.1.

## Фаза 1. Контекст и инструкции (быстрые выигрыши)

1. **Проектные инструкции.** Сейчас в системный промпт не попадают `AGENTS.md` / `CLAUDE.md` проекта. Подмешивать их (с лимитом размера и пометкой источника).
   Готово, когда: агент в проекте с `AGENTS.md` следует его правилам; тест на сборку промпта.
2. **Compaction вместо отбрасывания.** Сейчас `recentTurns` выбрасывает целые старые ходы при ~90 тыс. знаков. Делать: сжимать старые ходы в сводку отдельным запросом к модели, обрезать большие tool-результаты внутри хода, сохранять сводку в истории чата. Команда `ide.agent.compact` для ручного запуска, авто-запуск на 90% контекста (как у Claude Code).
   Готово, когда: длинный чат не теряет цели и решения начала разговора; сводка видна в UI.
3. **Реальный размер окна.** Вместо константы 128k (`PROJECTOR_AGENT_CONTEXT_TOKENS`) брать окно из настроек модели в `providers.json` (поле у модели; env остаётся запасным).
4. **Память.** Файл заметок на проект и на пользователя в `$XDG_DATA_HOME/projector/agent`; инструменты `memory_read` / `memory_write`; просмотр и правка в настройках. Запись только по просьбе пользователя или с подтверждением.

## Фаза 2. Надёжность и управление ходом

1. **Retry и fallback.** Сделано: retry с backoff (3 раза, `Retry-After` уважается) на 429/5xx/обрывах соединения, пока модель ещё ничего не сказала; в чате статус «провайдер не ответил, повтор N». Осталось: обрыв посреди ответа и переход на запасную модель из настроек.
2. **Не только Qwen.** `enable_thinking` задан жёстко. Вынести в возможности модели (`reasoning`, `effort`) и показать как параметр над строкой ввода, как у внешних агентов. Для провайдеров без поддержки не отправлять.
3. **Бюджет хода.** Сделано: лимит шагов настраивается (`PROJECTOR_AGENT_MAX_STEPS`, по умолчанию 24), ход останавливается, когда один и тот же вызов трижды подряд даёт тот же результат, и агент говорит об этом. Осталось: лимиты токенов и времени, кнопка «Продолжить» вместо текста «напишите продолжай».
4. **Prompt caching** там, где провайдер его поддерживает: стабильный префикс (система, инструкции, каталог виджетов), динамика в конце.

## Фаза 3. Расширяемость и внешний мир

1. **MCP-серверы.** Подключать `.mcp.json` проекта и пользовательские серверы (stdio, http/sse) как инструменты агента; ACP-агенты уже получают http/sse оттуда. Подтверждения по тем же правилам, что у остальных инструментов.
2. **Веб.** `web_search` и `web_fetch` как tool-spec; провайдер поиска настраивается в интеграциях, ключ вводится через `request_secret`. Загруженный текст помечается как недоверенный (защита от инъекций в промпт).
3. **Skills и пользовательские команды.** Папка `skills/` в проекте и у пользователя, подгрузка по описанию; слэш-команды для штатного агента. Список доступен команде `list_commands`.
4. **Хуки** (до/после инструмента, при завершении хода) с конфигом на диске; первый пример — уведомление при завершении долгого хода.

## Фаза 4. Работа с кодом (только при варианте B)

1. Инструменты `read_file`, `glob`, `grep`, `edit`, `write` в пределах проекта; правки с diff-подтверждением, как у Claude Code в чате.
2. Долгие фоновые команды через терминальные сессии Projector вместо 30-секундного `bash`; вывод читается как вкладка.
3. Изменение промпта: убрать запрет на код, сохранить приоритет IDE-команд.
4. Откат файлов остаётся не реализованным (решение из прошлой дорожной карты); откатывается только разговор.

## Фаза 5. Автономность и наблюдаемость

1. **Субагенты.** Делегирование кодовым агентам — решение 0. Дополнительно инструмент `task` для чтения без правок: исследование в отдельном контексте на модели провайдера, результат — сводка.
2. **Расход.** Токены и стоимость хода/чата (цены модели в `providers.json`), tooltip как у Claude Code с кэшем.
3. **Расписание и триггеры.** Запуск хода по расписанию или событию (например, упал dev-сервер) с уведомлением; требует отдельного решения о правах без пользователя.
4. **Evals.** Набор сценариев (`tests/`): выбор команд, отказ от выдумывания аргументов, работа с секретами, соблюдение подтверждений. Прогон при смене промпта или модели.
