# Дорожная карта штатного агента Projector

Касается только штатного агента (`server/modules/agents/projector`, OpenAI-compatible провайдеры). Claude Code, Codex, OpenCode и Cursor получают возможности от своих CLI. Состояние на 2026-10-21 взято из кода, не из замеров.

Каждый пункт: что сейчас → что делаем → критерий готовности. Всё новое для пользователя регистрируется как IDE-команда (`ide.*`), а инструменты модели описываются один раз в `tool-specs.ts`.

## Решение 0. Как агент работает с кодом

Ваш ответ: сам код агент не правит, но запускает субагентов, которые работают с кодом. Это вариант A плюс делегирование; фаза 4 (свои файловые инструменты) не делается.

**Принцип: субагент — обычный чат внешнего агента.** Не новая подсистема, а Claude Code, Codex, OpenCode или Cursor в обычной вкладке чата. Пользователь видит его, может остановить, откатить разговор, ответить на запрос разрешения и влить изолированную копию. Всё это уже есть; штатному агенту не хватает только способа этим управлять.

Что уже работает через `execute_command`: `ide.agent.chats.list`, `ide.agent.chat.send/stop/inject`, `ide.agent.chat.isolate`, `ide.agent.worktree.status/merge/discard`, `ide.agent.tasks.list`. Чаты остаются смонтированными в фоне (keep-alive дока), так что вкладку можно открыть, не отнимая фокус.

Чего не хватает, из кода:

1. `ide.workbench.<agent>.open` открывает терминал, если режим сессии TUI, и не возвращает ключ чата.
2. `ide.agent.chat.send` ждёт конца всего ответа, а мост команд обрывает вызов через 60 с (`createCommandBridge`).
3. `ide.agent.turns.list` отдаёт только первые 200 знаков, полного ответа субагента не прочитать.
4. Штатный агент не знает про делегирование: в `IDE_CAPABILITIES` и промпте об этом нет, а промпт отправляет «в терминал».
5. Субагента не видно в панели задач самого штатного чата.

Что делаем (все действия — IDE-команды в реестре):

1. **`ide.agent.chat.delegate`** `{ agent, task, isolate? }`. Открывает новый графический чат выбранного агента независимо от TUI/GUI, в фоновой вкладке; в git-проекте по умолчанию включает изолированную копию (`isolate`), чтобы параллельные субагенты не мешали друг другу. Отправляет `task` первым сообщением, не дожидаясь ответа, и сразу возвращает `{ chat, agent, worktree? }`. Подтверждение как у любой изменяющей команды: карточка показывает агента и задание.
2. **`ide.agent.chat.result`** `{ chat, wait? }`. Возвращает `status` (`running | done | error | needs-user`), полный последний ответ (с лимитом), число и список изменённых файлов, состояние изолированной копии и задач самого субагента. `wait` до 45 с держит вызов, пока не изменится состояние, и умещается в 60 с моста; длиннее агент вызывает команду снова. `needs-user` — субагент ждёт разрешения или ответа в своём чате: штатный агент сообщает об этом и не отвечает за пользователя.
3. **`ide.agent.delegate.agents`** — какие агенты можно запустить (CLI установлен и вошёл) и какой выбран по умолчанию; значение по умолчанию лежит в настройках сессий агентов (`launcher.json`).
4. **Промпт и подсказки.** Строка в `IDE_CAPABILITIES` и правило: любую работу с кодом (написать, править, отлаживать, чинить сборку и тесты) отдавать субагенту; независимые части — разным субагентам, каждый в своей копии; результат сверять с `ide.agent.chat.result` и git-diff; изолированную копию вливать (`ide.agent.worktree.merge`) только по просьбе пользователя. Запрет «писать код не твоя задача» заменяется на «пишешь не сам, а через делегирование».
5. **Панель задач.** Результат `delegate` превращается в `task` события (контракт `agent-task`: `kind: "agent"`, `subagent` — агент, `session` — ключ чата) и обновляется по `result`; клик по задаче открывает вкладку чата субагента, а не только чтение.
6. **Уведомление.** Конец ответа субагента показывается так же, как у обычного чата (уведомление и остров активности), даже если штатный агент уже закончил ход.

Ограничения и риски:

- Команды выполняются в браузере: пока вкладка проекта не открыта, делегировать нельзя (как и для остальных IDE-команд).
- Субагент спрашивает разрешения у пользователя по своим правилам; штатный агент не повышает права и не нажимает за пользователя.
- Один субагент не вызывает других через Projector (глубина 1), чтобы не получить лавину чатов; лимит одновременных делегированных чатов — 4.
- Docker/Dev Container-проекты: внешние чаты там отказывают (см. «Агенты в графическом чате»), делегирование тоже; штатный агент говорит об этом пользователю.

Порядок: сначала команды 1–3 (пользуются ручным вызовом и уже полезны), затем промпт (4), потом панель задач и уведомления (5–6). Переносится в фазу 5.1.

## Фаза 1. Контекст и инструкции (быстрые выигрыши)

1. **Проектные инструкции.** Сейчас в системный промпт не попадают `AGENTS.md` / `CLAUDE.md` проекта. Подмешивать их (с лимитом размера и пометкой источника).
   Готово, когда: агент в проекте с `AGENTS.md` следует его правилам; тест на сборку промпта.
2. **Compaction вместо отбрасывания.** Сейчас `recentTurns` выбрасывает целые старые ходы при ~90 тыс. знаков. Делать: сжимать старые ходы в сводку отдельным запросом к модели, обрезать большие tool-результаты внутри хода, сохранять сводку в истории чата. Команда `ide.agent.compact` для ручного запуска, авто-запуск на 90% контекста (как у Claude Code).
   Готово, когда: длинный чат не теряет цели и решения начала разговора; сводка видна в UI.
3. **Реальный размер окна.** Вместо константы 128k (`PROJECTOR_AGENT_CONTEXT_TOKENS`) брать окно из настроек модели в `providers.json` (поле у модели; env остаётся запасным).
4. **Память.** Сделано: заметки в `$XDG_DATA_HOME/projector/agent/memory` (`user.md` и по файлу на проект), лимит 6000 знаков на область; входят в системный промпт после инструкций проекта; инструменты `memory_read` и `memory_write` (запись только с подтверждением, если не «Без вопросов»; агент пишет по просьбе пользователя); раздел «Память агента» в настройках и команды `ide.agent.memory.get/set`. Готово, когда: «запомни X» переживает новый чат — проверено тестами хранилища, живой разговор с моделью не гонялся.

## Фаза 2. Надёжность и управление ходом

1. **Retry и fallback.** Сделано: retry с backoff (3 раза, `Retry-After` уважается) на 429/5xx/обрывах соединения, пока модель ещё ничего не сказала; если не помогло, отвечает запасная модель провайдера (поле «запасная модель» в настройках, из его зарегистрированных); в чате статусы «провайдер не ответил, повтор N» и «запасная модель · …». Обрыв посреди ответа не повторяется — ход пришлось бы проигрывать заново, поэтому пользователь видит ошибку и жмёт «Повторить».
2. **Не только Qwen.** Сделано: единый адаптер `server/modules/providers/thinking.ts` — диалект провайдера (`thinkingStyle`: qwen, vllm, deepseek, ollama, openai, openrouter, none; по умолчанию от типа, меняется в настройках) превращает выбранный над строкой ввода уровень в поля запроса; `thinking: false` у модели отключает параметр. Диалекты сверены с документацией провайдеров, на живых API не проверены. Осталось: бюджет токенов размышления (`thinking_budget` у Qwen, `reasoning.max_tokens` у OpenRouter).
3. **Бюджет хода.** Сделано: лимиты шагов (`PROJECTOR_AGENT_MAX_STEPS`, 24), времени (`PROJECTOR_AGENT_MAX_SECONDS`, 900 с, 0 — без лимита) и токенов (`PROJECTOR_AGENT_MAX_TOKENS`, по умолчанию без лимита); ход останавливается и на зацикливании (один вызов с тем же результатом трижды подряд). Агент пишет причину, под ответом кнопка «Продолжить». Лимиты проверяются между шагами.
4. **Prompt caching.** Сделано: префикс запроса стабилен (система, каталог виджетов, затем проект, инструкции и сводка — всё, что меняется, в конце), поэтому автоматический кэш DeepSeek, OpenAI и Qwen его находит; тест следит, чтобы в системном промпте не было времени и дат. Под ответом агента подсказка «Токены и кэш» показывает долю из кэша для первого запроса и всего ответа (`cached_tokens` из ответа провайдера). `prompt_cache_hit_tokens` DeepSeek учитывается. Не сделано: явные `cache_control` для Anthropic/Gemini через OpenRouter (SDK кладёт его на уровень сообщения, а OpenRouter ждёт его в части содержимого — нужна проверка на живом API).

## Фаза 3. Расширяемость и внешний мир

1. **MCP-серверы.** Сделано: штатный агент в начале каждого ответа подключает серверы пользователя (`<данные Projector>/agent/mcp.json`) и проекта (`.mcp.json`) — stdio, http (streamable) и sse; инструменты называются `mcp__<сервер>__<инструмент>` и ходят в тот же ход. Сервер из репозитория запускает программу, поэтому запуск подтверждается; инструмент, не помеченный сервером как `readOnlyHint`, перед вызовом спрашивает подтверждение (в режиме «Без вопросов» не спрашивает). Недоступный сервер не ломает ход, агент сообщает о нём пользователю; ответы серверов помечены в промпте как данные. Раздел «MCP-серверы агента» в настройках и команды `ide.agent.mcp.get/set`. Проверено тестом с настоящим stdio-сервером; живой разговор с моделью и http/sse-серверы не гонялись. Осталось: OAuth удалённых серверов, ресурсы и промпты MCP, соединения дольше одного хода.
2. **Веб.** Сделано: инструменты `web_search` и `web_fetch`. Поиск идёт через Brave Search (ключ) или свой SearXNG; выбор и ключ — в настройках «Веб-поиск агента» (команды `ide.agent.web.get/set/key.clear`, ключ в системном хранилище секретов, запись `web-search` в `integrations.json`), либо агент просит ключ через `request_secret` (`kind integration`, `web_search`). `web_fetch` читает http(s)-страницы как текст (до 2 МБ, HTML очищается): адреса локальной сети, включая перенаправления и подмену DNS, недоступны, первое обращение к сайту подтверждается («Всегда» запоминает хост до перезапуска сервера). Результаты помечены `untrusted`, промпт запрещает исполнять инструкции из них. Проверено тестами и живой загрузкой страницы; поиск на живых Brave/SearXNG и разговор с моделью не гонялись. Осталось: PDF и другие не текстовые форматы, JavaScript-страницы, кэш.
3. **Skills и пользовательские команды.** Сделано: навык — папка `skills/<имя>/SKILL.md` с `description:` в шапке, команда — файл `commands/<имя>.md` (`$ARGUMENTS`, `argument-hint:`). Ищутся в папке пользователя (`<данные Projector>/agent/`), в `.projector/` и `.claude/` проекта; одноимённый навык пользователя главнее проектного. В промпт попадают только имена и описания (до 40), текст агент загружает инструментом `use_skill`. Слэш-команды: `/имя аргументы` разворачивается в текст команды или в просьбу применить навык; список для подсказки `/` отдаёт бэкенд вместе со встроенной `/compact`. Раздел настроек «Навыки и команды агента» (только чтение) и команда `ide.agent.skills.list`. Проверено тестами и запросами к API; подсказку `/` в самом чате и разговор с моделью не гонял. Осталось: в истории следующих ходов остаётся набранное `/имя`, а не развёрнутый текст; создание навыков из интерфейса; `allowed-tools` и вложенные папки команд.
4. **Хуки.** Сделано: `<данные Projector>/agent/hooks.json` вида `{"hooks": {"Stop": [{"command": "notify-send Projector готов", "minSeconds": 30}]}}`. События: `PreToolUse` (перед инструментом, в том числе MCP; `matcher` — регулярное выражение по имени инструмента; код выхода 2 запрещает вызов, вывод хука уходит модели как причина), `PostToolUse` (после) и `Stop` (после ответа; `minSeconds` — только для ходов не короче). Команда идёт через оболочку в папке проекта, событие приходит в stdin как JSON, в окружении `PROJECTOR_HOOK_EVENT` и `PROJECTOR_PROJECT_DIR`; таймаут 30 с (`timeout` в секундах). Хук может ответить JSON-ом: `{"decision":"block","reason":"…"}` запрещает вызов, `{"additionalContext":"…"}` у `PostToolUse` дописывается к результату инструмента. Хуки проекта (`.projector/hooks.json`) действуют после подтверждения раз в ход (в режиме «Без вопросов» без вопроса). Раздел настроек «Хуки агента» (проверка файла при сохранении, список действующих хуков) и команды `ide.agent.hooks.get/set`. Проверено тестами `tests/agent-hooks.test.mjs` и запросом к API; страницу в браузере и ход с живой моделью не гонял. Осталось: `SessionStart`, изменение ввода инструмента ответом хука, запуск хуков в `/compact`.

## Фаза 4. Работа с кодом — не делаем

Решение 0 выбрало вариант A: код пишут Codex, Claude Code, OpenCode и Cursor, штатный агент им делегирует. Пункты ниже не реализуются и оставлены как отвергнутый вариант B.

1. Инструменты `read_file`, `glob`, `grep`, `edit`, `write` в пределах проекта; правки с diff-подтверждением, как у Claude Code в чате.
2. Долгие фоновые команды через терминальные сессии Projector вместо 30-секундного `bash`; вывод читается как вкладка.
3. Изменение промпта: убрать запрет на код, сохранить приоритет IDE-команд.
4. Откат файлов остаётся не реализованным (решение из прошлой дорожной карты); откатывается только разговор.

## Фаза 5. Автономность и наблюдаемость

1. **Субагенты.** Делегирование кодовым агентам — решение 0. Дополнительно инструмент `task` для чтения без правок: исследование в отдельном контексте на модели провайдера, результат — сводка.
2. **Расход.** Сделано: у зарегистрированной модели в настройках провайдера появилась цена за 1 млн токенов (вход, выход, из кэша; сохраняется, только когда заданы вход и выход; валюта — как в тарифе, символ не показывается). С ней событие `usage` несёт `cost` ответа (кэш считается по своей цене, без неё — по цене входа), подсказка «Токены и кэш» показывает стоимость ответа и «Весь чат» (токены и стоимость по ответам с ценой, нарастающим итогом). Запасная модель считается по своей цене. Проверено тестами (`tests/agent-cost.test.mjs`); интерфейс в браузере и живой ответ с ценой не гонял. Осталось: цены по умолчанию для известных моделей, учёт сжатия истории и проверки команд (их запросы в сумму не входят), расход за период.
3. **Расписание и триггеры.** Запуск хода по расписанию или событию (например, упал dev-сервер) с уведомлением; требует отдельного решения о правах без пользователя.
4. **Evals.** Сделано: `tests/evals/` — сценарии (`scenarios.mjs`: поиск и вызов команды, `describe_command` перед `execute_command`, отказ выдумывать аргументы, остановка после отказа пользователя, не удалять без просьбы, код — кодовым агентам, секрет формой и без утечки значения) и харнесс (`harness.mjs`: настоящий штатный агент со своим IDE-каталогом, запись вызовов, судья `judge`). Сам харнесс проверяется в обычном `vp test` на подставном OpenAI-сервере со сценарием ответов. Прогон на реальной модели: `PROJECTOR_EVAL=1 OPENAI_URL=… OPENAI_API_KEY=… OPENAI_MODEL=… [PROJECTOR_EVAL_RUNS=3] vp test run tests/agent-evals.test.mjs`. На живой модели ещё не гонялся (локальный сервер был недоступен). Осталось: сценарии про инъекции из веб-страниц и MCP, про навыки и хуки, сохранение результатов прогонов для сравнения моделей.

- Отдельные чаты «отсюда» (решение прошлой карты).
