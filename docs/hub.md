# Projector Hub

Hub — отдельное приложение `@projector/hub` в `packages/hub`. Он отдаёт общий собранный
веб-интерфейс и направляет API-запросы конкретным подключённым экземплярам Projector.
Проекты, файлы, агенты и PTY остаются на устройствах. Браузеру нужен доступ только к Hub.

## Локальный запуск

Требуются зависимости workspace и собранный интерфейс:

```bash
vp install
vp run build
```

Запустите один обычный Projector (`vp dev` или `./bin/projector --server`), затем Hub
в другом терминале. Значения credentials задайте самостоятельно; пароль браузера и
токен подключения устройств должны различаться:

```bash
export PROJECTOR_HUB_PASSWORD='<пароль браузера>'
export PROJECTOR_HUB_DEVICE_TOKEN='<случайный токен устройств>'
vp run hub
```

По умолчанию Hub слушает `127.0.0.1:4180`, публичный origin — `http://localhost:4180`.
В локальном Projector откройте **Настройки → Hub**, укажите адрес, стабильный id устройства
и токен, нажмите «Добавить Hub», затем «Подключить». Можно сохранить несколько хабов;
активен только один. Выбор записи открывает её настройки, «Подключить» переключает туннель.
«Отключить» сохраняет запись и токен, «Удалить» удаляет их и отключает активную запись.
Адрес (origin) идентифицирует запись; сохранение другого адреса добавляет отдельный Hub.
Существующее одиночное подключение загружается автоматически.
Статус обновляется автоматически; смена настроек
и отключение туннеля не перезапускают server и не завершают его задания.
При сохранении существующего подключения пустой токен сохраняет прежний секрет;
для другого адреса Hub требуется новый токен. Токен никогда не возвращается в браузер.

То же подключение доступно через API. Следующая команда использует переменную из
окружения, не помещая токен в аргументы curl:

```bash
node --input-type=module <<'JS'
const response = await fetch('http://localhost:4177/api/hub', {
  method: 'PUT',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    url: 'http://localhost:4180',
    deviceId: 'local',
    token: process.env.PROJECTOR_HUB_DEVICE_TOKEN,
  }),
});
console.log(response.status, await response.json());
JS
```

Откройте <http://localhost:4180> и введите пароль браузера. Вход и список устройств
используют Vue и общие компоненты Projector. Выберите подключённую машину, чтобы открыть
`/devices/local/`. Отключившиеся устройства остаются в списке до перезапуска Hub,
помечаются «Не в сети» и недоступны для открытия. Список обновляется автоматически.
В интерфейсе устройства кнопка «Hub · id» возвращает к списку, «Выйти» отзывает сессию.
Полная навигация между устройствами создаёт отдельный контекст страницы; события и
терминальные SharedWorker разделены по устройствам.

`GET http://localhost:4177/api/hub` показывает `enabled`, `online`, `url`, `deviceId`,
а также `connections: [{url, deviceId}]` без токенов. `url` и `deviceId` верхнего уровня
относятся к активному подключению. `PUT` с `{"enabled":false}` отключает connector,
сохраняя список. `PUT` с `action: "save"` и полями `url`, `deviceId`, `token` сохраняет
запись без переключения; сохранение активной записи обновляет её туннель при изменении
параметров. `action: "activate"` или `"delete"` с `url` подключает или удаляет запись.
Для совместимости `PUT` без `action` сохраняет запись и сразу подключает её. Оба endpoint доступны
только непосредственно с локальной машины. Подключение сохраняется в `hub.json`
в каталоге данных Projector с правами `0600` и восстанавливается при запуске.

## Контракт

- Hub: `GET /api/hub/health`, после входа — `GET /api/hub/devices`.
- Вход: публичная страница `/login` отдаёт собранный `hub.html` без запуска device API.
  `GET /api/hub/session` показывает состояние входа, `POST` с JSON `{password}` создаёт
  сессию, `DELETE` отзывает её. `POST /login` сохраняет совместимость с form-urlencoded.
  После входа можно вернуться только на внутреннюю страницу `/devices/:id/…`.
- Выход и истечение восьми часов закрывают HTTP/SSE/WebSocket текущей сессии на Hub.
  Авторизованные операции и локальные процессы устройства не отменяются.
  Отказ API с challenge `Session realm="Projector Hub"` возвращает браузер ко входу;
  ошибки авторизации провайдеров и других API такого перехода не вызывают.
- Страница устройства: `/devices/:deviceId/…`; статика поступает с диска Hub.
- API устройства: `/api/devices/:deviceId/…`; на устройство передаётся `/api/…`.
- Connector открывает исходящий WebSocket `/api/hub/connect`, протокол версии 1.
  Credentials идут в заголовке Authorization, а не в query.
- Управляющий канал получает одноразовые tickets для исходящих каналов данных.
  Каждый канал привязан к текущему подключению устройства и ограничен таймаутом открытия.
- HTTP, загрузки, SSE и WebSocket передаются потоками с backpressure. До 128 каналов
  на устройство, до 128 устройств. Полные тела запросов и файлов не буферизуются.
- Heartbeat обнаруживает потерю связи, connector переподключается с backoff и jitter.
  Живые запросы при разрыве завершаются; изменяющие операции не повторяются автоматически.
  PTY и агенты продолжают жить на устройстве.
- Недоступное устройство даёт `503`, разрыв уже начатого запроса — `502` либо обрыв потока.

## Доступ и границы первой версии

Это первый контур для одного владельца: общий пароль браузера, сессии в памяти Hub на
8 часов и отдельный общий токен регистрации устройств. После рестарта Hub требуется
повторный вход. Индивидуальные credentials устройств, pairing, отзыв отдельных устройств,
пользователи, ACL и взаимодействие device → device пока не реализованы.

Hub проверяет Host и Origin, не передаёт на устройства собственные cookies и не доверяет
присланным proxy-заголовкам. Локальный server узнаёт туннель по помеченному connector
потоку, а не по HTTP-заголовку. Авторизованный запрос Hub считается удалённым: локальные
операции, включая изменение подключения Hub и перезапуск сервера, остаются закрыты.
Пароль LAN не заменяет авторизацию Hub и не требуется для уже проверенного tunnel-входа.

Для удалённого origin нужен HTTPS. Настройки Hub: `PROJECTOR_HUB_HOST`,
`PROJECTOR_HUB_PORT`, `PROJECTOR_HUB_ORIGIN`. TLS завершает внешний reverse proxy
(например, Caddy), который передаёт исходный Host и поддерживает WebSocket и SSE.
Hub по умолчанию остаётся на loopback за ним. Канал устройства к такому Hub — WSS.
VPS с завершением TLS может читать трафик; сквозного шифрования от браузера до устройства нет.

Сейчас Hub запускается из checkout и использует корневой `dist`; отдельный npm-артефакт,
Docker-образ, агрегированные статусы и встроенный браузер на `*.proxy.localhost` не входят
в этот контур. Интерфейс и устройства следует обновлять вместе: проверяется версия
туннельного протокола, согласование версий всех API ещё не реализовано.

## Проверка

`vp test run tests/hub.test.mjs tests/hub-settings.test.mjs` проверяет собственную статику,
авторизацию, туннель, удалённый контекст, SSE, бинарное тело, WebSocket, отзыв сессий,
безопасный возврат после входа и сохранение/очистку credentials. Для ручной проверки откройте проект
через Hub, прочитайте файл, создайте Shell и выполните команду. После обновления страницы
существующая сессия должна восстановиться. Проверьте отказ локальных операций через Hub.
