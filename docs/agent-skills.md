# Навыки и команды агента

Навык — папка `skills/<имя>/SKILL.md` с инструкцией и шапкой-описанием. Команда — файл `commands/<имя>.md`, который пользователь набирает как `/имя аргументы`. Оба вида читаются с диска на каждом ходу, поэтому правка файла действует со следующего сообщения без перезапуска.

## Где ищутся

Порядок важен: одноимённый навык или команда остаётся за первым источником.

| Источник  | Путь                                                                    | Кто кладёт                      |
| --------- | ----------------------------------------------------------------------- | ------------------------------- |
| `user`    | `$XDG_DATA_HOME/projector/agent/skills/<имя>/SKILL.md`                  | пользователь                    |
| `user`    | `$XDG_DATA_HOME/projector/agent/commands/<имя>.md`                      | пользователь                    |
| `project` | `<проект>/.projector/skills/…`, `.projector/commands/…`                 | проект                          |
| `project` | `<проект>/.claude/skills/…`, `.claude/commands/…`                       | совместимость с Claude Code     |
| `system`  | `packages/server/modules/agents/projector/system-skills/<имя>/SKILL.md` | Projector, вместе с приложением |

Имена — `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`; папка или файл с другим именем пропускаются. Навык пользователя главнее проектного, проектный — встроенного. Команды и навыки не конфликтуют между собой: ключ уникальности — `вид:имя`.

## Формат

Шапка — плоские строки `key: value` между `---`, как у Claude Code. Читаются `description`, `name` (только у навыка: может переименовать папку) и `argument-hint`. Вложенный YAML, массивы и `allowed-tools` не разбираются.

```md
---
name: release
description: Как выпускать версию проекта
argument-hint: <версия>
---

Шаги выпуска…
```

Описание берётся из `description`, иначе из первой непустой строки без `#`, иначе из имени; максимум 240 символов. Тело обрезается до 30 000 символов.

## Как пользуется Projector

- В системный промпт попадают только описания навыков (до 40 пользовательских и проектных); текст грузится инструментом `use_skill`, когда описание подошло задаче. Встроенные навыки перечисляются всегда и не вытесняются списком пользователя.
- `use_skill` возвращает `{ name, instructions, directory }`: соседние файлы навыка агент читает обычными инструментами чтения.
- Команды в промпт не попадают. Сообщение, целиком состоящее из `/имя аргументы`, разворачивается: тело команды заменяет сообщение, `$ARGUMENTS` заменяется аргументами, иначе они дописываются в конец. Для навыка сообщение становится просьбой вызвать `use_skill`.
- Меню `/` показывает команды, навыки и `/compact` (`projectorBackend.commands`).
- Если у команды и навыка одно имя, слэш выбирает команду.

## Встроенные навыки

Системные навыки лежат рядом с кодом агента и попадают в поставку вместе с ним. Они нужны, чтобы держать в базовом промпте только правила, а длинные инструкции подгружать по мере надобности. Сейчас так вынесены: `add-projects` (добавление приложений), `agent-jobs` (ведение фоновых кодовых агентов), `agent-management` (возможности, роли, контролы и сессии агентов), `agent-roles` (проектирование ролей и шаблонов контекста), `docker` (Docker и Compose), `github-ci` (просмотр GitHub и CI), `network-gateway` (LAN-доступ и OpenAI-совместимый API) и `widgets` (создание проектных и встроенных виджетов агента).

Чтобы добавить системный навык, положите `SKILL.md` в `packages/server/modules/agents/projector/system-skills/<имя>/` и опишите в `description`, когда его загружать. Отдельной регистрации нет; шаблон копируется в `@ai-projector/ide` при сборке. Пользователь может заменить встроенный навык своим или проектным с тем же именем.

## Роли и внешние агенты

Chat-роль хранит имена: поле `skills` отсутствует — видны все навыки, `[]` — ни одного, список — только выбранные. Для Projector это ещё и ограничение `use_skill`. Внешним агентам роль передаёт имена и пути к файлам (`agent-roles/runtime.ts`), чтобы они прочитали инструкцию сами; их нативные навыки список роли не отключает.

Боковые вопросы (`side`) и субагент `task` навыков не получают: у них свой набор инструментов. Терминальные сессии Projector тоже не ведёт.

## Настройки и API

- Настройки → «Навыки агента»: список с источником и пути папок. Создания и правки в интерфейсе нет.
- `GET /api/agent/skills?projectId=…` — `{ skills, folders }`.
- `ide.agent.skills.list` `{ projectId? }` — то же для агента.
- Код: `projector-skills.ts` (поиск, шапка, слэши), `agent-tools.ts` (`use_skill`), `projector-backend.ts` (промпт), `agent-roles/runtime.ts` (контекст внешних агентов).
- Проверки: `packages/server/tests/agent-skills.test.mjs`, контекст ролей — `packages/server/tests/agent-roles.test.mjs`.
