# Возможности агентов

Необязательные умения, которые Projector добавляет агенту: виджеты в ответах — графики, показатели, вкладки и формы прямо в markdown — и команды IDE через MCP. Умолчания задаются на странице агента в настройках «Агенты» рядом с его включением и режимом сессий, а остров **возможности** в табе агента переопределяет их только для текущего чата.

## Умолчания и переопределение

- **Умолчания** лежат в `$XDG_DATA_HOME/projector/agent/features.json`:

  ```json
  { "features": { "widgets": ["projector", "codex"] } }
  ```

  Возможность, которой нет в файле, использует свои умолчания; у виджетов это `projector`. Пустой список — «выключено у всех». Запись атомарная, через временный файл; повреждённый JSON читается как «всё по умолчанию».

- **Выбор чата** — список id возможностей, сохранённый вместе с чатом (`chats.features` в `agent/history.sqlite`). Пока его нет, действуют умолчания; пустой список — «в этом чате всё выключено». Кнопка «Как по умолчанию» удаляет выбор чата.
- Переопределение передаётся серверу вместе с каждым ходом (`features` в `POST /api/agent`), поэтому применяется и после перезагрузки страницы.
- Остров в табе агента показывает только возможности этого чата; умолчания каждого агента лежат на его странице в настройках «Агенты». Изменение умолчания в настройках сразу видно в открытых чатах без собственного выбора.

## Как возможность попадает в модель

Текст возможности — обычная строка, которую отдаёт её определение. Каждый бэкенд доставляет её своим путём, потому что у агентов разные точки входа:

| Агент                               | Куда попадает текст                                                        | Когда действует         |
| ----------------------------------- | -------------------------------------------------------------------------- | ----------------------- |
| Projector                           | системный промпт, раздел «Интерактивные блоки»                             | со следующего сообщения |
| Claude Code                         | `systemPrompt.append` рядом со штатным промптом `claude_code`              | со следующего сообщения |
| Codex, OpenCode, Cursor, Kimi (ACP) | первое сообщение новой сессии, перед вопросом пользователя и после истории | в новой сессии          |

- ACP-сессия, продолженная через `session/load`, уже содержит прежний контекст: новая настройка применится в следующей сессии, а не задним числом.
- Claude Code не записывает системный промпт в сессию (`snapshot: false`), поэтому переключатель применяется со следующего сообщения, даже если сессия продолжается.
- Ничего не пишется в конфиги Claude Code, Codex, Cursor, Kimi или в проект: только в промпт.
- Промпт chat-роли добавляется рядом с возможностями: у Projector — в системный промпт, у Claude Code — в тот же `systemPrompt.append`, у ACP — в первое сообщение перед возможностями. Снимок роли применяется к каждому ходу, поэтому уже начатый чат сохраняет свой промпт. Навыки и MCP роль ограничивает отдельно — см. [роли агентов](agent-roles.md).
- Если у текущего проекта есть доверенный `.projector/widgets.json`, его виджеты добавляются к справке `widgets` только в чатах этого проекта. `describe_widget` и MCP-сервер `projector-widgets` получают `projectId` и описывают проектные определения; без доверия они не видны — см. [компоненты в ответах](agent-widgets.md).

Текст виджетов собирается из живого каталога (`widgetCatalog.guide()`), как и промпт Projector: описание компонентов не может разойтись с тем, что умеет рисовать клиент. Обычные виджеты описаны целиком, специальные (`special: true`) — только именем и условием использования. Их свойства и пример выдаёт `describe_widget`: у штатного Projector это встроенный инструмент, внешним агентам при включённых виджетах передаётся stdio-сервер `projector-widgets`.

Hosted-ход — отдельный процесс со своей композицией. `packages/server/app/plugin.ts` регистрирует возможности для сервера, `projector-runner.ts` и `claude-runner.ts` — для ответов Projector и Claude Code; новый раннер обязан сделать те же вызовы, иначе каталог в нём пуст и включённая галочка ничего не добавит. Это проверяет тест, который запускает раннер отдельным процессом.

## Команды IDE через MCP

Возможность `ide` даёт внешнему агенту доступ к живому реестру команд Projector. Она выключена по умолчанию: команды меняют файлы, Git и сам Projector, поэтому пользователь включает её в настройках или в острове конкретного чата.

- **Не по инструменту на фичу.** MCP-сервер `projector-ide` отдаёт три инструмента: `list_commands`, `describe_command` и `execute_command`. Каталог читается из открытой страницы, поэтому новых команд не нужно описывать в MCP отдельно. Это та же модель, что у штатного агента Projector; у него эти инструменты уже есть, и MCP ему не передаётся.
- **Виджеты по требованию.** Отдельный `projector-widgets` отдаёт один инструмент `describe_widget`. Он передаётся внешним агентам только при включённой возможности `widgets` и читает тот же статический каталог определений; подробности специальных виджетов не занимают постоянный промпт. Для обычного виджета инструмент тоже вернёт описание, но вызывать его не обязательно.
- **Как доставляется.** Claude Code получает сервер в `mcpServers` каждого запроса, ACP-агенты — в `session/new` и `session/load` рядом с серверами проекта. Терминальные сессии возможность не получают.
- **Как выполняется.** MCP-сервер запускается агентом как stdio-процесс с `PROJECTOR_PROJECT_ID` и ключом из `agent/ide-mcp.token`. Он зовёт `POST /api/ide/command-request`; сервер шлёт событие `ide-command-request` в открытые страницы, страница проекта забирает запрос (claim), выполняет его через браузерный SDK и возвращает результат. Чужие проекты и закрытая страница недоступны.
- **Одна страница на MCP-сессию.** Первая ответившая вкладка становится владельцем сессии: следующие вызовы идут к ней, поэтому `list_commands`, `describe_command` и `execute_command` видят один workbench. Другая вкладка может взять запрос после короткой паузы, если владелец не ответил; закрытие владельца освобождает сессию, а уже выполнявшийся запрос завершается ошибкой, а не повторяется.
- **Подтверждение и срок.** Команды, которые только смотрят или открывают, выполняются сразу. Изменяющая команда показывает `confirm` в окне Projector; отказ возвращает агенту ошибку. Это отдельный от чата запрос, потому что MCP-процесс живёт вне SSE-потока ответа. В событии есть `expiresAt`; страница проверяет срок перед подтверждением и перед выполнением, получает отмену по `ide-command-cancel` и передаёт команде `AbortSignal`.
- **Границы.** Нужна открытая вкладка проекта; запрос живёт 60 секунд. Изолированная копия проекта работает с командами исходного проекта. ACP-сессия, продолженная через `session/load`, может не обновить список MCP-инструментов до новой сессии. Свой сервер `projector-ide` из `.mcp.json` не трогается, пока встроенная возможность выключена.

### Как добавить возможность

1. `packages/server/app/features.ts`: `registerAgentFeature({ id, title, summary, defaults, instruction: () => "…" })`. `instruction` вызывается при каждом ходе, поэтому может читать актуальный каталог.
2. Если возможность умеет только часть агентов, ограничьте `defaults` и проверяйте id в своём бэкенде.
3. Добавьте доставку в бэкенды, где она нужна: Projector — в `buildSystemPrompt`, Claude Code — в `claudeSystemPrompt` (`systemPrompt.append`), ACP — в `featurePrompt` первого сообщения. `featurePrompt` фильтрует по включённым возможностям и принимает выбор чата.
4. Для нового hosted-раннера вызовите `registerBuiltinWidgetDefinitions()` и `registerBuiltinAgentFeatures()` до `runHostedRunner`, как в `projector-runner.ts` и `claude-runner.ts`.
5. `vp test run tests/agent-features.test.mjs`.

## API и команды

- `GET /api/agent/features` — `{ features: [{ id, title, summary, agents: [{ id, label, enabled }] }], file }`; `enabled` — умолчание.
- `PUT /api/agent/features` — `{ feature, agent, enabled }`; меняет умолчание и отвечает тем же состоянием.
- `POST /api/agent` принимает `features: string[]` — выбор чата; пустой список выключает всё, отсутствие поля означает умолчания.
- `GET/PUT /api/agent/history/:chat` возвращает и сохраняет `features` рядом с `turns`; `null` — вернуть умолчания.
- В табе агента (scope `surface: agentFeatures`): `ide.agent.features.chat.list`, `ide.agent.features.chat.set` `{ feature, enabled }`, `ide.agent.features.chat.reset`, `ide.agent.features.panel`.
- В настройках (scope `surface: agentFeatureDefaults`): `ide.agent.features.defaults.list`, `ide.agent.features.defaults.set` `{ feature, agent, enabled }`.

## Ограничения

- Возможности живут в промпте, а не в файлах агента: нативные `SKILL.md`, правила Cursor и `AGENTS.md` не создаются. Исключение — MCP-сервер `projector-ide`: он передаётся в конфигурацию сессии, но в файлы проекта и пользователя не пишется.
- Терминальные сессии (TUI) возможностей не получают: их ведёт сам CLI, Projector в его контекст не вмешивается.
- Команды IDE требуют открытой вкладки проекта: пока страница закрыта, MCP-вызов ждёт ответа и завершается ошибкой через 60 секунд.
- Выбор чата не копируется в ветку или форк: новая ветка начинает с умолчаний.
- Разные наборы для разных моделей одного агента не поддерживаются.
