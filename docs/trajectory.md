# Траектория агента

Панель показывает ход работы агента как журнал записей и обзорную шкалу: запросы, ответы, размышления, инструменты, задачи, контекст и сжатие. Данные приходят из команды агента (готовый документ или сессия) либо из файла `*.trajectory.json`; сама панель не читает бэкенд и не сохраняет данные на диск.

## Где открыть

- **Вкладка** — команда `ide.trajectory.open` с данными.
- **Правая панель** — команда `ide.trajectory.panel` с теми же данными. Панель включается для проекта и выбирает раздел «Траектория»; на телефоне вместо неё открывается вкладка.
- **Файл** — откройте `incident.trajectory.json` или `incident.trace.json` как обычный файл.

Повторный вызов с тем же `id` обновляет документ: открытая вкладка и панель перерисовываются.

## Команды

### `ide.trajectory.open`

Открывает вкладку. Аргументы:

| Поле       | Что это                                           |
| ---------- | ------------------------------------------------- |
| `data`     | Объект траектории или JSON-строка с ним           |
| `document` | Готовый документ `{ title?, subtitle?, data }`    |
| `title`    | Заголовок вкладки                                 |
| `subtitle` | Пояснение под заголовком                          |
| `id`       | Идентификатор документа; без него создаётся новый |

Без `data`/`document` открывается последний документ. Если документов ещё нет — ошибка.

### `ide.trajectory.panel`

То же, но показывает документ в правой панели. На телефоне открывает вкладку. Без `data` берёт последний документ.

### Генерация из сессии

Три команды собирают документ из открытого чата или прошлой сессии:

| Команда                           | Что делает                                           |
| --------------------------------- | ---------------------------------------------------- |
| `ide.trajectory.session.generate` | Собирает и запоминает документ, вкладку не открывает |
| `ide.trajectory.session.open`     | Собирает и открывает вкладку                         |
| `ide.trajectory.session.panel`    | Собирает и открывает правую панель                   |

Аргументы: `chat` (ключ открытого чата) или `session` (прошлая сессия с обязательным `backend`), а также `adapter`, `id`, `title`, `subtitle`. Если источник не указан, берётся открытый чат, с которым работали последним. Для чата используется история его активной ветки. `ide.trajectory.session.generate` возвращает `{ id, title, adapter, counts, warning? }`. Результат можно открыть через `ide.trajectory.open` с этим `id`.

### Адаптеры

Генератор выбирает адаптер по `backend`, затем общий `turns`:

| id          | Что читает                                                                                                                                                  |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `turns`     | История открытого чата или `loadSessionTurns` любого агента                                                                                                 |
| `projector` | То же для встроенного Projector-агента                                                                                                                      |
| `opencode`  | Явно указанная сессия OpenCode из каталога проекта или его изолированной копии. SQLite даёт шаги, TTFT/decoding, reasoning, инструменты, usage и compaction |

Если адаптер не может собрать подробную траекторию, генератор пробует `turns` и возвращает `warning` с причиной. Для OpenCode запасной вариант тоже требует подтвердить принадлежность сессии проекту. Старые базы OpenCode могут дать историю через ACP. Отключить запасной вариант можно аргументом `fallback: false` в API генератора.

Свой адаптер регистрируется в клиентском коде:

```ts
import { registerTrajectoryAdapter } from "@ai-projector/client/modules/agent-trajectory/index.ts";

const detach = registerTrajectoryAdapter({
  id: "my-agent",
  label: "My Agent",
  backends: ["my-agent"],
  async generate(session, context) {
    const payload = await context.request("/api/my-agent/trajectory", {
      projectId: session.projectId,
      sessionId: session.session,
    });
    // data должен иметь форму TrajectoryData; панель сама пересчитает counts/usage
    return { data: payload.data, title: payload.title, source: "my-agent" };
  },
});
```

`context` даёт `loadTurns()` (чат, переданные turns или прошлая сессия), `chatTurns()` и `request()` для собственного серверного endpoint. Вызов `detach()` убирает адаптер.

## Формат

Минимальный документ — только записи:

```json
{
  "format": "projector.trajectory",
  "version": 1,
  "title": "Разбор падения",
  "data": {
    "records": [
      {
        "id": "u",
        "kind": "user",
        "turn": 1,
        "title": "Почему упал тест?",
        "text": "Почему упал тест?"
      },
      {
        "id": "a",
        "kind": "assistant",
        "turn": 1,
        "title": "Ответ",
        "text": "Причина в устаревшем ожидании."
      },
      {
        "id": "t",
        "kind": "tool",
        "turn": 1,
        "title": "Команда",
        "text": "FAIL tests/core",
        "status": "error",
        "durationMs": 3500,
        "startedAt": 1790000000000,
        "endedAt": 1790000003500
      }
    ]
  }
}
```

`turns` можно не передавать: нормализатор сгруппирует записи по `turn` и заполнит заголовки, счётчики и usage. Можно передать и полный `TrajectoryData` с `turns`, `records`, `counts`, `usage`, `capabilities`; счётчики и usage всё равно пересчитываются.

Также принимаются:

- прямой объект `{ "records": [...] }` без обёртки;
- `turns` из чата (`role: "user" | "assistant"`, `text`, `tools`, `parts`) — они проецируются текущим чат-адаптером;
- JSON-строка вместо объекта.

### Запись

| Поле                   | Обязательное | Смысл                                                                                                                                    |
| ---------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                   | нет          | Стабильный идентификатор; без него `record:<index>`                                                                                      |
| `kind`                 | нет          | `user`, `assistant`, `thought`, `tool`, `subtool`, `task`, `note`, `judge`, `context`, `system`, `compaction`; неизвестное станет `note` |
| `turn`                 | нет          | Номер хода, по умолчанию 0                                                                                                               |
| `title`                | нет          | Название строки; по умолчанию название вида                                                                                              |
| `text`                 | нет          | Короткая строка журнала                                                                                                                  |
| `detail`               | нет          | Полный текст для инспектора; для сообщений рендерится Markdown                                                                           |
| `status`               | нет          | `running`, `done`, `error`, `stopped`                                                                                                    |
| `startedAt`, `endedAt` | нет          | Unix-время в миллисекундах                                                                                                               |
| `durationMs`           | нет          | Длительность, если концы не записаны                                                                                                     |
| `tool`                 | нет          | Данные инструмента: `id`, `name`, `status`, `input`, `detail`, `output`, `time`                                                          |
| `task`                 | нет          | Задача: `id`, `kind`, `title`, `status`, `summary`, `log`                                                                                |
| `usage`                | нет          | `input`, `output`, `cacheRead`, `cacheWrite`, `cost`                                                                                     |
| `parentId`             | нет          | Родительский вызов или задача                                                                                                            |
| `meta`                 | нет          | Дополнительные поля для инспектора                                                                                                       |

Незаполненные поля не выдумываются: шапка панели показывает, что именно недоступно (`шаги модели`, `TTFT`, `сжатие`). Чтобы они перестали считаться недоступными, передайте `capabilities` с `true` и заполните соответствующие записи.

## Ограничения

- Документы живут в памяти страницы: после перезагрузки вкладка откроется пустой, пока команда не пришлёт данные снова.
- Панель не читает файлы сама; файл открывается штатным `ide.editor.path.open` или деревом проекта.
- Исполнение и сохранение данных — не задача панели; она только отображает присланный документ.

## Где лежит

- `packages/client/modules/agent-trajectory/model/types.ts` — контракт `TrajectoryData` и документа.
- `model/documents.ts` — разбор `.trajectory.json` и команды.
- `model/store.ts` — общие документы вкладки и панели.
- `model/commands.ts` — команды данных и генерации сессий.
- `model/generator.ts` — реестр адаптеров, встроенные `turns`/`projector`/`opencode`, fallback.
- `packages/server/modules/agents/opencode/trajectory.ts` — чтение и сериализация шагов из базы OpenCode в рабочем потоке.
- `ui/AgentTrajectoryTab.vue`, `ui/AgentTrajectoryAside.vue`, `ui/TrajectoryDocumentView.vue` — три поверхности.
