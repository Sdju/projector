# Траектория агента

Панель показывает ход работы агента как журнал записей и обзорную шкалу: запросы, ответы, размышления, инструменты, задачи, контекст и сжатие. Данные приходят **только** из команды агента или из файла `*.trajectory.json`; сама панель ничего не читает у бэкенда и не сохраняет данные на диск.

## Где открыть

- **Вкладка** — команда `ide.trajectory.open` с данными.
- **Правая панель** — команда `ide.trajectory.panel` с теми же данными. Панель включается для проекта и выбирает раздел «Траектория»; на телефоне вместо неё открывается вкладка.
- **Файл** — откройте `incident.trajectory.json` или `incident.trace.json` как обычный файл.

Повторный вызов с тем же `id` обновляет документ: открытая вкладка и панель перерисовываются.

## Команды

### `ide.trajectory.open`

Открывает вкладку. Аргументы:

| Поле       | Что это                                           |
| ---------- | ------------------------------------------------- |
| `data`     | Объект траектории или JSON-строка с ним           |
| `document` | Готовый документ `{ title?, subtitle?, data }`    |
| `title`    | Заголовок вкладки                                 |
| `subtitle` | Пояснение под заголовком                          |
| `id`       | Идентификатор документа; без него создаётся новый |

Без `data`/`document` открывается последний документ. Если документов ещё нет — ошибка.

### `ide.trajectory.panel`

То же, но показывает документ в правой панели. На телефоне открывает вкладку. Без `data` берёт последний документ.

## Формат

Минимальный документ — только записи:

```json
{
  "format": "projector.trajectory",
  "version": 1,
  "title": "Разбор падения",
  "data": {
    "records": [
      {
        "id": "u",
        "kind": "user",
        "turn": 1,
        "title": "Почему упал тест?",
        "text": "Почему упал тест?"
      },
      {
        "id": "a",
        "kind": "assistant",
        "turn": 1,
        "title": "Ответ",
        "text": "Причина в устаревшем ожидании."
      },
      {
        "id": "t",
        "kind": "tool",
        "turn": 1,
        "title": "Команда",
        "text": "FAIL tests/core",
        "status": "error",
        "durationMs": 3500,
        "startedAt": 1790000000000,
        "endedAt": 1790000003500
      }
    ]
  }
}
```

`turns` можно не передавать: нормализатор сгруппирует записи по `turn` и заполнит заголовки, счётчики и usage. Можно передать и полный `TrajectoryData` с `turns`, `records`, `counts`, `usage`, `capabilities`; счётчики и usage всё равно пересчитываются.

Также принимаются:

- прямой объект `{ "records": [...] }` без обёртки;
- `turns` из чата (`role: "user" | "assistant"`, `text`, `tools`, `parts`) — они проецируются текущим чат-адаптером;
- JSON-строка вместо объекта.

### Запись

| Поле                   | Обязательное | Смысл                                                                                                                                    |
| ---------------------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `id`                   | нет          | Стабильный идентификатор; без него `record:<index>`                                                                                      |
| `kind`                 | нет          | `user`, `assistant`, `thought`, `tool`, `subtool`, `task`, `note`, `judge`, `context`, `system`, `compaction`; неизвестное станет `note` |
| `turn`                 | нет          | Номер хода, по умолчанию 0                                                                                                               |
| `title`                | нет          | Название строки; по умолчанию название вида                                                                                              |
| `text`                 | нет          | Короткая строка журнала                                                                                                                  |
| `detail`               | нет          | Полный текст для инспектора; для сообщений рендерится Markdown                                                                           |
| `status`               | нет          | `running`, `done`, `error`, `stopped`                                                                                                    |
| `startedAt`, `endedAt` | нет          | Unix-время в миллисекундах                                                                                                               |
| `durationMs`           | нет          | Длительность, если концы не записаны                                                                                                     |
| `tool`                 | нет          | Данные инструмента: `id`, `name`, `status`, `input`, `detail`, `output`, `time`                                                          |
| `task`                 | нет          | Задача: `id`, `kind`, `title`, `status`, `summary`, `log`                                                                                |
| `usage`                | нет          | `input`, `output`, `cacheRead`, `cacheWrite`, `cost`                                                                                     |
| `parentId`             | нет          | Родительский вызов или задача                                                                                                            |
| `meta`                 | нет          | Дополнительные поля для инспектора                                                                                                       |

Незаполненные поля не выдумываются: шапка панели показывает, что именно недоступно (`шаги модели`, `TTFT`, `сжатие`). Чтобы они перестали считаться недоступными, передайте `capabilities` с `true` и заполните соответствующие записи.

## Ограничения

- Документы живут в памяти страницы: после перезагрузки вкладка откроется пустой, пока команда не пришлёт данные снова.
- Панель не читает файлы сама; файл открывается штатным `ide.editor.path.open` или деревом проекта.
- Исполнение и сохранение данных — не задача панели; она только отображает присланный документ.
