# Иконки файлов

Дерево использует самостоятельный resolver из `core/modules/file-icons/contract.ts`. Он не зависит от Vue, сервера или списка поддерживаемых языков. Компонент дерева передаёт только имя, путь, тип записи и состояние папки. SVG отображаются через CSS mask: один файл можно использовать с любым цветом.

Тема: [`public/file-icons/theme.json`](../public/file-icons/theme.json). Встроенная палитра использует пастельные цвета Catppuccin Mocha; SVG взяты из уже установленных Lucide и Simple Icons. Это собственная тема Projector, без зависимости от расширения VSCode.

При открытии дерева тема загружается с диска через `/file-icons/theme.json`, один раз на приложение. После редактирования обновите страницу. В собранном приложении редактируйте `dist/file-icons/theme.json` и добавляйте SVG в `dist/file-icons/icons/`: пересборка не нужна. При ошибке конфигурации остаётся последняя корректная тема (на первом запуске — встроенная), а дерево показывает уведомление. `reloadFileIconTheme()` позволяет перечитать тему программно, в том числе после исправления ошибки.

## Добавить тип файла

Для существующей иконки достаточно добавить расширение в подходящее правило или добавить правило в `rules`:

```json
{
  "id": "file-my-format",
  "kind": "file",
  "extensions": ["myfmt", "myfmt.json"],
  "icon": "json"
}
```

Для новой иконки положите SVG с `viewBox` в `public/file-icons/icons/my-format.svg` и добавьте запись в `icons`:

```json
"my-format": {
  "src": "/file-icons/icons/my-format.svg",
  "color": "mauve"
}
```

Укажите `"icon": "my-format"` в правиле. Цвет — ключ из `palette` или `#rrggbb`. Иконка должна быть монохромной с непрозрачными контурами: CSS mask использует альфа-канал. Разрешены локальные SVG внутри `/file-icons/`; скрипты и внешние URL в теме не поддерживаются.

## Правила и приоритет

Исполняемые файлы (любой бит `+x`, маска `0o111`) получают иконку `executable` перед правилами имён и расширений. Права читает сервер; правило действует в файловом дереве и дереве Git-изменений по текущему рабочему файлу. После `chmod` обновите обзор. Правило настраивается в теме: `{ "id": "file-executable", "kind": "file", "executable": true, "icon": "executable" }`. Если добавить имена или расширения, они ограничат выборку исполняемых файлов. Для директорий это условие не используется.

Правила проверяются сверху вниз; **первое совпадение побеждает**. Поэтому специфичные имена, пути и составные расширения размещайте перед общими расширениями. Это позволяет переопределить любую встроенную ассоциацию.

| Поле            | Значение                                                                                  |
| --------------- | ----------------------------------------------------------------------------------------- |
| `id`            | Уникальное имя правила, для диагностики                                                   |
| `kind`          | `file` или `directory`                                                                    |
| `names`         | Точные имена, включая dotfiles: `package.json`, `.git`                                    |
| `extensions`    | Суффиксы файлов: `ts`, `d.ts`, `tar.gz`; начальная точка необязательна                    |
| `patterns`      | Glob по имени: `*.test.*`, `Dockerfile.*`                                                 |
| `paths`         | Glob по пути относительно проекта: `**/schema/*.json`                                     |
| `caseSensitive` | По умолчанию `false`; `true` включает учёт регистра                                       |
| `executable`    | Для файлов: наличие любого бита исполнения; применяется вместе с условиями имени или пути |
| `icon`          | Ключ из `icons`                                                                           |
| `expandedIcon`  | Необязательный значок открытой папки                                                      |

Внутри правила списки имён, расширений и путей объединяются через **ИЛИ**; `kind` и `executable` ограничивают тип и права записи независимо от этих списков. Нужно хотя бы одно поле сопоставления или `executable`. Для сочетания условий имени и пути задайте более точный `paths`.

В glob `*` и `?` не пересекают `/`, `**` пересекает папки, `**/` допускает ноль папок. Остальные символы буквальные, включая квадратные скобки. Brace expansion и regex не поддерживаются. Пути нормализуются к `/`.

Папки отображаются составной иконкой: `defaults.directory` или `defaults.expandedDirectory` задаёт основу, а `icon` из правила — небольшой цветной значок в правом нижнем углу. Значок сохраняется при раскрытии; `expandedIcon` позволяет заменить его в открытом состоянии. Цвет папки соответствует категории значка. Папки без совпавшего правила отображаются без значка, с цветом основы из темы. `defaults.file` задаёт иконку неизвестного типа файла.

## Проверка

[`theme.schema.json`](../public/file-icons/theme.schema.json) подключена через `$schema` для подсказок редактора. Runtime дополнительно проверяет ссылки на иконки/цвета, уникальность правил и структуру всей темы до её применения.

`vp run test:file-icons` проверяет приоритеты, пользовательские правила, glob, регистр, открытые папки, ошибки конфигурации и наличие всех встроенных SVG. Тест входит в `vp run test`.

Источники и лицензии SVG: [`public/file-icons/NOTICE.md`](../public/file-icons/NOTICE.md).
