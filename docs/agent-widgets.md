# Компоненты в ответах агента

Ответ штатного ассистента может содержать Vue-компоненты прямо в markdown: показатели, графики, колонки, вкладки, формы выбора. Агент пишет блок с новой строки (`<Stat label="…" value="…" />`), клиент рисует его настоящим компонентом.

## Где что лежит

Виджеты — масштабируемая сущность, поэтому они регистрируются через сквозной модуль (контейнер) в `core` и `src`, по образцу `agents-integration` ([архитектура](architecture.md)):

| Место                                         | Что                                                                                                                                           |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `core/modules/widget-catalog`                 | Контракт `WidgetDefinition` и каталог: из определений собирает инструкцию агенту (`guide()`) и справку по компоненту (`describe(name)`)       |
| `core/modules/agent-widgets/<имя>/index.ts`   | Определение виджета: имя, группа, описание, свойства с типами, `v-model`, примечания, пример. Без Vue                                         |
| `src/modules/agent-widgets/<имя>/`            | Реализация: `ui/<Имя>.vue` и `index.ts`, который отдаёт `{ definition, component }`. Общее ядро контейнера (`_/`) — контексты формы и вкладок |
| `src/modules/widget-runtime`                  | Реестр (`registerWidget`), разбор сообщения, автозакрытие, компиляция, хост компонента, общий контекст ответа, мост `reply`                   |
| `src/app/widgets.ts`, `server/app/widgets.ts` | Единственные места, где виджеты названы: клиент регистрирует определение с компонентом, сервер — определение для промпта ассистента           |

Чат не знает ни одного виджета, а промпт ассистента не содержит их описаний: `buildSystemPrompt(widgetCatalog.guide())` берёт текст из зарегистрированных определений, поэтому он не расходится с тем, что клиент умеет рисовать. Тест сверяет определения, свойства компонентов (`defineProps`) и оба списка регистрации.

### Как добавить виджет

1. `core/modules/agent-widgets/<имя>/index.ts`: `defineWidget({ name, group, summary, props, model?, notes?, example })`. Описание — это то, что прочитает агент: когда виджет нужен, что значит каждое свойство, какие у него неочевидные правила.
2. `src/modules/agent-widgets/<имя>/ui/<Имя>.vue` и `index.ts` с `WidgetEntry`.
3. Добавьте виджет в `src/app/widgets.ts` и `server/app/widgets.ts`.
4. `vp test run tests/agent-widgets.test.mjs`: тест проверит, что свойства определения совпадают со свойствами компонента.

## Как рендерится

- **Разбор** (`split.ts`). Блок — строка, начинающаяся с `<PascalCase`, чьё имя есть в реестре, вне кода. Всё остальное — markdown (`html: false`, DOMPurify). `<script>` между блоками — отдельная часть; внутри блока — часть блока.
- **Прогрессивность** (`autoclose.ts`). Пока блок пишется, недописанное отбрасывается (тег, который ещё не закрыт, открытое `{{`, комментарий, `<script>`), а каждый открытый элемент закрывается. Получается валидный шаблон, который растёт элемент за элементом.
- **Без пересоздания** (`host.ts`, `ui/AgentWidget.vue`). Виджет монтируется одним компонентом на всю жизнь. Состояние скрипта создаётся один раз, меняется только функция рендера (не чаще раза за кадр; одинаковый текст шаблона компилируется один раз). Поэтому DOM, введённый текст, ползунок и вкладка переживают каждый чанк. Если новый текст не продолжает прежний, хост создаётся заново.
- **Почему это работает.** Скомпилированный шаблон помечает слоты стабильными и строит блоки с перечнем динамических потомков; Vue верит этому и не обновляет то, что «не менялось». Для одного шаблона это верно, для подмены шаблонов нет. Рендер идёт без отслеживания блоков (`setBlockTracking`), а флаг стабильных слотов заменён на динамический (`compile.ts`), и Vue делает полный diff.
- **Терпимость.** Пока сообщение не закончилось, имя, которого ещё нет, читается как пустое, ошибка дочернего компонента гасится, а виджет `inert` (недописанную форму нельзя отправить). Когда ответ завершён, неизвестное имя или исключение показываются как ошибка с исходником.
- **Компилятор.** `@vue/compiler-dom` загружается лениво при первом блоке.

## Скрипты и данные

- `<script>` внутри блока видит только этот блок. Между блоками `<script>` один на весь ответ: его значения видны во всех блоках (ползунок в одном управляет графиком в другом), порядок не важен. В скрипте доступны `ref`, `reactive`, `computed`, `watch`, `onMounted`, `reply`; он заканчивается `return { … }`. Исполнение кода не ограничено.
- Блок, которому не хватило имени из скрипта, пришедшего позже, пробует снова после выполнения скрипта.

## Ответ агенту

`reply(данные, "подпись")` отправляет в чат сообщение пользователя: подпись и данные в JSON. Отправка только по клику: `reply` проверяет `navigator.userActivation`, поэтому `onMounted`, `watch` и программный `.click()` в скрипте ничего не отправят. `<Form>` с полями `name` и кнопкой `<Button submit>` делает то же без скрипта: после отправки форма блокируется.

## Проверка

`tests/agent-widgets.test.mjs` (разбор, автозакрытие на каждом префиксе, каталог, сверка наборов) и `tests/agent-widgets-browser.test.mjs` (реальный Chromium: стриминг без пересоздания узлов, отсутствие ошибок на каждом шаге, одно выполнение скрипта, формы, лейауты, общий контекст). Живая проверка с настоящим агентом отдельно: сценарий и ограничения — в истории коммитов.
