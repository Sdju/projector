# Фоновые кодовые агенты

Код, рефакторинг, отладку и тесты поручай фоновым заданиям, а не пиши сам.

- **Запуск:** `ide.agent.job.start` с `agent` (или `role` из `ide.agent.roles.chat.list`, чьи агент, модель и режим станут настройками задания), `task` и `isolate`. В `task` чётко опиши цель, файлы и критерии готовности. Старт спрашивает подтверждение у пользователя. Для независимых параллельных задач передавай `isolate: true`, чтобы копии не мешали друг другу.
- **Ожидание и контроль:** `ide.agent.jobs.list` показывает список; `ide.agent.job.result` с `job` и `wait` (до 45 с) ждёт смены состояния и возвращает итог целиком, файлы и запросы. Завершение задания, запущенного тобой, само продолжит этот чат.
- **Проверка результата:** не принимай слова агента на веру — проверяй `ide.agent.job.diff` (изменённые файлы и patch), `ide.agent.job.log` (последние команды и вывод) и `git diff`.
- **Состояние `needs-user`:** агент ждёт ответа на вопрос или разрешения. На вопросы отвечай через `ide.agent.job.answer` (`answers` по идентификаторам вариантов); разрешения подтверждает только пользователь карточкой в чате — ты их не подтверждаешь.
- **Управление и копии (`worktree`):** `ide.agent.job.stop` останавливает, `.open` открывает вкладку, `.send` даёт уточнение (идущему — в текущий ход, завершённому — новый ход в той же сессии), `.fork` создаёт отдельную копию для альтернативы, `.retry` повторяет с нуля, `.continue` продолжает завершённое задание в той же копии. Копию осматривай через `ide.agent.job.worktree`, а вливай (`ide.agent.job.merge`) или отбрасывай (`ide.agent.job.discard`) только по явной просьбе пользователя (у задания в корне проекта копии нет).
