# Проектирование ролей агентов

Используй этот навык, когда пользователь просит создать, изменить или объяснить роль: пресет агента для нового чата, фоновых заданий или `task`. Сначала прочитай `docs/agent-roles.md` — там актуальный контракт. Роль не создаёт навыки и MCP-серверы: она выбирает из уже существующих.

## 1. Выбери вид роли

- **Служебная** (`doctor`, `lens`, `judge`) — внутренний вызов Projector с фиксированным промптом, без инструментов и истории. У неё настраивается только модель; промпт, навыки и MCP менять нельзя.
- **Chat-роль** — пресет для нового чата, фонового задания и `task`. Хранит агента, `selection` контролов, режим разрешений, промпт, шаблон, навыки и MCP.
- **Роль проекта** — та же chat-роль из `.projector/roles.json`; действует только в своём проекте и только после доверия к текущему хешу файла.

Перед созданием уточни цель, агента и где роль должна работать. Не предлагай роль вместо фонового задания, если пользователю нужен один запуск.

## 2. Заполни роль

- **`name` и `description`** — коротко и по делу: название видно в меню «+», описание объясняет, когда роль выбирать.
- **`agent`** — установленный бэкенд. `projector` умеет `task` и hosted-задания; внешний агент — только свои возможности.
- **`selection`** — карта `control id → value` (провайдер, модель, усилие, режим). Пустое значение наследует умолчание агента. Не угадывай идентификаторы: смотри `ide.agent.roles.list` и контролы агента в настройках.
- **`permissionMode`** — `default`, `auto` или `bypassPermissions`. `bypassPermissions` включай только по явной просьбе: роль обходит подтверждения.
- **`isolate`** — для ролей, которые запускают кодовые фоновые задания: работа идёт в отдельной git-копии проекта.
- **`skills` и `mcp`** — отсутствие поля означает «все доступные», `[]` — «никакие», список — только эти имена. Не добавляй в роль несуществующий навык или сервер: Projector перечислит его внешнему агенту как недоступный.
- **`prompt`** — до 8000 символов. Без шаблона он добавляется к системному промпту агента, не заменяя его.

Подробные процедуры не копируй в промпт роли: вынеси их в навык и выбери его полем `skills`. В промпте оставь цель, границы, критерии готовности и порядок работы.

## 3. Реши, нужен ли шаблон контекста

Включай `template: true`, если роль должна сама собирать системный промпт из контекста. Подстановки: `{system}`, `{features}`, `{widgets}`, `{project}`, `{memory}`, `{skills}`, `{mcp}`, `{role}`, `{summary}`.

- У Projector шаблон **заменяет** системный промпт. Без `{system}` базовые правила, инструменты и границы безопасности не попадут в роль. Это допустимо только осознанно.
- `{features}` уже содержит инструкции виджетов; не ставь одновременно `{widgets}` — будет дубль.
- `{project}` даёт путь и `AGENTS.md` / `CLAUDE.md`, `{memory}` — заметки, `{summary}` — сжатую историю, `{mcp}` — подключённые серверы.
- У внешнего агента доступны только `{role}`, `{project}` (путь) и `{skills}`. Остальные подстановки пусты: свой системный промпт и возможности агент получает отдельно. Для внешней роли чаще достаточно обычного промпта.
- Неизвестные `{…}` остаются в тексте; не используй самодельные подстановки.

Пример безопасного шаблона ревьюера Projector:

```text
{system}

Ты — ревьюер проекта. Сначала читай diff, затем проверяй края и тесты.

{project}

{skills}
```

## 4. Меняй роль командами

- Открыть список доступных chat-ролей: `ide.agent.roles.chat.list`.
- Открыть новый чат с ролью: `ide.agent.role.open` с `role`.
- Открыть редактор нужной роли: `ide.agent.role.edit` с `role` — он перейдёт в глобальные настройки или в «Роли проекта».
- Глобальные настройки (раздел `agentRoles`): `ide.agent.roles.list`, `ide.agent.roles.create`, `ide.agent.roles.save`, `ide.agent.roles.delete`.
- `ide.agent.roles.save` принимает `role`, `name`, `agent`, `description`, `selection`, `prompt`, `template`, `skills`, `mcp`. Не переданные поля сохраняются; пустой массив `skills`/`mcp` выключает набор.
- Проектные роли (раздел `agentProjectRoles`): `ide.agent.projectRoles.list`, `.create`, `.save`, `.delete`, `.trust`.
- Не правь `agent/roles.json` и `.projector/roles.json` вручную, если доступна команда. Проектный файл — часть репозитория: после любой правки доверие к нему отозвано. Проверь diff и только потом вызывай `ide.agent.projectRoles.trust` с `trusted: true`.

## 5. Помни про снимок

Роль применяется один раз при открытии чата и записывается в историю как `AgentRoleSnapshot`. Правка роли не меняет уже начатые чаты и задания; удаление роли их не ломает. Фоновое задание сохраняет свой снимок для `retry` и `fork`. `task` принимает chat-роль Projector, а без неё наследует роль текущего чата; внешние и служебные роли для `task` не подходят.

## 6. Проверь результат

- Убедись, что роль появилась в `ide.agent.roles.chat.list` или `ide.agent.projectRoles.list` и имеет ожидаемые поля.
- Открой новый чат через `ide.agent.role.open`; правка уже открытого чата не должна менять его поведение.
- Для проектной роли после сохранения проверь состояние доверия: без него роли не видны в меню, заданиях и `task`.
- Для шаблона проверь, что в промпте есть нужные разделы: минимум `{system}` для Projector, если не задумано полное замещение.
- Точечные проверки: `vp test run packages/server/tests/agent-roles.test.mjs` и `packages/server/tests/agent-project-roles.test.mjs`.
