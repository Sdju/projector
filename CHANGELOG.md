# Changelog

## Unreleased

### Интерфейс

- Появились цветовые схемы интерфейса: тёмная, светлая и «как в системе». Выбор хранится в `appearance.json` и меняется в разделе «Интерфейс»; `GET/PUT /api/appearance` отдаёт и сохраняет его. Перед первым кадром `GET /api/appearance/bootstrap.js` читает файл на каждый запрос и выставляет `data-appearance`/`data-theme`, `color-scheme` и `theme-color` обновляются при смене и при изменении системной темы; пересборка и перезапуск не нужны. Редактор кода, Markdown и терминал пока сохраняют собственное оформление и перейдут на схему отдельно.
- Цвета интерфейса больше не зависят от яркости темы: `--hover` и `--active` выводятся из `--text`, а мёртвые токены `--panel`, `--radius`, `--surface` и `--shadow-pop` заменены существующими. Тултип графика снова в цветах темы, ошибка в избранных папках использует `--err`, а просмотр SVG берёт цвет по умолчанию из `--text-2`.

### Агент

- Очередь сообщений агенту хранится с историей чата: перезагрузка страницы и синхронизация с другой вкладкой возвращают сообщения в прежнем порядке. Флаг «Передаётся агенту» не сохраняется — незавершённая передача начинается заново.
- `/compact` у ACP-агентов больше не завершается пустым ответом: чат показывает «Сжимаю историю», а сводка сжатия приходит в `compaction_update` и остаётся в истории. Старые сборки OpenCode с `session_info_update._meta` поддержаны, ошибка или отмена сжатия тоже видны; автодополнение команд обновляется, когда список агента приходит во время набора.
- Chat-роли получили собственный промпт, набор навыков и MCP-серверов. Промпт добавляется к системному промпту Projector, Claude Code или первому сообщению ACP-агента; `skills` и `mcp` отсутствуют — «все доступные», пустой массив — «ничего», список — только выбранные. Всё входит в снимок роли, поэтому чаты, ветки, задания и `task` сохраняют поведение после правки роли. Глобальные и проектные роли редактируются одинаково; проектные по-прежнему требуют доверия к `.projector/roles.json`.
- Проект может объявить свои виджеты в `.projector/widgets.json`: Vue-шаблон из встроенных компонентов и HTML, свойства, JSON-данные проекта, CSS, форма ответа и необязательный `script` отдельным полем. Скрипт получает `ref`, `computed`, `watch`, `props`, `data` и `reply`, выполняется после загрузки данных и только после доверия файлу по хешу; `<script>` внутри шаблона и импорты запрещены. Виджеты добавляются к промпту и `describe_widget` только в чатах своего проекта, а клиент рисует их из отдельного реестра по `projectId`; правка файла отзывает доверие.
- Поля формы сведены в один `Field` с `type`: text, textarea, number, slider, select, radio, checks, switch, date, time и segmented; `required` блокирует отправку с ошибкой у поля. `Input`, `Checks` и `Slider` остались только для старых ответов и скрыты из постоянной справки; для больших определений появился компактный `guide`, полное описание по-прежнему отдаёт `describe_widget`. Справка сократилась примерно с 11,6 до 8,8 тыс. символов, её бюджет проверяется тестом. Добавлены Chromium-тест `Field` и eval-сценарии на реальном OpenCode через ACP (`pnpm eval:widgets:opencode`), проверяющие форму через `Field` без legacy-полей.

### Установка

- Публичные npm-пакеты переименованы в `@projector-ai/ide` и `@projector-ai/native`; внутренние workspace-пакеты остаются `@projector/*` и не публикуются. В манифестах появились `publishConfig`, `files`, README и `projector-install-desktop`; `vp run verify:distribution` проверяет поставку перед публикацией.
- Добавлен `.github/workflows/publish.yml` для публикации из GitHub Release через OIDC trusted publishing, без `NPM_TOKEN`. Первый выпуск каждого имени до настройки trusted publisher выполняется вручную; порядок описан в `docs/distribution.md`.

## 0.10.0

Выпуск вводит роли агентов — глобальные, служебные и проектные — и read-only субагента `task`, делает ответы надёжнее за счёт Answer Doctor и точных ссылок, а выделение из чата, редактора и терминала теперь попадает в поле ввода. Код разложен по пакетам pnpm workspace, IDE и GTK-палитра разделены для установки, а проекты получили раздел Releases.

### Проверки

- Проверки снова зелёные на macOS и Windows: `spawn-helper` node-pty получает право на запуск при установке (в checkout и в `@projector/ide`), Windows-тесты не зависят от установленных приложений и сравнивают пути через JSON, ротация `server.log` не переименовывает открытый файл, а историю чатов проверяет отдельный процесс.

- Тестовый прогон ускорен примерно вдвое (локально 140 → 65 с): быстрые чистые кейсы собраны в `tests/units-a.test.mjs`/`tests/units-b.test.mjs` и делят один граф модулей, тестовые Vite-серверы не запускают FEOD, браузерные тесты работают конкурентно, `environment-runtime` по умолчанию делает два поколения, а тест Kimi не ждёт десять секунд. Точечный прогон больше не тратит десять секунд на закрытие сервера.

### Агент

- Встроенные служебные роли Доктор, Lens и Судья получили собственную модель: раздел «Роли агентов» выбирает провайдера и модель для каждого внутреннего вызова, а без выбора роль наследует модель чата. Настройка хранится в `agent/roles.json` и не меняет промпты, лимиты, отсутствие инструментов и политику Судьи. API — `GET /api/agent/roles`, `PUT /api/agent/roles/:id`, `POST /api/agent/roles/:id/reset`, команды — `ide.agent.roles.list|set|reset`.
- Появились chat-роли: пресет агента и его модели/усилия/режима открывается из меню «+» командой `ide.agent.role.open` и сохраняется в историю чата снимком. Правка или удаление роли не меняет уже начатые чаты; смена настройки внутри ролевого чата не переписывает `agentDefaults`. Роли создаются, редактируются и удаляются в разделе «Роли агентов»; ветки и недавние чаты сохраняют снимок.
- Фоновое задание можно запустить с chat-ролью: `ide.agent.job.start` и `POST /api/agent/jobs` принимают `role`, сервер берёт агента, `selection` и `permissionMode` роли, а `job.role` хранит снимок для `retry` и `fork`. Служебная роль заданием не запускается; несовпадение роли и агента отклоняется.
- У штатного агента появился `task` — read-only субагент в отдельном контексте: `read_file`, `list_directory`, `search`, 6 шагов и 90 секунд, без записи и разрешений. Он принимает chat-роль Projector, иначе наследует роль текущего чата, и показывается в «Работе» как обычная задача.
- Роли проекта: `.projector/roles.json` хранит chat-роли рядом с кодом, но они не действуют, пока пользователь не доверит текущий файл. Настраиваются на странице настроек проекта, в разделе «Роли проекта». Доверие привязано к хешу и отзывается при любой правке; файл или `.projector` с симлинком наружу не читается. Проектные роли перекрывают глобальные с тем же id, работают в меню «+», заданиях и `task`.
- Ссылки в ответах агента стали предсказуемыми: веб-адреса открываются в новой вкладке браузера, а путь к файлу — во вкладке редактора с переходом на строку (`:12`, `:12-34`, `#L12-L34`). Контекстное меню ссылки копирует адрес, относительный или абсолютный путь; файл вне проекта открывается как внешний.
- Выделенный текст в чате цитируется кнопкой «Цитировать» у выделения: он попадает в поле ввода этого же чата как Markdown-цитата (`>` по строке на каждую строку выделения) без отправки. Выделение вне ленты сообщений и пустое выделение кнопку не показывают.
- Answer Doctor автоматически чинит завершённые ответы со сломанной Vue-разметкой, незакрытыми виджетами и Markdown внутри виджетов: до трёх проверенных попыток через Projector-модель, после чего исправленный текст сохраняется в истории и остаётся после перезагрузки. Обычный Markdown вне виджетов не изменяется.
- Неудачный ответ сохраняет причину в ходе и предлагает «Повторить» и в самом чате, и в баннере ошибки; после перезагрузки кнопка остаётся. OpenCode-повторы провайдера передаются в статус чата, а ошибки перегрузки без HTTP-статуса повторяются автоматически.
- Настройки адаптеров собраны в разделе «Агенты»: у каждого кодового агента своя страница с включением, режимом сессий и возможностями, как у провайдеров внешних API. Прежние разделы «Интеграции агентов», «Сессии агентов» и «Возможности агентов» заменены одним.
- Вкладка чата называется по имени сессии, которое агент даёт по ходу первого хода, а до него — по первому сообщению; явный заголовок (ветка, чат из истории) не перезаписывается. У агента Projector нативной сессии нет, поэтому его вкладка берёт имя из первого сообщения.
- Имя нативной сессии, которое агент взял из первого сообщения, очищается от внедрённого текста возможностей Projector: в истории и вкладках остаются слова пользователя.
- Чтение навыка и картинки в чате стало понятным до раскрытия блока: у `SKILL.md` строка показывает имя навыка, у `Skill` и `use_skill` — загружаемый навык прямо в заголовке строки, в том числе когда агент передаёт его полем `id`. Прочитанное изображение показывается картинкой и открывается в общем просмотре с масштабом, а результат чтения Kimi очищается от номеров строк (`N\t…`) и в новых, и в уже сохранённых чатах.
- Фоновая команда Codex больше не остаётся «Без итога»: по завершении задача получает строку из последнего вывода или кода выхода (`Код выхода 1`, `Завершено без вывода`), а если агент действительно ничего не сообщил, вкладка задачи говорит «Агент не сообщил итог».

### Структура

- IDE и GTK-палитра разделены для установки: `vp run build:distribution` собирает JavaScript-артефакты `@projector/ide` и `@projector/native`. IDE не устанавливает GTK, vio или Vite; без дополнения открывает браузер, а трей и хоткей работают через OS-резидент. В Linux палитра создаётся только при первом открытии. Подробнее: `docs/distribution.md`.

- Код разложен по пакетам pnpm workspace: `@projector/client`, `@projector/server`, `@projector/native`, `@projector/core`, `@projector/cli` с манифестами и зависимостями через `workspace:*`. Межпакетные импорты идут по имени, FEOD проверяет корни через `layerAliases`, tsconfig, Vite, bin-скрипты и тесты переведены на новые пути. Оболочка приложения (`index.html`, `public`, `resources`, `dist`, `bin`, тесты) остаётся в корне. Версии внешних зависимостей вынесены в `catalog` (`pnpm-workspace.yaml`), манифесты ссылаются на них через `catalog:`.

### Палитра

- Избранные папки показывают ещё не открытые прямые дочерние каталоги: они ищутся по тексту и по явному `/`, а пустой обзор избранные папки не сканирует. Открытие регистрирует проект. `new/имя` для уже существующей папки открывает её, а не оставляет пустые действия.

### Workspace

- Проекты в переключателе проекта стали ссылками: Ctrl/⌘-клик, Shift-клик или средняя кнопка открывают проект в новой вкладке, обычный клик по-прежнему открывает его в текущей. Ссылкой стали и найденные репозитории GitHub/GitLab, и ещё не зарегистрированные папки на диске.

- В GitHub- и GitLab-проектах появился раздел Releases: список релизов, Markdown-описание, вложенные файлы, внешние ссылки и source archives. Ассеты скачиваются через Projector потоком, токен не уходит на подписанный URL; у GitHub показывается `latest`, у GitLab — `upcoming`. Работает и в `gh:/…`/`gl:/…`, и в локальных проектах с хостингом в `origin`.

- Выделенные строки редактора можно добавить в чат агента: `ide.editor.selection.toChat`, `Mod+Shift+L` и кнопка «В чат» у выделения вставляют чип `@path:12-34` в поле ввода видимого или последнего использованного чата, а без открытого чата открывают самый свежий сохранённый. Без выделения берётся строка под курсором; сообщение не отправляется, а клик по чипу открывает файл на этих строках.

- Кнопка «В чат» теперь есть у выделения в визуальном редакторе Markdown и в терминале: выбранный текст с подписью источника попадает в поле ввода чата без отправки. В Markdown действие встроено в нативную панель форматирования, в терминале кнопка появляется рядом с курсором после окончания выделения, а не во время протяжки. Визуальный редактор использует `ide.editor.selection.toChat` с аргументом `text`, терминал — `ide.terminal.selection.toChat`; чат выбирается так же, как для строк файла.

- В меню дерева файлов появилась команда `ide.fileTree.entry.reveal` — «Показать в проводнике»: файл или папка выделяются в системном файловом менеджере, а без записи открывается корень проекта. Команда доступна только для локального проекта при работе на компьютере с сервером; в снимках и удалённых источниках она скрыта.

### Лимиты

- Kimi Code: 15-минутный OAuth-токен обновляется по `refresh_token` в том же слоте, который указан в `config.toml`, под локом CLI и с атомарной записью; при ротации CLI побеждает его пара. Индикатор выбирает первое доступное окно и пропускает отсутствующие, поэтому новые тарифы без недельного лимита больше не показывают «—». Добавлены `limit_month_code`, legacy `usage`/`limits[]` и числовые строки `used_ratio`.

### Сервер

- `server.log` ротируется: активный файл до 10 МиБ, рядом хранятся до пяти архивов `server.log.1…5`. Перезапуск начинает новый файл, а работающий сервер проверяет размер каждые 15 секунд и продолжает писать в новый файл без потери строк. Размеры меняются через `PROJECTOR_LOG_MAX_BYTES` и `PROJECTOR_LOG_MAX_FILES`; старые сегменты удаляются по кольцу.

- Фавикон вкладки и логотип проекта GitHub/GitLab берутся из самого репозитория: аватар проекта или владельца с хостинга, а если его нет — иконка из `index.html` или привычных файлов (`public/favicon.svg`, `src/assets/logo.svg` и т.п.) на выбранной ветке. Логотип хостинга больше не подставляется; без доступного логотипа остаётся буквенная иконка проекта.

## 0.9.0

Выпуск делает Projector полноценным readonly-клиентом GitLab и вводит общие снимки файлов: рабочая копия, коммит и сравнение открываются одним деревом с поиском, diff и вложениями. Фоновые задания стало можно проверять, продолжать и вливать, подтверждения оценивает Projector Judge, а ответы агента получили картинки, умные формы и Lens.

### Агент

- Поток ответов больше не размножает фрагменты после HMR: подключение событий страницы сохраняется между загрузками runner, обновляется только его обработчик. Исправление общее для всех агентов, SharedWorker и прямого SSE.

- ACP-пикер: boolean и `model_config` видны как флаги (Fast, effort) над вводом, группы опций сохраняют заголовок, статус хода показывает имя модели. Кишки конкретного агента остаются в его адаптере: Cursor просит parameterized-пикер и `subagents` в `clientCapabilities`, раскладывает старый id вида `model[k=v]` и отвечает на `create_plan` / `update_todos` / `task` / `generate_image`.
- История ACP: пробная сессия всегда пробует `session/delete` и `session/close`; `session/load` создаёт новую сессию только если старой нет; `deleteSessions` в UI — только после handshake, если агент обещал удаление. Нативная сессия с тем же заголовком, что уже продолжена чатом Projector, не дублирует строку.

- Возможности Projector, внедрённые в первое сообщение внешнего агента, больше не выглядят частью сообщения пользователя: конец блока помечен, чат показывает текст пользователя, а инструкции — в сворачиваемом «Возможности Projector»; сессии до маркера распознаются, пока набор возможностей совпадает.

- Рассуждения и вызовы инструментов собраны в сворачиваемый блок «Работа»: закрыт по умолчанию, в заголовке показан только текущий шаг, а содержимое монтируется при открытии и прокручивается внутри блока.
- Картинки в ответах: `![alt](путь)` показывает изображение. Путь проекта идёт через `asset`, абсолютный файл (`/tmp/...`, `file://`, `C:\...`) — через `external-asset`, внешний URL и `data:` — напрямую; опасные схемы не становятся картинками, а битая загрузка заменяется alt-ссылкой. Клик открывает модальный просмотр в стиле вкладки изображения: масштаб, панорамирование, вписать/100% и фон, по умолчанию прозрачный; закрывают кнопка, Escape и клик по backdrop; на телефоне просмотр раскрывается на весь экран. Виджет `<Image>` принимает те же пути (общий модуль `chat-images`), открывает тот же просмотр с масштабом и при сбое загрузки оставляет ту же alt-ссылку, поэтому скриншоты из `/tmp` работают и внутри карточек и вкладок. Чип-вложение с картинкой открывает этот же просмотр вместо новой вкладки браузера.
- Умная форма: ответ может закончиться блоком `<IntelligentForm>` с полями управления, и этот блок занимает место поля ввода. В композере форма отправляется общей кнопкой поля ввода, без второй кнопки; в сообщении и readonly-снимке остаётся собственная кнопка. Активная форма не дублируется в ответе; пользователь заполняет её на месте текстового поля, а его сообщение в истории показывает ту же форму с выбранными значениями только для чтения. Карандаш снимает блокировку для нового ответа. Кнопка-иконка режима возвращает обычное поле, команды `ide.agent.form.show/text` делают то же. Снимок формы хранится в истории; старая разметка `<Form>` с `<Button submit>` продолжает работать.
- Отправленная форма не остаётся второй активной копией в ответе: блок скрывается, а выбранные значения показывает только readonly-снимок в сообщении пользователя. Это переживает перезагрузку, повтор ответа и правку снимка.
- Evals: `intelligent-form-project`, `intelligent-form-release` и `intelligent-form-docker` проверяют выбор `IntelligentForm` в сложных настройках; на `deepseek-flash` — 9/9 ответов с формой.
- Form Doctor: форма с ошибкой компилятора сначала чинится эвристиками (дубли атрибутов, незакрытые теги), затем до трёх раз переписывается Projector-моделью по истории и тексту ошибки. Каждый вариант проверяется Vue-компилятором; в композер попадает только валидный результат, иначе остаётся текстовое поле.
- Lens читает рассуждения агента, поэтому называет намерение, а не угадывает его по команде. Автообновление по таймеру пропускает шаг, если работа не сдвинулась, и не просит ту же подпись повторно. У сабагента появился свой Lens в строке задачи и в шапке его чата: подпись можно включить, не открывая задачу, или читать рядом с перепиской внутри неё.
- Lens не тратит запрос в первые секунды хода: пока нет рассуждения, текста или вызова, показывается «Агент обдумывает задачу…», а первая подпись запрашивается, когда рассуждение накопилось или сменился шаг. Самое свежее рассуждение передаётся модели отдельным блоком, поэтому в фазе размышлений Lens называет намерение, а не сообщает, что сообщений ещё нет; рост мысли не вызывает запрос на каждый токен.
- Projector Judge: карточка подтверждения показывает риск действия по шкале 1–5, короткое объяснение и эффект. Настройки «Судья Projector» задают показ оценки и автоматическое разрешение низкого риска; для чата они переопределяются в меню «Ещё». Автоматизация ограничена баллом 3, требует достаточной уверенности и никогда не срабатывает при ошибке Judge; решение оставляется строкой в блоке «Работа». Judge общий для Projector, Claude Code, ACP и фоновых заданий.
- Карточка подтверждения окрашивается по уровню риска, показывает крупный квадрат с оценкой, «Почему» и «Что изменится» отдельными строками. Для риска 4–5 кнопка «Всегда разрешать» скрыта. Команда в карточке ACP больше не повторяется трижды: инструмент берётся из `kind` (`bash`), а команда показывается один раз в тёмном превью.

### Делегирование

- Задания стали управляемыми: `ide.agent.job.diff` показывает файлы, `--stat` и patch, `ide.agent.job.log` — последние вызовы инструментов и их вывод, итог в `ide.agent.job.result` больше не обрезается. Штатный агент проверяет работу по diff и проверкам, а не по словам субагента.
- Разрешения заданий решает пользователь: ожидающий запрос показывается карточкой в чате Projector, ответ уходит прямо в задание, а `ide.agent.job.answer` отвечает только на вопросы. Модель больше не может подтвердить разрешение за пользователя.
- Задания видны в чате Projector в общей строке активности над полем ввода: задания, задачи, план и очередь сводятся в одну раскрываемую строку, а запросы разрешений и вопросов — в одну стопку карточек без наложений; завершение задания, запущенного этим чатом, продолжает разговор само (`origin` задания, отметка «Продолжение после задания»).
- Итог задания больше не сжимается в тонкую полоску: сетка вкладки задания и чата сабагента растягивает прокручиваемый блок результата по содержимому (до 240 px), поэтому текст читается.
- Завершённое задание не исчезает из чата: сводка показывает «завершено: N», а в раскрытом списке остаётся группа «Завершено» с временем и числом изменённых файлов. Заголовок вкладки и шапка берут имя сессии агента, пока оно не появилось — короткую первую фразу задания; полная постановка лежит в свёрнутом блоке «Задание», поэтому длинный префикс не отвлекает. Сообщение о завершении выглядит обычным сообщением пользователя и показывает имя, а не id; id остаётся в скрытом тексте хода для команд. Строка задачи в доке больше не показывает сырой markdown.
- Копия задания: `ide.agent.job.worktree/merge/discard` — осмотреть, влить и удалить; слияние и удаление только по просьбе пользователя.
- Идущее задание принимает уточнение (`ide.agent.job.send`); завершённое — новый ход в той же записи, копии и сессии, без создания второго задания. `retry` остаётся повтором с нуля, `fork` создаёт отдельную копию из текущего состояния работы.
- Потолок в 4 одновременных задания убран; `ide.agent.job.answer` принимает `answers` по идентификаторам вариантов.
- Evals: сценарий `delegation-checked` проверяет, что агент запускает задание и сверяет результат с diff.
- Документация: [фоновые задания и делегирование](docs/agent-jobs.md).

### Интеграции

- GitLab стал полноценным readonly-клиентом: `gl:/<instance>/<group>/<project>` открывает дерево, файлы, Markdown и изображения, карточку проекта, Issues, Merge requests, историю Git, коммиты и diff. Снимок привязан к коммиту, `?ref=` выбирает ветку, `?path=` открывает файл. Запись, Git-мутации, терминалы и агент недоступны — как у `gh:/`.
- Палитра `gl/` теперь открывает проект, а не только клонирует; клонирование осталось отдельным действием. Полная ссылка на проект ищется напрямую, а не через общий поиск GitLab; путь группы показывает её проекты, `gl/` — недавние. Строка пути показывает группы и проекты GitLab с подсказками, а команда `ide.gitlab.repository.open` открывает ссылку, `gl:/…`, `<instance>/<path>` или `group/project` настроенного инстанса.
- Локальный проект с GitLab в `origin` получает Issues, Merge requests, Pipelines и вкладку «О проекте»; файлы, Git, поиск и терминалы остаются локальными. Поддерживаются HTTPS, SSH и scp-подобные remote, self-hosted принимается только для настроенного инстанса.
- Pipelines GitLab: раздел в сайдбаре с фильтром по статусу, вкладка запуска с джобами по стадиям и вкладка джоба с readonly-логом до 2 MiB. Контракт общий для GitHub и GitLab: действия `pipelines`, `pipeline` и `job`; команды `ide.pipelines.*`, `ide.pipeline.*` и `ide.job.*`.
- Pipelines GitHub: те же раздел, вкладки и команды читают Actions workflow runs. Фильтр статуса переводится в `in_progress`/`failure`/`success`/`cancelled`, запуски и джобы показываются без стадий, лог до 2 MiB скачивается по подписанной ссылке без передачи токена хранилищу. Работает в `gh:/` и в локальном проекте с GitHub в `origin`.
- Merge requests GitLab: список показывает точку CI, число комментариев, конфликты и отдельный фильтр «влитые»; карточка — готовность к merge, раскрываемый ход pipeline по стадиям и изменённые файлы с inline-diff. Diff читает две стороны из `diff_refs` (для fork — head из `source_project_id`), дерево изменений открывается временной панелью в группе Merge requests, файлы — вкладкой base → head; бинарные и большие файлы, а также `changes_count: "1000+"` показываются явно. Команды `ide.mergeRequest.*`.
- GitLab-клонирование получило фоновые задачи с фазами и отменой, выбор папки и Docker-окружение; публичный `gitlab.com` клонируется без входа, self-hosted — с токеном. Контейнерный клон общий с GitHub, но токен передаётся только через временный `--env-file`.
- Вход в GitLab: OAuth Device Flow (GitLab 17.1+) с Client ID, PAT как запасной вариант. OAuth access token обновляется по refresh token за 60 секунд до истечения, параллельные запросы делят один refresh, после 401 — один повтор. Токен уходит только на настроенный инстанс, `gitlab.com` при self-hosted читается анонимно.
- Границы паритета: пока нет Snippets, Wiki и нескольких инстансов одновременно; реакции на комментариях GitLab не загружаются, чтобы не делать N+1. Подробности — [интеграции](docs/integrations.md), [архитектура](docs/architecture.md).

### Интерфейс

- Мобильные жесты: поверхности «Файлы / Редактор / Терминалы» листаются горизонтальным свайпом с сопротивлением у краёв, а нижние шторки-острова и выбор проекта закрываются свайпом вниз с уезжающим листом и гаснущим фоном. Свайпы уступают горизонтальной прокрутке, вертикальным спискам и полям ввода; короткий жест возвращает страницу или шторку на место. Общий распознаватель — `src/common/utilities/swipe-gesture.ts`.
- Шапка чата разгружена: заметными остались история, меню «Ещё» и новый чат. Возможности агента, Lens, вопрос в сторону, скачивание и изолированная копия собраны в меню «Ещё» с подписями; активные пункты отмечены, а строка действий больше не плавает поверх переписки, а занимает своё место над сообщениями.
- Git-изменения показывают статус фоном: зелёный у новых записей, красный у удалённых, изменённые остаются без подсветки; буквы `?`, `D`, `M` рядом с именем убраны.

### Рабочее пространство

- Иконки разделов боковой панели умеют группироваться: временные разделы стоят рядом с родительской иконкой в общей подложке и отделяются чертой. Первый такой раздел — «Файлы коммита @hash»: дерево на момент коммита в режиме только для чтения открывается кнопкой в обзоре коммита и пунктом контекстного меню (`ide.git.commit.openTree`); сверху панели показан источник снимка, файлы открываются без права записи, импорт и изменение дерева отключены. Второй — «Изменения !N» merge request: дерево изменённых файлов с поиском по пути, статусами и `+/-`, одиночные цепочки каталогов схлопываются как в GitLab, а длинные пути и имена усекаются по центру (`…`); строки используют общий `UiActionRow`; открывается кнопкой «Дерево» в карточке MR (`ide.mergeRequest.files.open`). На ПК раздел закрывается правым кликом по его иконке, на телефоне — отдельной кнопкой в шапке панели; обе используют `ide.workbench.section.close`.
- Снимок файлов стал общим понятием (`FileScope`): рабочая копия, коммит и сравнение задаются данными, а не набором флагов в каждом вызове. Дерево коммита теперь один раздел `tree` с параметром scope; так же открывается история GitHub и GitLab (чтение дерева и файлов по sha, кеш каталогов по снимку). Вкладка хранит scope, live-ключи сессии не изменились; права записи и наблюдения выводятся из вида снимка. Статусы изменений Git, коммитов и merge request сведены к `FileChange`, поэтому подсветка дерева и панель изменений MR используют один словарь. Сравнение локальных снимков открывается из обзора коммита (`ide.git.commit.openChanges`): панель `changes` показывает изменённые файлы, фильтр, схлопывание цепочек и `+/-`, а строки открывают read-only diff двух снимков. Сервер отдаёт `changes?from&to` и `compare-file?from&to&path&originalPath`; GitHub сравнивает через свой compare API, GitLab — через `repository/compare`. Временные разделы снимков и их read-only-вкладки переживают перезагрузку: scope хранится в сессии, раздел восстанавливается из параметров, а вкладка — только вместе со своим разделом. Вложения снимка читаются отдельно от рабочей копии: локальный `asset?rev`, GitHub `asset?commit` и GitLab `asset?sha`; Markdown коммита рендерится с картинками и ссылками того же снимка, растровые изображения и SVG открываются просмотрщиками, а HTML/архивы остаются только для live и получают явную подпись, если открыты из снимка. Поиск по снимку открывается из раздела файлов коммита и переходит по результатам в тот же снимок: локально через `git grep`, в GitLab через blob search с `ref`; GitHub поиск по коммиту не объявляет.

### Приложение

- Установка как PWA: манифест, иконки 192/512 и maskable, отдельное окно на localhost. Service worker включается только при режиме сервера prod и ничего не кеширует: навигация идёт в сеть, при недоступном сервере показывается страница «Projector не отвечает»; `/api`, терминалы и модули dev-сервера не перехватываются. В dev регистрация снимается, а оставшиеся кеши `projector-shell-*` удаляются, чтобы HMR не получал устаревший HTML.
- Полноэкранный режим: команда `ide.workbench.fullscreen.toggle`, кнопка в мобильной нижней панели и раздел настроек «Приложение». На iPhone экран освобождает только установка на домашний экран.
- Статика: `.webmanifest` отдаётся как `application/manifest+json`.
- Windows: ограничение прав только что записанного файла повторяется, если антивирус или индексатор на миг занял его, поэтому сохранение настроек интеграций не падает из-за `icacls`.

### Сборка и тесты

- `vp run check` проверяет типы до тестов и убирает повторный явный запуск FEOD-архитектуры; шаги architecture, types и build:app кэшируются, а `build` и `check` используют общий `build:prepare`. В `AGENTS.md` описан быстрый цикл: `vp test related`, точечные тесты и `vp check`, а полный gate — перед коммитом.
- Проверки стабильны на macOS и Windows: обновление сессий терминала переживает смену поколения API и рестарт конфига, тесты заданий дожидаются записи истории на диск, MSYS-pid не сверяется с Windows-процессами, сценарий перезагрузки API получает запас времени на медленных macOS-раннерах, а чтение файла копии не зависит от CRLF.

Форк доступен и во время ответа агента: кнопки не блокируются на время работы, а иконка в подвале ответа видна только при наведении.

Время вызова переживает переподключение к ответу.

Отвечает с любого origin (CORS), необязательный ключ доступа (Bearer). Выключен по умолчанию; включается в настройках («OpenAI API», команда `ide.openai.gateway.set`) или через `PUT /api/openai`. Подробнее — [usage](docs/usage.md#openai-совместимый-api).

- Слежение за файлами и папками делегировано провайдерам профиля workspace (`files.watch`), поэтому источники без локального сервера тоже могут сообщать об изменениях.
- Доступные действия проекта в веб- и GTK-палитре определяются одной функцией `resolveLauncherAction`.
- Всплывающие окна сессий используют общий фокус и жизненный цикл; настройки интеграций выполняют операции через общий слой и доступны как IDE-команды.
- Сценарий запуска проекта может задать папку внутри проекта, свой адрес и режим запуска; пустые значения берутся из проекта. Сервер проверяет их при сохранении, терминал стартует сценарий в его папке (только для запуска на этой машине). Сценарии — страницы раздела «Запуск» настроек с перетаскиванием порядка (Alt+стрелки с клавиатуры). Редактор и команды `ide.project.command.*` используют одни и те же проверки; команды принимают папку, адрес и режим и получили `move` и `duplicate`. Запуск, застрявший в «останавливается» без терминала, переходит в «простой», поэтому проект можно снова остановить и удалить.

### Платформы

- Windows и macOS работают через адаптеры ОС (`core/modules/os`, общий POSIX-код в `core/modules/os-posix`): на Windows — файлы только для владельца через ACL, завершение деревьев процессов через `taskkill`, значок в трее и глобальная горячая клавиша вместе с `vp dev`, запуск GTK-палитры из нативного окружения; на macOS — каталог приложений из `.app`, резидент в строке меню с глобальной горячей клавишей, Keychain для секретов и GTK-палитра при установленном GTK4 (иначе палитра на Chromium). Обе платформы проверяются в CI. Сервер, запущенный из сессии Claude Code, больше не передаёт её метки терминалам и агентам.

### Рабочее пространство

- Вкладка-«псевдобраузер» открывает веб-страницы и dev-серверы проекта через серверный прокси: каждый сайт получает свой origin вида `<host>.<tag>.<key>.proxy.localhost`, поэтому относительные ссылки, `fetch` и хранилище работают; ключ защищает прокси-хост, cookies лежат на сервере, адреса loopback и LAN отклоняются.
- Сервер следит за открытыми файлами и раскрытыми папками (`PUT workspace/watch`, события `file-changed`, `dir-changed`, `watch-error` по SSE страницы). Вкладки без правок обновляются сами, при несохранённых правках панель предлагает «загрузить с диска» или «оставить мои» (`ide.editor.file.reloadFromDisk`, `ide.editor.file.keepMine`), автосохранение до выбора приостановлено; списки раскрытых папок перечитываются.
- Файлы и папки из системы можно перетащить в выбранную папку дерева (по пути из файлового менеджера или загрузкой из браузера). Занятые имена не перезаписываются молча: один конфликт предлагает оставить оба, заменить (старое уходит в `.projector-trash`) или отменить, несколько — общий префикс. Команда `ide.fileTree.entry.import`.
- Избранные папки в лаунчере: проекты из них идут первыми, префикс `new/` создаёт проект в избранной папке.
- Вкладки: перетаскивание вкладки принимается и на полосе пустой группы; после кнопки новой сессии добавлен разделитель.

### Агент

- Чат агента: поле ввода с файловыми чипами и `@`-упоминаниями, подсказки слэш-команд, картинки в сообщениях, предпросмотр чипа при наведении и открытие по клику; кольцо заполнения контекста; ответ собирается из упорядоченных частей, вход инструмента показан читаемо, режим разрешений «авто».
- История чата хранится в SQLite (`agent/history.sqlite`): одна строка на ход, ветки — несколько строк с общим `parent`, сохраняются только изменённые строки; старые JSON-файлы импортируются один раз. Схема истории больше не отвергает чат из-за длины полей или числа вызовов, а ошибка сохранения показывается в чате.

- Вопросы агента (ACP elicitation) показываются карточкой поверх переписки над полем ввода и не сдвигают сообщения; можно выбрать вариант, несколько или написать свой.
- Ошибка в чате сворачивается до трёх строк и скрывается кнопкой; длинные имена вызовов обрезаются, а вывод команд Codex (`terminal_output_delta`) показывается как результат вместо «Ожидание результата…».
- Claude Code может работать в графическом чате через Agent SDK вместо терминала (переключатель TUI/GUI, по умолчанию терминал).
- Проверка архитектуры FEOD в `vp dev` больше не блокирует сервер: раньше `buildStart` вызывал `oxlint` через `spawnSync` без таймаута, и каждый перезапуск замораживал процесс, а нарушение (например, файл длиннее 400 строк) или падение `oxlint` останавливали сервер. Теперь проверка идёт асинхронно с таймаутом (`checkFeodAsync`), результат пишется в лог; `vp build`, `vp run architecture` и pre-commit по-прежнему блокируют.
- Ход Codex, OpenCode и Cursor переживает перезапуск сервера, закрытую вкладку и перезагрузку страницы. Процесс агента держит отдельный хост `cli/app/agent-host.mjs` (своя группа процессов, сокет в каталоге хода), он записывает весь обмен в `trace.log`; сервер подключается к нему как к обычному дочернему процессу (`server/modules/agent/hosted-process.ts`). После перезапуска чат повторяет запрос с `attach`, сервер заново проходит ход по журналу — отправленные ранее запросы повторно агенту не уходят, уже отвеченные запросы разрешений не показываются снова, — и дальше идёт живой поток; если хоста уже нет, ответ воспроизводится из файла. Закрытие страницы больше не останавливает агента: отменяет только «Стоп» (`POST /api/agent/cancel`), который убивает дерево процессов по сохранённой идентичности процесса, а не по pid. Хост сам завершает агента через 30 минут без подключённого сервера, а завершённые ходы, к которым не вернулись, удаляются через час (при старте сервера, при новом ходе и по таймеру), а хост старше суток останавливается. Чат автоматически переподключается при обрыве потока, а id хода хранится в истории (`run`). Claude Code работает внутри процесса сервера, его ход перезапуск по-прежнему обрывает.
- Codex, OpenCode и Cursor можно открывать в графическом чате, как Claude Code: один клиент Agent Client Protocol (`server/modules/agent/acp-*.ts`) запускает `opencode acp`, `agent acp` или Codex через `codex-acp` (глобальный бинарь предпочтительнее; иначе `npx -y @agentclientprotocol/codex-acp` вне папки проекта, чтобы npm не спотыкался о `devEngines` его `package.json`), ведёт сессию (`session/new`/`session/load`), стримит текст и инструменты в общие события чата, отвечает на `session/request_permission` из кнопок «Разрешить / Отклонить» и отменяет ход через `session/cancel`. Переключатель **TUI/GUI** и раздел настроек теперь доступны всем четырём агентам; процесс запускается через `os.tools.spawnAgentProcess` отдельно на каждый ход.
- ACP-клиент: запуск `npx` для Codex закреплён на версии `codex-acp@2.1.1`; рукопожатие (`initialize`, `session/new`, `authenticate`) ограничено 2 минутами простоя, ход `session/prompt` таймера не имеет (его прерывает «Стоп» или закрытие процесса); `session/load` вызывается только если агент объявил `loadSession`, а падение процесса или отсутствие входа больше не маскируются под «сессия не найдена».
- У графических чатов Claude Code, Codex, OpenCode и Cursor появились модель, усилие рассуждений и режим, а также прошлые сессии. Агент сам объявляет свои параметры (ACP `configOptions`, у Claude Code — `model` и `effort` SDK), над строкой ввода они показываются выпадающими списками, применяются до отправки сообщения (сначала модель — от неё зависят уровни усилия), запоминаются для агента в `launcher.json` и отражают то, что агент реально применил. Кнопка с часами в шапке открывает прошлые сессии агента в папке проекта (`session/list`, у Claude Code — `listSessions`), включая начатые в терминале; выбранная загружается в чат (`session/load`) и продолжается. Команды `ide.agent.controls.list`, `ide.agent.control.set`, `ide.agent.sessions.list`, `ide.agent.session.resume` доступны штатному агенту.
- Графические чаты переживают перезагрузки в dev-режиме: вопрос и идентификатор сессии агента сохраняются в начале хода, а не в конце, поэтому после перезапуска сервера или страницы прерванный ответ показывается как «Ответ прерван…», и следующее сообщение продолжает ту же сессию агента. Закрытие вида чата обрывает запрос с задержкой в 1,5 с и не срабатывает, если тот же чат тут же смонтирован снова, а карты чатов лежат в `import.meta.hot.data`: правка компонента или `session.ts` посреди ответа больше не убивает агента. Состояние чата разделено на `chat-state.ts`, `external.ts` и `session.ts`.
- Графические чаты находят CLI так же, как терминал: PATH берётся из интерактивного шелла пользователя, а не только из окружения сервера (раньше OpenCode, Cursor и Codex из `~/.local/bin` и `~/.opencode/bin` «не находились», если сервер запущен из ярлыка).
- Остановка агента завершает всё дерево процессов (в Linux — своя группа и сигнал группе, в Windows — `taskkill /T`), а не только процесс-обёртку: команды, запущенные агентом через shell, больше не переживают «Стоп». Запрос разрешения показывает diff/содержимое правки, а обычное «Разрешить» всегда разовое: постоянное разрешение даёт только отдельная кнопка «Всегда разрешать» (и лишь когда агент его поддерживает).
- Живой снимок вкладок для штатного агента: `ide.workbench.tab.read` теперь возвращает текущее состояние служебных вкладок — раздел и поиск настроек, черновик настроек проекта, фильтры горячих клавиш, режим локальной сети, контейнеры Docker, обзор коммита, issue/PR/discussion, информацию о репозитории и чат агента. Снимок публикует сам view через `useTabReadout` (`src/common/utilities/tab-readout.ts`), статический `TabType.read` остаётся запасным, секреты не раскрываются. Владелец вкладки приоритетнее вложенных view (секция внутри настроек не подменяет снимок вкладки и не теряется при её размонтировании). Панели с состоянием стали `keepAlive`: открытая, но скрытая вкладка тоже читается.

### Просмотр файлов

API: `POST/GET/DELETE /api/integrations/github/clone-jobs`. Прежний синхронный `POST …/github/clone` сохранён.

### Docker и изолированные окружения

- Интеграция Docker: локальный context, панель контейнеров, Compose-привязки, start/stop/restart/remove, логи и shell в обычных вкладках терминала, опубликованные порты; команды `ide.docker.*`.
- **Изолированное окружение проекта.** Клонирование по умолчанию идёт в Docker; Shell, команды проекта, Git, Codex/Claude/OpenCode и Bash штатного агента выполняются в контейнере: непривилегированный UID, read-only rootfs, без capabilities, Docker socket и HOME хоста, лимиты 2 CPU / 2 GiB / 256 процессов, сеть выключена по умолчанию, порты только на `127.0.0.1`. Отказ Docker не приводит к запуску на хосте.
- При запуске Projector удаляет контейнеры окружений, оставшиеся после аварийного завершения предыдущего процесса (SIGKILL, сбой). Чужие контейнеры, контейнеры текущего процесса и Dev Container не затрагиваются.

### Dev Container и доверие к репозиторию

- Если `devcontainer.json` требует больше, чем даёт ограниченная модель (команда на хосте, права контейнера, `runArgs`, `mounts`, Compose, `build`, Features, lifecycle-команды), при открытии проекта появляется окно «Доверять этому репозиторию?» с перечнем запрошенного и места выполнения. Отказ оставляет проект в прежней модели; согласие открывает **новые терминалы и Bash агента внутри Dev Container** через `@devcontainers/cli` (`up` + `exec`, прогресс сборки виден в терминале).
- Доверие хранится в `devcontainer-trust.json` (0600) по реальному пути проекта и привязано к хешу конфига вместе с Dockerfile и Compose-файлами: любое изменение отзывает его, проект возвращается к ограниченной модели и спрашивает снова. Решение принимается только с локальной машины и не является IDE-командой, чтобы агент не мог выдать доверие себе. Доступны `ide.devcontainer.status`, `ide.devcontainer.review` и `ide.devcontainer.stop` (нужен `confirm: true`).
- Ссылки на файлы в выводе доверенного терминала сопоставляются с проектом; пути вне проекта и `..` отклоняются; перетаскивание файлов хоста в такой терминал отключено.
- Ограничения: проверен один образ без Features и Compose; Git и Docker-панель работают на хосте; читается один конфиг на проект; контейнер долгоживущий и общий для терминалов.

### Секреты

- Токены и ключи интеграций (GitHub, Docker) хранятся в системном хранилище секретов (Linux: Secret Service по D-Bus — KWallet, GNOME Keyring); в `integrations.json` остаётся пометка `"vault": "keyring"`. Без доступного хранилища используется прежний файл с правами 0600; страница настроек показывает, какой вариант действует, `PROJECTOR_SECRET_STORE=file` отключает хранилище.
- Открытые токены переносятся при первом открытии настроек, файл переписывается только после проверки чтения обратно. Недоступное или заблокированное хранилище не стирает сохранённый секрет, а блокирует изменение.
- В настройках у токена GitHub есть «глазок»: показ на 30 секунд, только с локальной машины и только для токена из хранилища. Просмотр не зарегистрирован как IDE-команда.
- Ключи AI-провайдеров в `providers.json` по-прежнему зашифрованы встроенным ключом и в хранилище не перенесены.

### Workspace, терминалы и агент

- Статусная строка редактора и недельный лимит Codex CLI: остаток процента и время сброса.
- Терминалы управляются по WebSocket вместо опроса сессий; переподключение восстанавливает экран, курсор и историю.
- Агент читает содержимое вкладок: `ide.workbench.tabs.list`, `ide.workbench.tab.read` (файлы с черновиками, diff, архивы, терминалы с серверного headless xterm, в том числе скрытые).
- Отдельные мобильные поверхности редактора и боковых панелей, компактный выбор проекта, правки мобильных элементов.
- Режим `prod` работает на собственном Node-сервере по `dist` вместо `vp preview`.
- Доступ по локальной сети: режим `lan` (`0.0.0.0`) включается на `/settings` или флагом `--lan`; необязательный пароль (scrypt-хеш) передаётся как `Authorization: Bearer`, терминалы и API принимают его через WebSocket-токен. Перезапуск, смена режима, просмотр токена и решения о доверии остаются локальными.
- Внутреннее: типы служебных вкладок и разделы боковой панели регистрируются реестрами; крупные компоненты workspace разбиты; проект целиком приведён к единому форматированию.
- Исправления: сохранение состояния редактора и таблицы Markdown, освобождение места пустыми и скрытыми группами панелей.

### Проверки и зависимости

- Новые зависимости: `@devcontainers/cli`, `jsonc-parser`.
- `vp run test:live` (нужен локальный Docker, в `vp run check` не входит) проверяет на настоящем демоне изоляцию, секреты, порты, отсутствие запуска на хосте, остановку во время создания, очистку после SIGKILL сервера и полный сценарий Dev Container.
