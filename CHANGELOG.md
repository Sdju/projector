# Changelog

## Не выпущено

### Агент

- Kimi Code снова переключается в графический режим: `kimi` добавлен в список программ с чатом, поэтому выбор **GUI** в настройках и в меню «+» сохраняется, а не отклоняется сервером.
- Возможности агентов: остров **возможности** в табе агента включает необязательные умения только для текущего чата; умолчания по агентам — в настройках «Возможности агентов». Первая возможность — виджеты в ответах: у Projector включены по умолчанию, остальным включаются в настройках или в чате. Projector получает их в системном промпте, Claude Code — в `systemPrompt.append`, ACP-агенты — в первом сообщении новой сессии; в чужие конфиги и проект ничего не пишется. Умолчания — `agent/features.json`, выбор чата — в его истории, API `/api/agent/features`, команды `ide.agent.features.chat.*` и `ide.agent.features.defaults.*`.
- Ветки чатов: «Ответвить в новый чат» у сообщения пользователя и «Продолжить в новом чате» у ответа создают отдельный чат из копии разговора, не меняя исходный. У Claude Code ветка нативная, остальные агенты переигрывают копию; текст вопроса у режима «до сообщения» сразу стоит в поле ввода новой ветки. Команда `ide.agent.chat.fork`.
- Закрытые вкладки чатов (включая ветки) больше не теряются: непустой чат индексируется по проекту и открывается из блока «Недавние чаты» в истории чата. Команда `ide.agent.chats.recent`, API `GET /api/agent/chats/recent`.
- Время работы видно вживую: у поля ввода тикает время текущего ответа, рядом с вызовом инструмента — его длительность (после завершения остаётся итог), у субагентов и фоновых заданий — их время, а остров активности показывает, сколько уже работает каждый агент. Время вызова переживает переподключение к ответу.

## 0.7.0

Выпуск превращает штатного агента Projector из помощника по настройкам в расширяемого: он подключает MCP-серверы, ищет в интернете, знает навыки и слэш-команды, запускает хуки, помнит заметки, сам сжимает длинные разговоры, считает токены и стоимость ответов и переживает сбои провайдера. Работу с кодом он по-прежнему поручает кодовым агентам.

### Агент

- Память: заметки «запомни…» (`memory_write` с подтверждением, `memory_read`) общие и по проектам, правятся в настройках «Память агента» и командами `ide.agent.memory.get/set`.
- MCP-серверы пользователя (`agent/mcp.json`) и проекта (`.mcp.json`): stdio, http и sse, инструменты `mcp__<сервер>__<инструмент>`. Запуск проектного сервера и вызов изменяющего инструмента подтверждаются, недоступный сервер не ломает ход. Настройки «MCP-серверы агента», `ide.agent.mcp.get/set`.
- Веб: `web_search` (Brave Search или свой SearXNG, ключ в системном хранилище секретов) и `web_fetch`. Адреса локальной сети, перенаправления и подмена DNS закрыты, первое обращение к сайту подтверждается, результаты помечены как недоверенные.
- Навыки (`skills/<имя>/SKILL.md`) и слэш-команды (`commands/<имя>.md`) из папки пользователя, `.projector/` и `.claude/` проекта; подсказка `/` в чате, инструмент `use_skill`, раздел «Навыки и команды агента».
- Хуки `PreToolUse`, `PostToolUse` и `Stop` (`agent/hooks.json` пользователя и `.projector/hooks.json` проекта с подтверждением и «Всегда разрешать»): код выхода 2 или JSON-ответ запрещает вызов, `additionalContext` дописывается к результату. Раздел «Хуки агента», `ide.agent.hooks.get/set`.
- Проектные `AGENTS.md` и `CLAUDE.md` попадают в промпт; старые ходы сжимаются в сводку вместо отбрасывания, сжатие идёт само при заполнении контекста и по `/compact`; окно контекста берётся из настроек модели.
- Надёжность: повтор запроса с паузой при сбоях провайдера, запасная модель провайдера, лимиты шагов, времени и токенов хода, обнаружение зацикливания, кнопка «Продолжить».
- Размышление агента — свойство модели с переключателем над строкой ввода; единый адаптер `providers/thinking.ts` переводит выбранный уровень в поля запроса Qwen, vLLM, DeepSeek, Ollama и LM Studio, OpenAI и OpenRouter.
- Расход: под ответом видны токены и доля из кэша провайдера, а с ценой модели (за 1 млн токенов, в настройках провайдера) ещё стоимость ответа и всего чата; данные расхода сохраняются в истории чата.
- Фоновые задания кодовых агентов (Claude Code, Codex, OpenCode, Cursor): сервер ведёт их сам, они видны в «острове активности» и во вкладке, уведомляют об ожидании пользователя и завершении; команды `ide.agent.job.*`.
- Реестр моделей провайдера с загрузкой списка, именами и несколькими включёнными провайдерами, типы провайдеров, баланс DeepSeek в строке состояния.

### Интерфейс

- Подсказка «Токены и кэш» вынесена в `UiTooltip` на CSS anchor positioning; время написания сообщения в строке действий.
- Длинные чаты монтируются с конца и показывают загрузку истории, потоковый Markdown рисуется блоками, переоткрытые чаты собираются так же, как живые.
- Редактор: верхняя панель с действиями и переключатель «исходник / документ» у Markdown. Настройки: отдельная страница на провайдера.

### Сервер

- Шлюз OpenAI API отказывает чужим origin и поддерживает белый список (шаблоны localhost и LAN); `providers.json` пишется атомарно, повреждённый файл сохраняется рядом.

### Тесты

- Сценарии проверки агента (`tests/evals/`): судья по записанным вызовам, подставная модель для самой проверки и запуск на сохранённом провайдере (`node tests/evals/run.mjs`).

## 0.6.0

Выпуск открывает Projector внешним приложениям через OpenAI-совместимый API, учит агента просить секреты так, чтобы они не проходили через модель, добавляет сценарии проекта с собственной папкой и адресом, переводит Claude Code в графическом чате на переживающий перезапуски ход и делает таблицы Markdown читаемыми при любой ширине.

### Безопасность

- Секреты агента уходят прямо в назначение и не проходят через модель: инструмент `request_secret` показывает поле пароля, значение записывается в `.env` проекта, в ключ AI-провайдера или в токен GitHub/GitLab (после проверки у сервиса), а модели возвращается только факт записи. `list_secret_destinations` перечисляет провайдеров (без ключей) и подключённые интеграции с токеном, чтобы модель могла назвать адресата. Форма показывает назначение до ввода; для провайдера — полный адрес, куда уйдёт ключ.
- Ключи AI-провайдеров хранятся только в системном хранилище (OS keyring); `providers.json` содержит настройки без ключей. Ключи, оставшиеся в файле от прежних версий, переносятся в хранилище при первом открытии. Без доступного хранилища ключ не принимается.
- Индикатор лимитов Claude Code спрашивает агента через Agent SDK. Projector больше не читает `~/.claude/.credentials.json` и не вызывает OAuth-эндпоинт использования с этим токеном.

### Сервер

- OpenAI-совместимый API под `/api/openai/v1` (`models`, `chat/completions`, `completions`, `embeddings`, потоковый ответ) проксирует запросы других приложений к провайдерам Projector. Отвечает с любого origin (CORS), необязательный ключ доступа (Bearer). Выключен по умолчанию; включается в настройках («OpenAI API», команда `ide.openai.gateway.set`) или через `PUT /api/openai`. Подробнее — [usage](docs/usage.md#openai-совместимый-api).

### Интерфейс

- Таблицы Markdown больше не обязаны вмещаться по ширине: колонки получают ширину по содержимому, слова не рвутся посреди, широкая таблица прокручивается по горизонтали и в редакторе растёт вправо за колонку текста до края окна (то же правило в чате агента).
- Docker: если daemon не отвечает, интеграция предлагает его запустить способом, принятым в системе (systemd/pkexec, Docker Desktop, OrbStack, Colima): кнопка «Запустить Docker» в боковой панели, панели и настройках и команда `ide.docker.daemon.start` для штатного агента (с подтверждением). Если запуск невозможен, показывается инструкция.
- Загрузка проекта показывает каркас рабочей области (`ProjectOpening`, `UiSkeleton`) вместо голой строки «открываю проект…»; дерево файлов и терминалы пишут, что загружаются, а не «Нет терминалов». Сообщение «проект не найден» получило кнопку «К списку проектов».
- Ошибки Git-панели, истории, выбора ветки и дерева файлов показываются карточками в правом нижнем углу (`reportError`, `toastErrors` в `notice.ts`): не сдвигают вёрстку, закрываются крестиком или сами через 15 секунд, у ошибки Git есть действие «Обновить».

### Агент

- Штатный агент Projector получил возможности GUI-агентов: выбор модели и режима разрешений в чате, подтверждение изменяющих команд оболочки и Projector (`projector-guard.ts`), список шагов, вопросы с вариантами, история вместе с вызовами инструментов, картинки в сообщениях, кольцо контекста и сообщение об остановке на лимите шагов. «Новый чат» откладывает беседу в историю чатов (открыть, закрепить, переименовать, удалить) вместо удаления.
- Режим разрешений «Авто» у агента Projector: команды оболочки, которые не только читают, проверяет отдельный запрос к модели (`projector-review.ts`); безопасные идут без вопроса, остальные и сбой проверки — на подтверждение с причиной.
- Рассуждения агента показываются сворачиваемым блоком в порядке появления: он раскрыт и следует за текстом, пока агент думает, и сворачивается по окончании (событие `thought`). Работает для Claude Code, ACP-агентов и агента Projector.
- Субагенты и фоновые команды описаны общим контрактом `core/modules/agent-task` и показаны панелью задач, вкладкой задачи и «островом активности». Для OpenCode и Codex различия протокола вынесены в диалекты (`acp-dialect-<агент>.ts`).
- Параметры и возможности чата (модель, усилие, режим, добавление в идущий ответ, ветвление, сжатие контекста) берутся из адаптера и общие для интерфейса и IDE-команд `ide.agent.*`.
- Переход между вкладками блока по Alt+PageUp / Alt+PageDown с историей блока.
- Claude Code в графическом чате работает через `agent-host`, как ACP-агенты: перезапуск сервера (Vite перезагружает dev-сервер при правке файла из его графа конфигурации), закрытая вкладка или перезагруженная страница больше не обрывают ответ. Запросы разрешений, вопросы и команды пересылаются сервером и показываются заново при возвращении в чат. Прежнее ограничение («ход Claude Code обрывается перезапуском») снято.

### Терминалы

- Вкладки браузера делят соединения терминалов через SharedWorker: один WebSocket для управления и один для экранов (`/api/terminal/shared`). Без SharedWorker, при сбое его запуска или с `?terminalTransport=legacy` используется прежний транспорт. Подробнее — [terminal-transport](docs/terminal-transport.md).
- Команда оболочки выбирается по среде выполнения: хост, Docker-контейнер или Dev Container.

### Рабочее пространство и лаунчер

- Лимит 1 МБ на открываемый текстовый файл снят (чтение, сохранение, `git show`, файлы из системы). Файл от 10 МБ открывается после вопроса «Открыть?» (сервер при `ask=1` отвечает только размером, `large`); технический потолок — 256 МБ.
- Слежение за файлами и папками делегировано провайдерам профиля workspace (`files.watch`), поэтому источники без локального сервера тоже могут сообщать об изменениях.
- Доступные действия проекта в веб- и GTK-палитре определяются одной функцией `resolveLauncherAction`.
- Всплывающие окна сессий используют общий фокус и жизненный цикл; настройки интеграций выполняют операции через общий слой и доступны как IDE-команды.
- Сценарий запуска проекта может задать папку внутри проекта, свой адрес и режим запуска; пустые значения берутся из проекта. Сервер проверяет их при сохранении, терминал стартует сценарий в его папке (только для запуска на этой машине). Сценарии — страницы раздела «Запуск» настроек с перетаскиванием порядка (Alt+стрелки с клавиатуры). Редактор и команды `ide.project.command.*` используют одни и те же проверки; команды принимают папку, адрес и режим и получили `move` и `duplicate`. Запуск, застрявший в «останавливается» без терминала, переходит в «простой», поэтому проект можно снова остановить и удалить.

## 0.5.0

Выпуск превращает агентов в графические чаты (Claude Code через Agent SDK, Codex, OpenCode и Cursor через ACP) с историей, версиями, откатом и вопросами агента, добавляет встроенный браузер-вкладку и слежение за файлами на диске, выводит поддержку Windows и macOS на уровень адаптеров ОС и вводит общий UI-кит.

### Платформы

- Windows и macOS работают через адаптеры ОС (`core/modules/os`, общий POSIX-код в `core/modules/os-posix`): на Windows — файлы только для владельца через ACL, завершение деревьев процессов через `taskkill`, значок в трее и глобальная горячая клавиша вместе с `vp dev`, запуск GTK-палитры из нативного окружения; на macOS — каталог приложений из `.app`, резидент в строке меню с глобальной горячей клавишей, Keychain для секретов и GTK-палитра при установленном GTK4 (иначе палитра на Chromium). Обе платформы проверяются в CI. Сервер, запущенный из сессии Claude Code, больше не передаёт её метки терминалам и агентам.

### Рабочее пространство

- Вкладка-«псевдобраузер» открывает веб-страницы и dev-серверы проекта через серверный прокси: каждый сайт получает свой origin вида `<host>.<tag>.<key>.proxy.localhost`, поэтому относительные ссылки, `fetch` и хранилище работают; ключ защищает прокси-хост, cookies лежат на сервере, адреса loopback и LAN отклоняются.
- Сервер следит за открытыми файлами и раскрытыми папками (`PUT workspace/watch`, события `file-changed`, `dir-changed`, `watch-error` по SSE страницы). Вкладки без правок обновляются сами, при несохранённых правках панель предлагает «загрузить с диска» или «оставить мои» (`ide.editor.file.reloadFromDisk`, `ide.editor.file.keepMine`), автосохранение до выбора приостановлено; списки раскрытых папок перечитываются.
- Файлы и папки из системы можно перетащить в выбранную папку дерева (по пути из файлового менеджера или загрузкой из браузера). Занятые имена не перезаписываются молча: один конфликт предлагает оставить оба, заменить (старое уходит в `.projector-trash`) или отменить, несколько — общий префикс. Команда `ide.fileTree.entry.import`.
- Избранные папки в лаунчере: проекты из них идут первыми, префикс `new/` создаёт проект в избранной папке.
- Вкладки: перетаскивание вкладки принимается и на полосе пустой группы; после кнопки новой сессии добавлен разделитель.

### Интерфейс

- Общий UI-кит (`src/common/ui`): панели, карточки, острова, поля, строки выбора, таблицы, сообщения, значки и прочие примитивы с описанием в [docs/ui-kit.md](docs/ui-kit.md) и браузерными тестами; рабочее пространство, каталог, лаунчер и настройки переведены на него.

### GitHub

- Клонирование репозитория больше не привязано к открытому острову строки пути: диалог и команды `ide.github.repository.clone.*` живут на уровне страницы репозитория (`github-clone:<projectId>`), поэтому доступны из командного центра и переживают закрытие переключателя проектов; `clone.directory` и `clone.cancel` помечены `palette: false` как работающие только внутри окна.

### Агент

- Чат агента: поле ввода с файловыми чипами и `@`-упоминаниями, подсказки слэш-команд, картинки в сообщениях, предпросмотр чипа при наведении и открытие по клику; кольцо заполнения контекста; ответ собирается из упорядоченных частей, вход инструмента показан читаемо, режим разрешений «авто».
- История чата хранится в SQLite (`agent/history.sqlite`): одна строка на ход, ветки — несколько строк с общим `parent`, сохраняются только изменённые строки; старые JSON-файлы импортируются один раз. Схема истории больше не отвергает чат из-за длины полей или числа вызовов, а ошибка сохранения показывается в чате.
- Откат и версии: правка или повтор сообщения сохраняет прежний вариант как версию; откат файлов к ходу, очередь сообщений, мгновенная вставка сообщения в идущий ответ, план, список изменённых файлов, вызовы субагентов вложены, изолированная копия проекта (`git worktree`) со слиянием или удалением, MCP-серверы из `.mcp.json` в сессии, команды `ide.agent.*` на уровне рабочего пространства.
- Вопросы агента (ACP elicitation) показываются карточкой поверх переписки над полем ввода и не сдвигают сообщения; можно выбрать вариант, несколько или написать свой.
- Ошибка в чате сворачивается до трёх строк и скрывается кнопкой; длинные имена вызовов обрезаются, а вывод команд Codex (`terminal_output_delta`) показывается как результат вместо «Ожидание результата…».
- Claude Code может работать в графическом чате через Agent SDK вместо терминала (переключатель TUI/GUI, по умолчанию терминал).
- Проверка архитектуры FEOD в `vp dev` больше не блокирует сервер: раньше `buildStart` вызывал `oxlint` через `spawnSync` без таймаута, и каждый перезапуск замораживал процесс, а нарушение (например, файл длиннее 400 строк) или падение `oxlint` останавливали сервер. Теперь проверка идёт асинхронно с таймаутом (`checkFeodAsync`), результат пишется в лог; `vp build`, `vp run architecture` и pre-commit по-прежнему блокируют.
- Ход Codex, OpenCode и Cursor переживает перезапуск сервера, закрытую вкладку и перезагрузку страницы. Процесс агента держит отдельный хост `cli/app/agent-host.mjs` (своя группа процессов, сокет в каталоге хода), он записывает весь обмен в `trace.log`; сервер подключается к нему как к обычному дочернему процессу (`server/modules/agent/hosted-process.ts`). После перезапуска чат повторяет запрос с `attach`, сервер заново проходит ход по журналу — отправленные ранее запросы повторно агенту не уходят, уже отвеченные запросы разрешений не показываются снова, — и дальше идёт живой поток; если хоста уже нет, ответ воспроизводится из файла. Закрытие страницы больше не останавливает агента: отменяет только «Стоп» (`POST /api/agent/cancel`), который убивает дерево процессов по сохранённой идентичности процесса, а не по pid. Хост сам завершает агента через 30 минут без подключённого сервера, а завершённые ходы, к которым не вернулись, удаляются через час (при старте сервера, при новом ходе и по таймеру), а хост старше суток останавливается. Чат автоматически переподключается при обрыве потока, а id хода хранится в истории (`run`). Claude Code работает внутри процесса сервера, его ход перезапуск по-прежнему обрывает.
- Codex, OpenCode и Cursor можно открывать в графическом чате, как Claude Code: один клиент Agent Client Protocol (`server/modules/agent/acp-*.ts`) запускает `opencode acp`, `agent acp` или Codex через `codex-acp` (глобальный бинарь предпочтительнее; иначе `npx -y @agentclientprotocol/codex-acp` вне папки проекта, чтобы npm не спотыкался о `devEngines` его `package.json`), ведёт сессию (`session/new`/`session/load`), стримит текст и инструменты в общие события чата, отвечает на `session/request_permission` из кнопок «Разрешить / Отклонить» и отменяет ход через `session/cancel`. Переключатель **TUI/GUI** и раздел настроек теперь доступны всем четырём агентам; процесс запускается через `os.tools.spawnAgentProcess` отдельно на каждый ход.
- ACP-клиент: запуск `npx` для Codex закреплён на версии `codex-acp@2.1.1`; рукопожатие (`initialize`, `session/new`, `authenticate`) ограничено 2 минутами простоя, ход `session/prompt` таймера не имеет (его прерывает «Стоп» или закрытие процесса); `session/load` вызывается только если агент объявил `loadSession`, а падение процесса или отсутствие входа больше не маскируются под «сессия не найдена».
- У графических чатов Claude Code, Codex, OpenCode и Cursor появились модель, усилие рассуждений и режим, а также прошлые сессии. Агент сам объявляет свои параметры (ACP `configOptions`, у Claude Code — `model` и `effort` SDK), над строкой ввода они показываются выпадающими списками, применяются до отправки сообщения (сначала модель — от неё зависят уровни усилия), запоминаются для агента в `launcher.json` и отражают то, что агент реально применил. Кнопка с часами в шапке открывает прошлые сессии агента в папке проекта (`session/list`, у Claude Code — `listSessions`), включая начатые в терминале; выбранная загружается в чат (`session/load`) и продолжается. Команды `ide.agent.controls.list`, `ide.agent.control.set`, `ide.agent.sessions.list`, `ide.agent.session.resume` доступны штатному агенту.
- Графические чаты переживают перезагрузки в dev-режиме: вопрос и идентификатор сессии агента сохраняются в начале хода, а не в конце, поэтому после перезапуска сервера или страницы прерванный ответ показывается как «Ответ прерван…», и следующее сообщение продолжает ту же сессию агента. Закрытие вида чата обрывает запрос с задержкой в 1,5 с и не срабатывает, если тот же чат тут же смонтирован снова, а карты чатов лежат в `import.meta.hot.data`: правка компонента или `session.ts` посреди ответа больше не убивает агента. Состояние чата разделено на `chat-state.ts`, `external.ts` и `session.ts`.
- Графические чаты находят CLI так же, как терминал: PATH берётся из интерактивного шелла пользователя, а не только из окружения сервера (раньше OpenCode, Cursor и Codex из `~/.local/bin` и `~/.opencode/bin` «не находились», если сервер запущен из ярлыка).
- Остановка агента завершает всё дерево процессов (в Linux — своя группа и сигнал группе, в Windows — `taskkill /T`), а не только процесс-обёртку: команды, запущенные агентом через shell, больше не переживают «Стоп». Запрос разрешения показывает diff/содержимое правки, а обычное «Разрешить» всегда разовое: постоянное разрешение даёт только отдельная кнопка «Всегда разрешать» (и лишь когда агент его поддерживает).
- Живой снимок вкладок для штатного агента: `ide.workbench.tab.read` теперь возвращает текущее состояние служебных вкладок — раздел и поиск настроек, черновик настроек проекта, фильтры горячих клавиш, режим локальной сети, контейнеры Docker, обзор коммита, issue/PR/discussion, информацию о репозитории и чат агента. Снимок публикует сам view через `useTabReadout` (`src/common/utilities/tab-readout.ts`), статический `TabType.read` остаётся запасным, секреты не раскрываются. Владелец вкладки приоритетнее вложенных view (секция внутри настроек не подменяет снимок вкладки и не теряется при её размонтировании). Панели с состоянием стали `keepAlive`: открытая, но скрытая вкладка тоже читается.

### Просмотр файлов

- Клонирование выполняется **фоновой задачей** с фазами (проверка Docker и образа → скачивание образа → клонирование → добавление проекта) и кнопкой «Прервать» (`ide.github.repository.clone.abort`): отмена останавливает `docker pull` или `git clone`, удаляет контейнер и временную папку, проект не добавляется. API: `POST/GET/DELETE /api/integrations/github/clone-jobs`. Прежний синхронный `POST …/github/clone` сохранён.

### Docker и изолированные окружения

- Интеграция Docker: локальный context, панель контейнеров, Compose-привязки, start/stop/restart/remove, логи и shell в обычных вкладках терминала, опубликованные порты; команды `ide.docker.*`.
- **Изолированное окружение проекта.** Клонирование по умолчанию идёт в Docker; Shell, команды проекта, Git, Codex/Claude/OpenCode и Bash штатного агента выполняются в контейнере: непривилегированный UID, read-only rootfs, без capabilities, Docker socket и HOME хоста, лимиты 2 CPU / 2 GiB / 256 процессов, сеть выключена по умолчанию, порты только на `127.0.0.1`. Отказ Docker не приводит к запуску на хосте.
- При запуске Projector удаляет контейнеры окружений, оставшиеся после аварийного завершения предыдущего процесса (SIGKILL, сбой). Чужие контейнеры, контейнеры текущего процесса и Dev Container не затрагиваются.

### Dev Container и доверие к репозиторию

- Если `devcontainer.json` требует больше, чем даёт ограниченная модель (команда на хосте, права контейнера, `runArgs`, `mounts`, Compose, `build`, Features, lifecycle-команды), при открытии проекта появляется окно «Доверять этому репозиторию?» с перечнем запрошенного и места выполнения. Отказ оставляет проект в прежней модели; согласие открывает **новые терминалы и Bash агента внутри Dev Container** через `@devcontainers/cli` (`up` + `exec`, прогресс сборки виден в терминале).
- Доверие хранится в `devcontainer-trust.json` (0600) по реальному пути проекта и привязано к хешу конфига вместе с Dockerfile и Compose-файлами: любое изменение отзывает его, проект возвращается к ограниченной модели и спрашивает снова. Решение принимается только с локальной машины и не является IDE-командой, чтобы агент не мог выдать доверие себе. Доступны `ide.devcontainer.status`, `ide.devcontainer.review` и `ide.devcontainer.stop` (нужен `confirm: true`).
- Ссылки на файлы в выводе доверенного терминала сопоставляются с проектом; пути вне проекта и `..` отклоняются; перетаскивание файлов хоста в такой терминал отключено.
- Ограничения: проверен один образ без Features и Compose; Git и Docker-панель работают на хосте; читается один конфиг на проект; контейнер долгоживущий и общий для терминалов.

### Секреты

- Токены и ключи интеграций (GitHub, Docker) хранятся в системном хранилище секретов (Linux: Secret Service по D-Bus — KWallet, GNOME Keyring); в `integrations.json` остаётся пометка `"vault": "keyring"`. Без доступного хранилища используется прежний файл с правами 0600; страница настроек показывает, какой вариант действует, `PROJECTOR_SECRET_STORE=file` отключает хранилище.
- Открытые токены переносятся при первом открытии настроек, файл переписывается только после проверки чтения обратно. Недоступное или заблокированное хранилище не стирает сохранённый секрет, а блокирует изменение.
- В настройках у токена GitHub есть «глазок»: показ на 30 секунд, только с локальной машины и только для токена из хранилища. Просмотр не зарегистрирован как IDE-команда.
- Ключи AI-провайдеров в `providers.json` по-прежнему зашифрованы встроенным ключом и в хранилище не перенесены.

### Workspace, терминалы и агент

- Статусная строка редактора и недельный лимит Codex CLI: остаток процента и время сброса.
- Терминалы управляются по WebSocket вместо опроса сессий; переподключение восстанавливает экран, курсор и историю.
- Агент читает содержимое вкладок: `ide.workbench.tabs.list`, `ide.workbench.tab.read` (файлы с черновиками, diff, архивы, терминалы с серверного headless xterm, в том числе скрытые).
- Отдельные мобильные поверхности редактора и боковых панелей, компактный выбор проекта, правки мобильных элементов.
- Режим `prod` работает на собственном Node-сервере по `dist` вместо `vp preview`.
- Доступ по локальной сети: режим `lan` (`0.0.0.0`) включается на `/settings` или флагом `--lan`; необязательный пароль (scrypt-хеш) передаётся как `Authorization: Bearer`, терминалы и API принимают его через WebSocket-токен. Перезапуск, смена режима, просмотр токена и решения о доверии остаются локальными.
- Внутреннее: типы служебных вкладок и разделы боковой панели регистрируются реестрами; крупные компоненты workspace разбиты; проект целиком приведён к единому форматированию.
- Исправления: сохранение состояния редактора и таблицы Markdown, освобождение места пустыми и скрытыми группами панелей.

### Проверки и зависимости

- Новые зависимости: `@devcontainers/cli`, `jsonc-parser`.
- `vp run test:live` (нужен локальный Docker, в `vp run check` не входит) проверяет на настоящем демоне изоляцию, секреты, порты, отсутствие запуска на хосте, остановку во время создания, очистку после SIGKILL сервера и полный сценарий Dev Container.
- Не проверялись вживую: private clone в Docker, OAuth Device Flow, установка AI CLI, Dev Container с Features и Compose.
