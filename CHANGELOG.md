## 0.4.0

Выпуск переделывает рабочее пространство: панели стали «островами» на общем холсте, верхняя строка объединена с переключателем проектов и запуском, а мобильная раскладка получила отдельный дизайн. Добавлены GitLab и просмотр HTML-страниц, архитектурные проверки перенесены на FEOD-плагин.

### Рабочее пространство
- Панели (тулбар, сайдбар, группы вкладок) — скруглённые острова на общем холсте с единым зазором вместо разделителей в 1 px; статусная строка плоская.
- Переключатель проектов в верхней строке: клик по названию открывает остров с редактируемой строкой пути, поиском и недавними проектами; путь больше не занимает шапку на десктопе.
- Верхние панели объединены: проект, запуск и раскладка живут в одной строке. Меню «+» и новое меню раскладки — острова, растущие из своих кнопок: сессии с подписями и лимитами, визуальные пресеты, видимость блоков и сайдбара, сброс. Команды `ide.workbench.layout.preset` и `ide.workbench.layout.group.toggle` доступны и агенту.
- Терминалы и агенты создаются через «+» перед первой вкладкой группы; в меню виден остаток лимита каждого агента с тем же цветом темпа, что и в статусной строке. Чат встроенного агента перенесён в «+» отдельной группой.
- Запуск — одна кнопка «▶ dev ˅»: остров со сценариями и их командами, «Открыть»/«Остановить» для запущенных и «Настроить сценарии…». Новые команды `ide.project.run.*` заменяют `RunControls`.
- Настройки проекта используют общий workbench настроек: разделы (общие, сценарии, запуск, удаление) делят один черновик и панель сохранения; `ide.workbench.project.settings.open` открывает вкладку, «Настроить сценарии…» ведёт сразу в нужный раздел.
- Разделы сайдбара — безрамочная вертикальная рейка рядом с панелью; клик по активному разделу сворачивает панель. Кнопка обновления появляется при наведении в углу панели (`ide.workbench.sidebar.refresh`).

### Мобильная раскладка
- Контент, файлы и терминалы лежат в островах на холсте; переключатель поверхностей — плавающая нижняя «пилюля» (активная подписана). Шапка компактная: проект и запуск в одной строке.
- Всплывающие панели запуска, раскладки, новой сессии и выбора проекта превращаются в нижние листы со scrim и выездом снизу (общий класс `mobile-sheet`, общий запрос compact viewport вместо дублированного media query).
- В терминальной поверхности есть меню «+», индикаторы квот перенесены в неё из статусной строки; на мобильном статусная строка не рисуется.

### Просмотр файлов
- HTML-файлы открываются как страница во вкладке: песочница iframe с изолированным origin, без доступа к API Projector. Сервер отдаёт файлы проекта по `/api/projects/<id>/site/<путь>`, поэтому относительные ссылки работают. Команды `ide.editor.html.*`.
- У HTML нет отдельных режимов просмотра: разделитель сам сворачивает любую из панелей. Перетаскиваемый разделитель SVG-просмотра вынесен в общий `SplitPanes`.

### GitLab
- Интеграция GitLab (gitlab.com и self-hosted): вход по Personal Access Token, папка импорта, поиск проектов в палитре по `gl/` (и по ссылкам любого хоста с `gitlab`) и клонирование в `папка/группа/подгруппа/проект`. Свои проекты находятся локально по полному пути (`группа/`, `группа/часть`, короткие слова), поиск GitLab добавляет только публичные. Команды `ide.gitlab.*`.
- Модуль интеграций разделён по ответственности: хранилище настроек и секретов, GitHub, GitLab, импорт по HTTPS (клонирование и задачи), Docker. URL API не менялись.

### Архитектура и разработка
- Собственный проверяльщик FEOD заменён конфигурацией плагина `@o-feod/oxlint-structure-plugin` (`feod.config.mjs`): корни, транзитные модули, подмодули только для родителя, публичные входы, циклы (включая type-only), границы платформ и реестр больших файлов. `scripts/check-feod.mjs` запускает только правила FEOD для сборки, тестов и старта Vite — один раз, без проверки на каждый HMR.
- Тесты архитектуры линтят фикстурные проекты реальной конфигурацией.

## 0.3.0

Выпуск посвящён безопасному запуску чужих репозиториев: просмотр GitHub без клонирования, ограниченное Docker-окружение, опциональный Dev Container по явному доверию и хранение секретов в системном хранилище. Требуется Docker только для функций контейнеров; остальное работает как раньше.

### GitHub

- Репозиторий открывается без клонирования как readonly-проект `gh:/owner/repo`: дерево, файлы, Markdown и изображения, фиксация ветки на SHA, `?ref=` и `&path=`. Публичные репозитории доступны без входа.
- История Git для GitHub: граф коммитов, поиск по сообщению и `@автору`, обзор коммита и diff относительно первого родителя.
- Кнопка с логотипом GitHub открывает вкладку **О репозитории** (описание, статистика, метаданные), команда `ide.github.repository.info`. Раздел **Issues** в боковой панели показывает открытые, закрытые или все issues и открывает вкладку обсуждения с Markdown и комментариями; команды `ide.issues.*`.
- Строка пути понимает `gh:/owner/` с подсказками репозиториев владельца (Tab, ↑/↓, Enter); есть кнопка клонирования с выбором папки и переходом в локальный проект.
- Клонирование выполняется **фоновой задачей** с фазами (проверка Docker и образа → скачивание образа → клонирование → добавление проекта) и кнопкой «Прервать» (`ide.github.repository.clone.abort`): отмена останавливает `docker pull` или `git clone`, удаляет контейнер и временную папку, проект не добавляется. API: `POST/GET/DELETE /api/integrations/github/clone-jobs`. Прежний синхронный `POST …/github/clone` сохранён.

### Docker и изолированные окружения

- Интеграция Docker: локальный context, панель контейнеров, Compose-привязки, start/stop/restart/remove, логи и shell в обычных вкладках терминала, опубликованные порты; команды `ide.docker.*`.
- **Изолированное окружение проекта.** Клонирование по умолчанию идёт в Docker; Shell, команды проекта, Git, Codex/Claude/OpenCode и Bash штатного агента выполняются в контейнере: непривилегированный UID, read-only rootfs, без capabilities, Docker socket и HOME хоста, лимиты 2 CPU / 2 GiB / 256 процессов, сеть выключена по умолчанию, порты только на `127.0.0.1`. Отказ Docker не приводит к запуску на хосте.
- При запуске Projector удаляет контейнеры окружений, оставшиеся после аварийного завершения предыдущего процесса (SIGKILL, сбой). Чужие контейнеры, контейнеры текущего процесса и Dev Container не затрагиваются.

### Dev Container и доверие к репозиторию

- Если `devcontainer.json` требует больше, чем даёт ограниченная модель (команда на хосте, права контейнера, `runArgs`, `mounts`, Compose, `build`, Features, lifecycle-команды), при открытии проекта появляется окно «Доверять этому репозиторию?» с перечнем запрошенного и места выполнения. Отказ оставляет проект в прежней модели; согласие открывает **новые терминалы и Bash агента внутри Dev Container** через `@devcontainers/cli` (`up` + `exec`, прогресс сборки виден в терминале).
- Доверие хранится в `devcontainer-trust.json` (0600) по реальному пути проекта и привязано к хешу конфига вместе с Dockerfile и Compose-файлами: любое изменение отзывает его, проект возвращается к ограниченной модели и спрашивает снова. Решение принимается только с локальной машины и не является IDE-командой, чтобы агент не мог выдать доверие себе. Доступны `ide.devcontainer.status`, `ide.devcontainer.review` и `ide.devcontainer.stop` (нужен `confirm: true`).
- Ссылки на файлы в выводе доверенного терминала сопоставляются с проектом; пути вне проекта и `..` отклоняются; перетаскивание файлов хоста в такой терминал отключено.
- Ограничения: проверен один образ без Features и Compose; Git и Docker-панель работают на хосте; читается один конфиг на проект; контейнер долгоживущий и общий для терминалов.

### Секреты

- Токены и ключи интеграций (GitHub, Docker) хранятся в системном хранилище секретов (Linux: Secret Service по D-Bus — KWallet, GNOME Keyring); в `integrations.json` остаётся пометка `"vault": "keyring"`. Без доступного хранилища используется прежний файл с правами 0600; страница настроек показывает, какой вариант действует, `PROJECTOR_SECRET_STORE=file` отключает хранилище.
- Открытые токены переносятся при первом открытии настроек, файл переписывается только после проверки чтения обратно. Недоступное или заблокированное хранилище не стирает сохранённый секрет, а блокирует изменение.
- В настройках у токена GitHub есть «глазок»: показ на 30 секунд, только с локальной машины и только для токена из хранилища. Просмотр не зарегистрирован как IDE-команда.
- Ключи AI-провайдеров в `providers.json` по-прежнему зашифрованы встроенным ключом и в хранилище не перенесены.

### Workspace, терминалы и агент

- Статусная строка редактора и недельный лимит Codex CLI: остаток процента и время сброса.
- Терминалы управляются по WebSocket вместо опроса сессий; переподключение восстанавливает экран, курсор и историю.
- Агент читает содержимое вкладок: `ide.workbench.tabs.list`, `ide.workbench.tab.read` (файлы с черновиками, diff, архивы, терминалы с серверного headless xterm, в том числе скрытые).
- Отдельные мобильные поверхности редактора и боковых панелей, компактный выбор проекта, правки мобильных элементов.
- Режим `prod` работает на собственном Node-сервере по `dist` вместо `vp preview`.
- Доступ по локальной сети: режим `lan` (`0.0.0.0`) включается на `/settings` или флагом `--lan`; необязательный пароль (scrypt-хеш) передаётся как `Authorization: Bearer`, терминалы и API принимают его через WebSocket-токен. Перезапуск, смена режима, просмотр токена и решения о доверии остаются локальными.
- Внутреннее: типы служебных вкладок и разделы боковой панели регистрируются реестрами; крупные компоненты workspace разбиты; проект целиком приведён к единому форматированию.
- Исправления: сохранение состояния редактора и таблицы Markdown, освобождение места пустыми и скрытыми группами панелей.

### Проверки и зависимости

- Новые зависимости: `@devcontainers/cli`, `jsonc-parser`.
- `vp run test:live` (нужен локальный Docker, в `vp run check` не входит) проверяет на настоящем демоне изоляцию, секреты, порты, отсутствие запуска на хосте, остановку во время создания, очистку после SIGKILL сервера и полный сценарий Dev Container.
- Не проверялись вживую: private clone в Docker, OAuth Device Flow, установка AI CLI, Dev Container с Features и Compose.

## 0.1.0

Первый публичный выпуск Projector из исходников для Linux.

- GTK-палитра для поиска приложений и проектов, трей и горячая клавиша.
- Веб-интерфейс и режим отдельного окна Chromium.
- Каталог проектов, команды из `package.json` и терминалы Shell, Codex и Claude Code.
- Обзор файлов, поиск, редактирование текста и Markdown, просмотр архивов, изображений и SVG.
- Git: изменения, diff, stage/unstage и групповые действия.
- Интеграция GitHub: PAT или OAuth Device Flow, список репозиториев и импорт.
- Настройки, ключи интеграций и состояние рабочего пространства сохраняются на диске.
- Пакет `vio`: Vue renderer для нативных GTK4-приложений.

Проверенное desktop-окружение — KDE Plasma/X11. Установка требует Node.js 24,
Vite+, GTK4 и системных зависимостей. Самостоятельный бинарный дистрибутив
в этот выпуск не входит; Projector запускает локальный сервер через `vp dev`.
