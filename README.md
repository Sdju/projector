# projector

Локальный лаунчер системных приложений и pnpm / vite проектов. Общие поиск и история запусков, три способа открытия интерфейса. Один сервер на машине: повторный запуск использует уже работающий процесс.

Контекст для продолжения разработки: [заметки перед следующей сессией](docs/session-notes.md).

## Установка в меню

```bash
vp install
vp run desktop
```

После этого в меню приложений появляется **Projector** с иконкой — его можно закрепить. Команда `projector` ставится в `~/.local/bin`.

## Запуск

```bash
projector          # выбранный интерфейс; по умолчанию системное окно
projector toggle   # показать/скрыть палитру; команда для системного хоткея
projector --tray   # запустить скрытым, только иконка в трее
projector quit     # выйти из Projector и остановить запущенные им проекты
projector --native # системная палитра GTK4
projector --window # отдельное Chromium app-окно
projector --browser # страница в браузере по умолчанию
vp run native      # системное окно
vp run window      # отдельное веб-окно
vp run browser     # обычная страница
vp run server      # только сервер в терминале; повторно не дублирует процесс
```

Адрес: http://localhost:4177. Сервер слушает только локальный интерфейс.

## Поиск и запуск

Главная страница — поиск приложений и сохранённых проектов. Начните вводить название: поддерживаются неточные совпадения, описание и ключевые слова. ↑↓ выбирают результат, Enter запускает. Пустое поле показывает до семи результатов с приоритетом часто запускаемых приложений.

В системном и отдельном веб-окне палитра скрывается после запуска, по Esc и при переключении в другое приложение. Перемещение фокуса между полем и результатами её не закрывает. В обычной вкладке остаётся подтверждение запуска, Esc очищает поиск. Ошибка запуска остаётся видна в интерфейсе.

Режим по умолчанию выбирается на `/settings`. CLI-флаги выбирают интерфейс только для текущего вызова. Настройки и история: `~/.local/share/projector/launcher.json` (или `$XDG_DATA_HOME/projector/launcher.json`).

В KDE Projector автоматически регистрирует `Ctrl+Alt+Space`: нажатие показывает/скрывает выбранную палитру. Сочетание можно изменить или выключить на `/settings`. Занятые другим приложением сочетания не перехватываются. Настройки показывают реальное состояние регистрации хоткея.

В других рабочих окружениях назначьте удобное сочетание в настройках клавиатуры на команду `projector toggle`. Если команда ещё не установлена в PATH, используйте абсолютный путь к `bin/projector` с аргументом `toggle`.

## Работа в трее

После запуска Projector остаётся в трее даже при скрытой палитре. Клик по иконке открывает поиск в выбранном режиме. Контекстное меню: поиск, проекты, настройки и выход. «Выйти из Projector» завершает фоновые процессы Projector и запущенные им проекты; Esc только скрывает палитру.

`projector --tray` запускает приложение без показа окна. Эту команду можно добавить в автозапуск рабочего окружения; автоматически автозапуск не устанавливается.

«Перезапустить» в меню трея полностью завершает сервер и системный интерфейс, останавливает все терминалы и запущенные в них процессы, затем запускает Projector заново в трее. Настройки сохраняются; терминальные сессии не восстанавливаются.

Трей использует StatusNotifierItem / DBusMenu и требует поддержки этого протокола рабочим окружением. В KDE Plasma проверены реальное нажатие хоткея, повторное скрытие и меню трея.

## Требования интерфейсов

- Системное окно: Linux, Node.js 24, GTK4 и GObject Introspection (включая GioUnix). `node-gtk` использует системные библиотеки; Python не нужен. Окно сохраняется в отдельном Node-процессе и повторно вызывается через D-Bus.
- Отдельное веб-окно: Chromium-совместимый браузер. Используется отдельный профиль Projector; профиль текущего браузера не меняется. Фокус, скрытие и повторный показ реализованы через `xdotool` и `xprop` в X11.
- Обычная страница: браузер по умолчанию через `xdg-open`.

Поиск системных приложений во всех режимах использует GIO через `node-gtk`. GIO читает установленный каталог `.desktop`, учитывает скрытые записи и запускает приложения с поддержкой `Exec`, `Terminal` и D-Bus activation. Если каталог недоступен, поиск проектов остаётся доступным с сообщением об ошибке. Трей и KDE-хоткей используют `dbus-next`; необязательный биндинг `usocket` отключён, обычного session D-Bus сокета достаточно.

## Переиспользование JS/TS

Нативный UI использует отдельный workspace-пакет [`vio`](packages/vio/README.md) — Vue custom renderer для GTK4. Полная палитра описана в `native/modules/desktop/Palette.vue`: обычные `v-for`, `v-if`, `v-model`, bindings и сигналы. `native/modules/desktop/palette.ts` — небольшой контроллер для resident/D-Bus; создание, обновление и удаление виджетов выполняет renderer. Пакет `vio` не импортирует Projector и включает отдельный Counter-пример.

`core/modules/launcher/launcher.ts` содержит общие типы и HTTP-клиент, `core/modules/launcher/launcher-model.ts` — поиск с отменой устаревших ответов, задержку ввода, выбор результата, состояние ошибок и защиту от повторного запуска. Эту модель используют и веб-палитра, и `native/modules/desktop/Palette.vue`; отображение остаётся отдельным для DOM и GTK.

`native/modules/desktop/catalog.ts`, `native/modules/desktop/tray.ts` и `native/modules/desktop/shortcut.ts` содержат системные адаптеры. Сервер вызывает `native/app/entry.ts` через тот же Node, которым он запущен. Для проверки TS GTK-декларации генерируются из установленных библиотек в `node_modules/.node-gtk-types` командой `vp run gtk:types`; сборка выполняет её автоматически.

```bash
vp run vio:build      # отдельный пакет: ESM + TypeScript declarations
vp run vio:test       # renderer и SFC compiler без display
vp run vio:gtk-test   # реальные GTK widgets; нужен desktop display
vp run vio:demo       # самостоятельный Vue/GTK Counter
```

На Wayland нативное окно использует правила активации рабочего окружения; размещение и фокус нужно проверить в целевом окружении. Для отдельного веб-окна на Wayland повторный показ/скрытие пока не реализован — используйте системный режим или обычную страницу.

## Проекты

Управление проектами и логами: `/projects` или ссылка «Проекты» в палитре.

1. Добавьте проект по пути на диске.
2. «Прочитать» подтянет имя и скрипты из `package.json`.
3. Запускайте конкретную команду (`dev`, `preview`, своя).
4. Режим **сервер** оставляет процесс и логи. Режим **окно** после старта открывает URL в app-окне.

Список проектов: `~/.local/share/projector/projects.json`.


## Обзор проекта

Страница проекта открывается как лёгкое рабочее пространство: слева **Файлы / Поиск / Git**, в центре Monaco в режиме чтения, справа существующие терминалы Shell, Codex и Claude Code и логи запуска. Ширину панелей можно менять перетаскиванием границ или стрелками после фокуса на границе. На узком экране терминал располагается под обзором.

Дерево загружает папки по мере раскрытия, скрывает зависимости и сборочные каталоги. Файлы открываются во вкладках с подсветкой синтаксиса; Monaco загружается при первом открытии файла. Поиск по содержимому использует установленный `rg`, учитывает `.gitignore`, ищет буквальный текст без учёта регистра и открывает выбранную строку. Лимиты: текстовые файлы до 1 МБ, 200 результатов, до 5 строк на файл.

Git показывает ветку и отдельные списки подготовленных и рабочих изменений. Выбор изменения открывает встроенный diff: **HEAD → index** или **index → рабочий файл**, включая новые, удалённые и переименованные файлы. Кнопка **↻** обновляет дерево, Git, поиск и активный файл после работы агента. Просмотр не записывает файлы и не выполняет Git-операций изменения состояния.

Проверка дерева, ограничений чтения, Unicode-поиска и Git diff: `node --test tests/workspace.test.mjs` (также входит в `vp run test`).

Иконки дерева настраиваются через `public/file-icons/theme.json`: палитра, SVG и упорядоченные правила по именам, расширениям и путям. Добавление типа файла не требует правок компонентов. [Формат темы и примеры](docs/file-icons.md). Проверка: `vp run test:file-icons`.

## Терминал в браузере

На странице проекта есть интерактивный терминал: **+ shell**, **+ Codex**, **+ Claude Code** создают отдельные сессии в папке проекта. Codex и Claude Code запускаются установленными командами `codex` и `claude` из окружения пользователя; установка и авторизация выполняются обычным способом через эти CLI. Можно также открыть shell и запустить любую команду вручную.

Терминал использует `node-pty`, xterm.js и WebSocket: поддерживает ввод, ANSI-цвета, Unicode, курсор, полноэкранные приложения, историю shell, Ctrl+C и изменение размера. Панель можно развернуть на весь экран. Ctrl+Shift+C копирует выделение, Ctrl+Shift+V вставляет текст; также работают стандартная вставка браузера и Shift+Insert.

Переключение вкладок, переход на другую страницу и перезагрузка браузера сохраняют процесс. При подключении восстанавливаются текущий экран, курсор, режимы терминала и до 5000 строк истории; выбранная вкладка запоминается в текущей вкладке браузера. Кнопка **закрыть сессию** завершает shell вместе с дочерними процессами. Удаление проекта и выход из Projector тоже закрывают его терминалы. Сессии живут в памяти сервера: перезапуск Projector завершает их.

Сессии терминала независимы от команд **dev / preview** и их панели логов. Одновременно можно держать несколько shell и агентов; общий лимит — 24 сессии. Медленная отрисовка приостанавливает чтение PTY до подтверждения браузером, а оборванное соединение восстанавливается автоматически.

Доступ разрешён через локальный адрес Projector; WebSocket проверяет Origin. Для сборки `node-pty` на Linux нужны Python, make и C++ compiler. Установка через `vp install` разрешает сборку этого модуля в `pnpm-workspace.yaml`.

Проверка настоящего PTY и WebSocket без запуска моделей:

```bash
node --test tests/terminal.test.mjs
```

Тест использует временный проект и проверяет ввод, Unicode, размер PTY, Ctrl+C, вывод без перевода строки, восстановление alternate screen, контроль потока, независимые сессии, сохранение при перезагрузке модулей, коды завершения, остановку дочернего процесса, игнорирующего SIGTERM, и ограничения Origin / Host. Он также входит в `vp run test`.

## Агент Qwen

На странице проектов есть поле агента: путь или «найди vite проекты в ~/code». Qwen (OpenAI-compatible, как в ai-companion) сам читает `package.json` и добавляет проект.

Настройки: `/settings`. Ключ можно задать в UI или через `DASHSCOPE_API_KEY` / `OPENAI_URL` / `OPENAI_MODEL`. Провайдеры: `~/.local/share/projector/providers.json`.

## Проверка

```bash
vp run build
node --test tests/launcher.test.mjs
node tests/launcher-model.test.mjs
```

Тест использует временный XDG-каталог в `/tmp`: проверяет поиск, скрытые `.desktop`-записи, запуск с пробелами и полями `Exec`, сохранение режима, общую историю и запрет запросов запуска с чужого origin. Пользовательские настройки не меняются.

## Интеграции (плагины)

На `/settings` есть раздел «интеграции». Каждая интеграция имеет переключатель, параметры и собственную авторизацию. Общий реестр находится в `server/modules/integrations/index.ts`, реализация GitHub — в `server/modules/integrations/github.ts`.

Настройки и учётные данные сохраняются сервером в `$XDG_DATA_HOME/projector/integrations.json` (по умолчанию `~/.local/share/projector/integrations.json`), с правами `0600` и атомарной заменой файла. Токен хранится в этом файле и не возвращается в браузер; `localStorage` для настроек не используется. Существующие настройки интерфейса и модели остаются в `launcher.json` и `providers.json`.

### GitHub

1. Включите GitHub, укажите папку для импорта и сохраните настройки.
2. Авторизуйтесь одним из способов:
   - **Через браузер:** создайте [GitHub OAuth App](https://github.com/settings/developers), включите **Enable Device Flow**, внесите её **Client ID** в настройки Projector. Homepage и callback URL при регистрации можно указать `http://localhost:4177`; Device Flow не использует callback или Client secret. Нажмите «войти через GitHub», откройте ссылку, введите показанный код и подтвердите доступ. Projector запрашивает `repo` для импорта приватных репозиториев.
   - **Personal Access Token:** fine-grained token с доступом к нужным репозиториям и **Contents: read**, либо classic token со scope `repo` для приватных репозиториев. Projector проверяет токен через `/user` перед сохранением. Доступ к организациям может требовать разрешения организации / SSO.
3. На `/projects` откройте «импорт из GitHub». Выберите репозиторий из списка или вставьте `owner/repository` / ссылку GitHub. Список доступных репозиториев загружается страницами по 50, фильтр действует на загруженные записи.

Импорт требует установленного `git`. Репозиторий клонируется по HTTPS в `<папка импорта>/<owner>/<repository>` и регистрируется в `projects.json`. Для JS-проектов читаются `package.json` и команды запуска. Для остальных добавляется безопасная команда `git status`, которую можно заменить в карточке проекта. Projector не устанавливает зависимости и не запускает код при импорте. Существующие папки не перезаписываются; их можно добавить обычным способом как локальный проект.

«Выйти» удаляет сохранённый токен из Projector. Для отзыва доступа на стороне GitHub используйте настройки аккаунта GitHub. Выключение интеграции запрещает новые импорты, сохраняя её параметры и уже добавленные локальные проекты.

Проверка входа, файловых настроек и импорта без обращения к настоящему GitHub:

```bash
node --test tests/integrations.test.mjs tests/launcher.test.mjs
```

Тесты используют временные XDG-каталоги, подмену GitHub API и Git; проверяют обязательную авторизацию, приватные репозитории, пагинацию, Device Flow (ожидание, ограничение частоты, истечение и отмену), права файла, отсутствие токена в публичном API и Git URL, повторный и параллельный импорт.

## Архитектура

Все приложения и библиотека renderer используют FEOD с обязательной проверкой границ. Структура, публичные API и разрешённые зависимости описаны в [docs/architecture.md](docs/architecture.md). Полная проверка: `vp run check`.
