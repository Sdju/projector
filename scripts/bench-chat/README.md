# Бенчмарк чата

Реальные `AgentTurn` и `AgentMessage` в Chromium: открытие чата, рост одного сообщения, поток,
прокрутка, переключение чатов и память. Это инструмент разработки, не тест: числа зависят от
машины, а сборка здесь — dev-сервер и development-сборка Vue, поэтому абсолютные значения выше
production.

```bash
node scripts/bench-chat/run.mjs
# JSON: /tmp/opencode/chat-bench.json (путь меняется через BENCH_OUT)
```

`page.html` собирает сценарии в браузере, `run.mjs` запускает Chromium через фикстуры из
`tests/fixtures`, считает p50/p95 и печатает сводку. Ответы — markdown на 1.2 КБ; поток идёт
кусками по 64–256 символов, как приходят события агента. Окно чата — 900×900 px, колонка 680 px.

Сценарии:

- `mount-chat` — открытие N запросов сразу; `mount-prose/code/table` — один ответ заданного размера;
- `mount-widgets`, `mount-tools`, `mount-thoughts` — виджеты, вызовы инструментов и рассуждения в одном ответе (блок «Работа» по умолчанию закрыт; варианты `*-open` раскрывают его);
- `open-windowed` — открытие длинного чата через `useChatWindow` (монтируются последние 5 запросов);
- `append-full`, `append-windowed` — добавление запроса в уже открытый чат;
- `stream-chat`, `stream-windowed` — поток ответа при разном числе запросов в чате;
- `stream-work` — поток ответа с 200 вызовами при закрытой и раскрытой «Работе»;
- `stream-prose/code` — стоимость одного обновления от размера сообщения без троттлинга;
- `stream-real`, `stream-pinned` — поток с троттлингом `AgentMarkdown`, в том числе с прокруткой вниз;
- `scroll` — прокрутка смонтированного чата; `switch-full/windowed` — смена чата;
- `heap` — память renderer после `HeapProfiler.collectGarbage`.

Маркеры `ZQ<n>ZQ` в потоке нужны, чтобы отличить синхронный рендер от отложенного троттлингом:
без них замер не знает, когда кадр действительно обновился. В прозе для потока нет таблиц —
маркер в строке-разделителе таблицы не попадает в DOM.
